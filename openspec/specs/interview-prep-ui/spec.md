## Requirements

### Requirement: 面试问题生成

系统 SHALL 基于目标 JD 和用户简历动态生成个性化面试题目，替代 hardcode 题库。页面使用单页 Pipeline 布局。

#### Scenario: JD 选择器从 JD 库加载

- **WHEN** 用户查看配置区的 JD 选择器
- **THEN** 下拉列表显示 `db.jds` 中的所有 JD 记录（公司+职位+日期）
- **AND** 默认选项为"通用出题（不限 JD）"

#### Scenario: 基于 JD 动态出题

- **WHEN** 用户选择目标 JD 并点击"生成面试题"
- **THEN** AI 生成 8-12 道题目，分四类标签：行为面试、技术/专业、案例分析、文化匹配
- **AND** 每道题显示生成依据（"本题基于 JD 中的 X 要求"）

#### Scenario: 基于弱项出题

- **WHEN** 用户已建立求职画像
- **THEN** AI 识别简历与 JD 的差距，针对性生成弱项题目
- **AND** 标注"针对你的弱项——建议重点准备"

#### Scenario: 无 JD 时的通用出题

- **WHEN** 用户未选择 JD
- **THEN** 基于用户简历生成通用题目
- **AND** 提示用户"选择目标 JD 可获得更精准的题目"

#### Scenario: 选中 JD 后传递正文

- **WHEN** 用户选中某个 JD 并点击"生成面试题目"
- **THEN** 系统读取该 JD 的 `body` 字段作为 `jdText` 传递给 API
- **AND** 同时读取选中 JD 的 `company` 和 `role` 字段

#### Scenario: CV 自动加载

- **WHEN** 出题 API 被调用时
- **THEN** 系统调用 `getCVFullText()` 读取简历全文作为 `cvText` 传递给 API
- **AND** 如果简历为空，传递空字符串，API 进入通用出题模式

#### Scenario: CV 状态指示

- **WHEN** 用户查看配置区
- **THEN** 显示简历加载状态：已加载（绿色标签"简历已就绪"）/ 为空（灰色标签"未找到简历，将通用出题"）

#### Scenario: 生成题目后展示在题目列表

- **WHEN** API 返回生成的题目
- **THEN** 题目以卡片网格形式展示在配置区下方的题目列表区
- **AND** 顶部显示进度统计（"已练习 0/8 题"）
- **AND** 每张卡片展示：分类标签、题目文本、考察意图、准备提示

#### Scenario: 通用出题模式

- **WHEN** 用户未选择 JD（选择"通用出题"）
- **THEN** 系统仅传递公司预设风格和简历全文
- **AND** API 回退到通用出题策略
- **AND** 题目注明来源为 `general`

### Requirement: 面试准备 Pipeline 布局

面试准备页 SHALL 使用单页 Pipeline 布局，替代原有的三 Tab 架构。

#### Scenario: Pipeline 区域展示

- **WHEN** 用户打开面试准备页
- **THEN** 页面按顺序展示：配置区 → 题目列表区 → 已练列表区
- **AND** 配置区包含 JD 选择器、CV 状态、公司预设、生成按钮
- **AND** 已练列表默认折叠

#### Scenario: 练习面板替换题目列表

- **WHEN** 用户点击题目卡片上的 [练习] 按钮
- **THEN** 题目列表区替换为练习对话面板
- **AND** 面板顶部显示返回按钮和当前题目信息
- **AND** 对话区域加载教练流式对话组件

### Requirement: 面试日程

用户可以追踪面试安排和准备进度。

#### Scenario: 面试日程视图

- **WHEN** 用户有待进行的面试
- **THEN** 在首页和面试准备页显示即将到来的面试
- **AND** 以时间线形式展示：公司、岗位、轮次、日期、准备状态

#### Scenario: 面试准备清单

- **WHEN** 用户点击某场面试
- **THEN** 显示准备清单：研究公司、复习 JD、准备故事、准备反问、技术复习
- **AND** 每项可勾选完成

### Requirement: 回答教练（六种模式）

系统 SHALL 提供六种面试回答模式（项目复盘/行为问答/情景应对/结构化面试/创始人对话/稳重应答），覆盖互联网大厂、外企、管培、中小企业、初创、国企等全场景。

#### Scenario: 模式选择与经历输入

- **WHEN** 用户在教练 Tab 中选择面试模式（六选一）并输入经历
- **THEN** AI 按对应模式结构输出：左侧输入经历 + 顶部模式选择器 + 右侧 AI 输出
- **AND** 生成模式对应的追问列表（3-5 个），每个附带回答要点提示
- **AND** 用户可编辑确认后保存

#### Scenario: 模式4 — 中小企业结构化面试

- **WHEN** 用户选择"结构化面试"模式
- **THEN** AI 按「为什么来→做过什么→怎么做的→结果→能带来什么」结构输出
- **AND** 追问侧重 HR 追细节、稳定性和即战力

#### Scenario: 模式5 — 初创创始人对话

- **WHEN** 用户选择"创始人对话"模式
- **THEN** AI 按「理解业务→能立刻上手→薪资期望→创业节奏」结构输出
- **AND** 附带风险识别提示（口头承诺、社保、期权真实性）

#### Scenario: 模式6 — 国企稳重应答

- **WHEN** 用户选择"稳重应答"模式
- **THEN** AI 按「学历背景→政治觉悟→服从意识→长期规划→家庭情况」结构输出
- **AND** 弱化"亮点突出"维度、强化"稳重得体"维度

### Requirement: 回答评分与反馈

系统 SHALL 对用户的面试回答进行 AI 评分和反馈。

#### Scenario: 提交回答获得评分

- **WHEN** 用户输入面试回答并点击"评分"
- **THEN** AI 从四个维度评分（1-5）：结构完整度、具体程度、亮点突出、时间控制
- **AND** 评分权重随所选模式变化，给出 2-3 条改进建议

#### Scenario: 长回答逐段反馈

- **WHEN** 用户回答 > 300 字
- **THEN** AI 分段标注优劣，在原文上内联展示

### Requirement: 大厂面试预设

系统 SHALL 提供大厂面试风格预设，影响题目生成倾向。

#### Scenario: 字节跳动预设

- **WHEN** 用户选择"字节跳动"预设
- **THEN** 出题偏向数据驱动、A/B 测试、快节奏决策类题目

#### Scenario: 腾讯预设

- **WHEN** 用户选择"腾讯"预设
- **THEN** 出题偏向产品感、用户体验、社交生态理解

#### Scenario: 阿里巴巴预设

- **WHEN** 用户选择"阿里巴巴"预设
- **THEN** 出题偏向价值观、执行力、业务闭环思维
