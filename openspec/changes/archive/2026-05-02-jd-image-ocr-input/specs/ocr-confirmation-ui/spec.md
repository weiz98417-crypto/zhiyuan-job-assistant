# Spec: OCR Confirmation UI

## ADDED Requirements

### Requirement: 逐张确认界面

系统 SHALL 在全部图片识别完成后，展示逐张确认界面，每张图片的提取字段以可编辑表单展示。

#### Scenario: 成功识别的图片可编辑

- **WHEN** 用户进入确认流程
- **THEN** 显示第一张成功识别的图片的提取字段
- **AND** 每个字段（公司、职位、地点、薪资、技能、正文）在可编辑输入框中展示
- **AND** 用户可修改任意字段内容

#### Scenario: 缺失字段警告

- **WHEN** 某个字段的值为 `"【缺失】"`
- **THEN** 该字段以黄色边框高亮
- **AND** 旁边显示警告图标和文字"请补充此字段"
- **AND** 输入框 placeholder 为"请补充公司名称"等引导文字

#### Scenario: 非 JD 图片提示

- **WHEN** 某张图片识别结果为 `isJD: false`
- **THEN** 显示提示"该图片可能不是职位描述，请确认"
- **AND** 提供"跳过"和"仍然保存"两个选项

### Requirement: 确认操作

系统 SHALL 为每张确认后的图片提供"保存到 JD 库"和"跳过"操作。

#### Scenario: 保存到 JD 库

- **WHEN** 用户确认字段内容并点击"保存到 JD 库"
- **THEN** 将 JD 记录写入 IndexedDB `jds` 表（`sourceType: "ocr"`）
- **AND** 自动前进到下一张图片的确认界面
- **AND** 显示保存成功 toast

#### Scenario: 跳过当前图片

- **WHEN** 用户点击"跳过"
- **THEN** 该图片的提取数据丢弃
- **AND** 自动前进到下一张图片的确认界面

#### Scenario: 全部确认完成

- **WHEN** 所有图片都已确认（保存或跳过）
- **THEN** 显示汇总："成功保存 N 条 JD 到库"
- **AND** 提供"前往 JD 库查看"和"继续识别"两个按钮

### Requirement: 失败图片处理

系统 SHALL 在确认流程中显示识别失败的图片，并提供重试选项。

#### Scenario: 显示失败图片

- **WHEN** 队列中有识别失败的图片
- **THEN** 在确认流程末尾显示失败图片列表
- **AND** 每张显示失败原因和"重试"按钮
- **AND** 提供"全部重试"选项

#### Scenario: 跳过失败图片

- **WHEN** 用户选择跳过失败图片
- **THEN** 失败图片从队列移除
- **AND** 不影响成功识别图片的确认流程
