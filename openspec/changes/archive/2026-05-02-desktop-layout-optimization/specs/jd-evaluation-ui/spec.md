## MODIFIED Requirements

### Requirement: JD 输入

用户可以通过粘贴文本或 URL 的方式输入职位描述，启动 AI 评估。

#### Scenario: 粘贴 JD 文本

- **WHEN** 用户在评估页面粘贴 JD 文本到输入框
- **THEN** 文本被接受并显示字符数
- **AND** "开始评估"按钮变为可用状态

#### Scenario: 粘贴 JD URL

- **WHEN** 用户粘贴一个 URL（如 https://www.zhipin.com/job_detail/xxx）
- **THEN** 系统识别为 URL 输入
- **AND** 提示将通过 Playwright 或 WebFetch 获取 JD 内容
- **AND** "获取并评估"按钮变为可用状态

#### Scenario: 空输入提示

- **WHEN** 用户未输入任何内容就点击评估
- **THEN** 输入框以温和的方式提示"请粘贴职位描述或链接"
- **AND** 不出现红色错误警告（不符合手帐的温暖调性）

#### Scenario: 桌面大屏输入布局

- **WHEN** 用户在 ≥1280px 屏幕访问评估输入页
- **THEN** 输入区 textarea 最小宽度 640px，行数增加到 18 行
- **AND** 整体输入区域不再受 `max-w-2xl` 限制

### Requirement: A-G 评估报告渲染

评估完成后，系统必须以结构化、可读的方式渲染完整的 A-G 报告。

#### Scenario: 报告加载状态

- **WHEN** 用户提交 JD 进行评估
- **THEN** 显示温暖的加载动画（如手写笔迹逐渐出现）
- **AND** 显示当前评估进度（"正在分析职位匹配度..."）

#### Scenario: 完整报告展示

- **WHEN** 评估完成后
- **THEN** 报告以手帐排版风格渲染，包含 A-G 全部模块
- **AND** 总体评分以 Display 字体大号展示，配合一句人话解读

#### Scenario: 桌面大屏报告双栏布局

- **WHEN** 用户在 ≥1280px 屏幕查看评估报告
- **THEN** 报告使用双栏布局：左侧 (55%) A-G blocks，右侧 (45%) 深度分析面板
- **AND** 深度分析面板包含关键词覆盖率、技能缺口、投递前重点关注
- **AND** 操作按钮组固定在右侧面板底部
- **AND** 当无深度分析数据时，右侧面板隐藏，报告恢复单栏居中

#### Scenario: 报告模块折叠

- **WHEN** 用户点击报告中的任意模块标题（如"薪资与市场"）
- **THEN** 该模块内容折叠/展开
- **AND** 折叠动画流畅自然

#### Scenario: 评分可视化

- **WHEN** 报告包含 A-F 各项分数
- **THEN** 每项分数以温暖的视觉形式呈现（非冰冷的进度条）
- **AND** 满分项和低分项有明显的视觉区分

### Requirement: 评估操作

评估报告页面需要提供后续操作的快捷入口。

#### Scenario: 添加到投递追踪

- **WHEN** 用户查看评估报告并点击"加入追踪"
- **THEN** 该职位自动添加到投递追踪列表
- **AND** 状态设为"已评估"，关联该报告

#### Scenario: 生成定制简历

- **WHEN** 用户点击"优化简历"
- **THEN** 跳转到简历优化页面
- **AND** 自动带入该 JD 的关键词和要求

#### Scenario: 面试准备

- **WHEN** 用户点击"准备面试"
- **THEN** 跳转到面试准备页面
- **AND** 自动基于该 JD 生成面试问题和 STAR+R 故事建议
