## Context

当前前端所有页面在桌面大屏（1280px+）上存在显著的空间浪费问题：

- AppShell 内容区 `max-w-4xl` (896px)，在 1440px 屏幕上仅占 62% 宽度，扣除 224px 侧栏后实际内容区仅 ~672px
- 评估输入页 `max-w-2xl` (672px)，14 行 textarea 在大屏上只有一小条
- 评估报告页 `max-w-3xl` (768px)，A-G 7 个 block 全都竖排堆叠
- CV 页 `lg:grid-cols-3` 在 XL 屏没有进一步升级
- JD 库和报告页卡片 grid 只有 `grid-cols-1 md:grid-cols-2`，XL 屏上卡片过宽

技术栈限制：Next.js 16 + Tailwind CSS 4 + Framer Motion + IndexedDB (Dexie.js)，纯前端无后端。

## Goals / Non-Goals

**Goals:**
- 桌面端 (1280px+) 内容区利用更多水平空间，减少无效留白
- 关键页面（评估、CV）在大屏上使用双栏布局，同时查看更多信息
- 卡片网格页面在更宽屏幕上自动增加列数
- 所有变更纯 CSS/布局层，不改功能逻辑

**Non-Goals:**
- 不改变移动端布局（<1024px）
- 不改变设计系统 token（色彩、字体、动画）
- 不修改 Tailwind 主题配置
- 不新增依赖

## Decisions

### Decision 1: 内容宽度 — 流体布局 (无 max-width)

AppShell 内容区移除 `max-w` 限制，内容自然填满可用空间（侧栏 + `--space-page` padding 之间）。页面级别不再各自设 `max-w`，从 AppShell 统一继承。

**Why 流体**: 这是一个仪表盘/工具型应用，布局以卡片 grid、双栏编辑器、表单为主，不是长文阅读页面。固定 max-width 在宽屏上造成大量无效留白（1920px 屏幕仅用 60%），流体布局在 1920px 上内容利用率达 88%。

**Trade-off**: 1920px+ 屏幕上，卡片和编辑区宽度相应增加。Card grid 通过 `xl:grid-cols-3` 自适应，CV 编辑器通过 `xl:grid-cols-[1fr_360px]` 保持合理比例。文本行长度可通过页面内部组件级 `max-w` 约束（如报告详情面板 `xl:max-w-lg`），不在全局层面限制。

### Decision 2: XL 屏双栏断点 — 1280px

统一 `xl` (1280px) 作为双栏布局的触发断点。`lg` (1024px) 保持单栏但放宽宽度。这样：
- 1024-1279px (小笔记本/平板横屏): 单栏但比现在宽
- 1280px+ (标准笔记本/台式): 双栏

**Why 1280px**: Tailwind 的 xl 断点是最接近主流笔记本分辨率 (1366-1440px) 的标准断点。低于 1280px 时双栏太挤。

### Decision 3: 评估报告页双栏方案

```
┌──────────────────────────────────────────────────┐
│                    报告头部                        │
├────────────────────────┬─────────────────────────┤
│   A-G Blocks (左 55%)  │  深度分析 + 操作 (右 45%) │
│                        │                         │
│   · 职位概览           │   关键词覆盖率            │
│   · 简历匹配           │   技能缺口               │
│   · 职级与策略         │   投递前重点关注          │
│   · 薪资与市场         │   操作按钮组             │
│   · 定制化方案         │                         │
│   · 面试准备           │                         │
│   · 职位合法性         │                         │
└────────────────────────┴─────────────────────────┘
```

**Why left-right split**: 评估报告的"深度分析"（关键词、技能缺口、差异化建议）是紧密关联的上下文信息，放在侧边 vs 底部能减少滚动。左右分栏比例 55:45 是因为 A-G blocks 是主要内容。

### Decision 4: CV 编辑页方案

CV 页当前 `lg:grid-cols-3`，改为 `lg:grid-cols-3 xl:grid-cols-[1fr_360px]`。

- 主编辑区占 `1fr`（剩余空间），更宽的 textarea
- JD 配对面板固定 360px，始终可见
- 模板选择器保持在编辑区上方

**Why 360px**: 右侧面板包含 select dropdown + 匹配度 + 关键词列表 + AI 建议，需要足够宽度展示表格和标签。360px 是内容舒适展示的最小宽度。

### Decision 5: 卡片 Grid 响应式升级

JD 库和报告页卡片 grid：
```
当前:  grid-cols-1 md:grid-cols-2
改为:  grid-cols-1 md:grid-cols-2 xl:grid-cols-3
```

卡片最小宽度约 320px。在 1152px 内容区中，3 列 = 每列 ~370px，刚好舒适。卡片内信息密度不变，列数随空间自适应。

### Decision 6: 不引入 CSS Container Queries

纯 Tailwind 响应式类足够覆盖所有场景。Container Queries 会增加复杂度和浏览器兼容性负担，在这个项目中没有必要。

## Risks / Trade-offs

- **[Risk] 文字行过长影响可读性** → 评估为低风险。该应用以卡片 grid、双栏编辑器、表单为主，非长文阅读。对少数长文本区域（如报告详情面板）使用组件级 `xl:max-w-lg` (512px) 约束
- **[Risk] 双栏布局在评估 loading 状态时需要适配** → loading 状态保持居中单栏，不受双栏影响
- **[Risk] 超宽屏 (2560px+) 卡片过大** → 3 列 grid 在 2336px 内容区中每列 ~763px，在可接受范围内。如需进一步优化可加 `2xl:grid-cols-4`
