# Spec: JD Evaluation UI

## MODIFIED Requirements

### Requirement: A-G 评估报告渲染

评估完成后，系统必须以结构化、可读的方式渲染完整的评估报告，包含雷达图、行话解读和行动建议。评估过程使用流式 SSE 输出，首字节 < 2 秒。

#### Scenario: 流式评估加载

- **WHEN** 用户提交 JD 进行评估
- **THEN** 通过 SSE 流式输出报告分段：摘要 → 匹配度打分 → 五维雷达 → 信号解读 → 行动建议
- **AND** 显示分段进度指示器（当前正在生成哪个部分）
- **AND** 已完成的段落可立即阅读

#### Scenario: 五维雷达图

- **WHEN** 评估完成
- **THEN** 渲染 SVG 雷达图，五个维度：技能匹配、经验匹配、薪资匹配、成长空间、风险指数
- **AND** 每个维度显示 0-5 分具体数值
- **AND** 使用手帐风格暖色渐变填充

#### Scenario: 行话解读

- **WHEN** JD 中包含"快速迭代"、"扁平化管理"、"抗压能力强"等行话
- **THEN** 在"信号解读"段中标黄提示真实含义
- **AND** 使用委婉表述（"可能"、"通常意味着"）

#### Scenario: 一句话行动建议

- **WHEN** 评估完成
- **THEN** 报告末尾生成一句行动建议
- **AND** 根据匹配度高低给出不同建议（推荐投递 / 谨慎尝试 / 建议跳过）

#### Scenario: 报告模块折叠

- **WHEN** 用户点击报告中的任意模块标题
- **THEN** 该模块内容折叠/展开
- **AND** 折叠动画流畅自然

## ADDED Requirements

### Requirement: 流式评估输入增强

评估输入区 SHALL 支持粘贴 JD 文本/URL 之外的输入方式：粘贴 Boss直聘/猎聘等平台的 JD 链接自动抓取。

#### Scenario: Boss直聘链接识别

- **WHEN** 用户粘贴包含 zhipin.com 的 URL
- **THEN** 系统识别并通过 fetch-jd API 获取 JD 内容
- **AND** 获取成功后自动填入输入框并显示预览

### Requirement: 评估历史搜索与对比

评估历史页面 SHALL 支持按公司名、岗位名、评分范围搜索，以及选中两条记录进行对比。

#### Scenario: 对比两条评估

- **WHEN** 用户在评估历史中选中两条记录并点击"对比"
- **THEN** 并排显示两份报告的摘要、评分、信号对比
- **AND** 高亮差异项
