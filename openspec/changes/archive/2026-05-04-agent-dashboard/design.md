## Context

agent-smart-recommend 提供了推荐能力，但首页仍然是 V1.5 的静态布局。V2.0 的体验闭环需要一个"指挥中心"——用户打开应用看到的是 Agent 为你做了什么、你需要做什么。

设计约束：(1) 首页是用户每天打开看到的第一屏，信息密度和信息温暖度需要平衡，(2) 自动评估改变了 evaluate 页面的交互模式，(3) 健康告警需要在有用和烦人之间找平衡。

## Goals / Non-Goals

**Goals:**
- 首页改版为四区布局：推荐 | 健康 | 操作 | 动态
- JD 粘贴后自动触发评估（去掉了"开始评估"按钮这步）
- Pipeline 健康告警可配置阈值
- 快速操作入口减少用户导航成本

**Non-Goals:**
- 不做数据大屏/BI 风格（保持手帳温度）
- 不做实时 WebSocket 推送
- 不做移动端独立布局（共用响应式）

## Decisions

### 首页布局

```
┌──────────────────────────────────────────────┐
│  🌅 早上好，[名字]                            │
│  你的求职竞争力：82分 ↑3                       │
├─────────────────────────┬────────────────────┤
│  Agent 推荐 Top 3       │  Pipeline 健康      │
│  (3 张横向推荐卡片)      │  (迷你桑基图/漏斗)   │
│                         │  绿灯：分布健康      │
├─────────────────────────┴────────────────────┤
│  ⚡ 待处理                          📋 最近动态 │
│  · 3 个新 JD 待评估                 · 字节一面  │
│  · 腾讯面试明天                      · 评估完成  │
│  · 2 个跟进提醒                      · 新推荐   │
└──────────────────────────────────────────────┘
```

**决策**: 四区布局，上下两行，每行左右分栏。推荐区占视觉重心（左上，F 型阅读模式的起点），健康面板在右上提供状态概览。保持手帳风格——卡片有温暖的有机圆角，数据用暖色系。

### 自动评估流程

用户粘贴 JD URL 或文本 → 检测到内容变化 → 自动调用 evaluate API → 流式输出报告。

关键差异 vs V1.5：
- V1.5: 粘贴 → 手动点"开始评估" → 等待
- V2.0: 粘贴 → 自动开始 → 流式展示

保留手动触发选项（用户可能想编辑 JD 文本后再评估），增加 2 秒防抖。

### Pipeline 健康面板

三个指示灯 + 简短文案：
- 🟢 绿灯：漏斗分布健康（各阶段比例在正常范围）
- 🟡 黄灯：注意（某阶段堆积 > 60%）
- 🔴 红灯：警告（某阶段堆积 > 80%，或某方向 0 回复 > 5 次）

告警阈值存储在 profile 中可配置，默认值硬编码。

### 快速操作入口

根据 Pipeline 状态动态生成操作建议：
- Evaluated > 5 且 Applied < 3 → "有 5 个评估完的岗位还没投递"
- Interview 阶段有即将到来的面试 → "明天有面试，去准备"
- 某跟进超过 7 天 → "该跟进了"

## Risks / Trade-offs

- [自动评估误触发] → 2 秒防抖 + 内容最小长度校验（>50 字符）
- [健康告警过频] → 每天最多触发一次同类告警，避免焦虑
- [首页信息过载] → 每个区域可折叠，默认全部展开
