## MODIFIED Requirements

### Requirement: App Shell Layout

应用必须提供一个统一的 App Shell，包含导航和内容区域，首页"今日手帐"以 Agent 推荐为核心展示 AI 每日摘要。

#### Scenario: 首次访问看到首页

- **WHEN** 用户首次访问应用
- **THEN** 显示"今日手帐"首页，包含温暖的欢迎语
- **AND** 如果用户已设定求职目标且存在推荐结果，Agent 推荐区置顶展示 Top 3 推荐
- **AND** 如果用户尚未设定目标，引导开启目标设定向导
- **AND** 左侧或底部显示主导航

#### Scenario: Agent 推荐卡片展示

- **WHEN** 首页加载且存在推荐结果
- **THEN** 推荐区展示最多 3 张推荐卡片
- **AND** 每张卡片显示：公司名、岗位、匹配分数（大号 Display 字体）、推荐理由列表（3-5 条）、风险提示（如有）
- **AND** 卡片从左到右排列，匹配度最高的在左侧
- **AND** 每张卡片提供"查看评估"和"不感兴趣"两个操作

#### Scenario: 推荐卡片"查看评估"交互

- **WHEN** 用户点击推荐卡片上的"查看评估"
- **THEN** 跳转到该 JD 的评估详情页

#### Scenario: 推荐卡片"不感兴趣"交互

- **WHEN** 用户点击推荐卡片上的"不感兴趣"
- **THEN** 该卡片以温和动画淡出
- **AND** 反馈发送至 Agent 偏好调整

#### Scenario: AI 摘要卡片交互

- **WHEN** 用户点击 AI 摘要卡片中的任意模块
- **THEN** 跳转到对应详情页（投递统计→analytics，最近评估→evaluate，跟进→tracker）

#### Scenario: 无数据时的摘要

- **WHEN** 用户尚无任何求职数据
- **THEN** AI 摘要卡片显示引导文案："开始你的求职之旅吧——去探索页和 AI 聊聊，或者评估你的第一个 JD"
- **AND** 提供跳转到 explore 和 evaluate 的快捷按钮

#### Scenario: 导航切换页面

- **WHEN** 用户点击导航中的任意菜单项
- **THEN** 页面内容以翻页般的过渡动画切换到目标页面
- **AND** 当前页面的导航项以暖色高亮

#### Scenario: 移动端适配

- **WHEN** 用户在手机屏幕上访问应用
- **THEN** 导航自动切换为底部 Tab Bar 模式
- **AND** 所有页面内容在窄屏幕上可读

#### Scenario: 内容区高度传递

- **WHEN** 子页面使用 flex-1 填充可用高度（如固定底部输入框的聊天布局）
- **THEN** AppShell 内容包裹层传递完整高度（h-full flex flex-col）
- **AND** 子页面的 flex-1 元素可正确填满到页面底部

#### Scenario: 桌面端内容宽度

- **WHEN** 用户在桌面浏览器 (≥1024px) 访问应用
- **THEN** 内容区最大宽度为 `max-w-6xl` (1152px)
- **AND** 内容区水平居中，两侧自动留白
- **AND** 在 1280px+ 屏幕上内容区利用率提升至约 80%

#### Scenario: 导航包含求职画像入口

- **WHEN** 应用渲染主导航
- **THEN** 导航项 SHALL 包含"求职画像"菜单项
- **AND** 点击后跳转到 `/profile` 页面
- **AND** 当前在画像页时该导航项以暖色高亮
