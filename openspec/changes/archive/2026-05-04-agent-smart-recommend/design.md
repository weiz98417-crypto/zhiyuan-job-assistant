## Context

求职画像引擎（career-profile-engine）提供了结构化的用户画像。Agent 智能推荐是画像的第一个消费者——让系统从"被动工具"变成"主动助手"。用户在目标设定向导中告诉 Agent 想要什么，Agent 每天扫描 Pipeline 中的 JD，基于画像做个性化匹配排序。

需要关注的设计约束：(1) 目标设定是低频操作（首次 + 偶尔调整），(2) 推荐是高频操作（每次打开首页），(3) 推荐质量直接决定用户对 Agent 的信任度。

## Goals / Non-Goals

**Goals:**
- 目标设定向导：3-5 步交互式流程，收集角色、级别、薪资、底线、偏好
- Agent 推荐引擎：基于画像 + 目标，对 Pipeline 中 JD 评分排序
- 每日 Top 3：附带个性化理由（为什么推荐这个岗位给你）
- 首页卡片升级：从静态统计变为 Agent 动态推荐

**Non-Goals:**
- 不做自动投递（那是 V2.5 的事）
- 不做外部 JD 搜索（用户仍需粘贴 JD 到 Pipeline）
- 不做实时通知/推送

## Decisions

### 目标设定向导设计

步骤设计（5 步，每步一个问题）：
1. "你想找什么样的工作？" → 角色 + 级别选择
2. "你的薪资期望？" → 税前月薪范围 + 年终奖预期
3. "哪些条件不能妥协？" → 多选：不加班/不出差/不外包/有公积金...
4. "公司偏好？" → 规模（大厂/中小企业/初创/外企/国企）+ 行业
5. 确认总结 → 展示所有选择，用户确认后写入画像

**决策**: 向导以 Modal 形式呈现，不跳页。理由：目标设定是低频但有深度的操作，Modal 比页面跳转更聚焦、更温暖。

### 推荐引擎策略

```
推荐分数 = 技能匹配(0.4) + 偏好契合(0.3) + 竞争力评估(0.2) + 画像信号(0.1)
```

- 技能匹配：JD 要求技能 ∩ 用户技能，加权计算
- 偏好契合：JD 的行业/规模/工作方式与用户偏好向量的余弦相似度
- 竞争力评估：基于历史同类型岗位的通过率
- 画像信号：用户画像中的整体竞争力分数作为基准

**决策**: 推荐计算在服务端完成（调用 DeepSeek API），不在客户端做。理由：需要 LLM 理解 JD 文本并做语义匹配，不是简单的关键词匹配。

### API 设计

`POST /api/agent/recommend`
- 入参: `{ limit?: number }`（默认 3，最多 5）
- 处理: 读取画像 → 读取 Pipeline 中状态为 Evaluated 的 JD → LLM 排序 → 返回 Top N
- 返回: `{ recommendations: { jdId, company, role, matchScore, reasons: string[], riskNote?: string }[] }`
- 缓存: 同一画像+同一批 JD 下缓存 1 小时

### 首页卡片升级

当前首页显示：投递统计 / 最近评估 / 跟进提醒 / Pipeline 灯。升级为：
- **Agent 推荐区**（新增，置顶）：Top 3 推荐卡片
- **Pipeline 概览**（保留）：精简为一行状态条
- **最近动态**（保留）：最近评估和面试动态

**决策**: 推荐区置顶，其他卡片下移。Agent 推荐是首页的"主角"。

## Risks / Trade-offs

- [冷启动] → 新用户无画像时，推荐退化为纯 JD-目标关键词匹配，并显示"完成更多评估以获得个性化推荐"
- [推荐不准] → 每条推荐附带"不感兴趣"按钮，用户反馈用于调整偏好权重
- [LLM 成本] → 推荐结果缓存 1 小时；如果 Pipeline 无新增 JD，返回缓存结果
