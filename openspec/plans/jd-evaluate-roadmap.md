# JD 评估工作台 — 完整路线图

> 将 `/evaluate` 从"单条 JD 打分器"升级为"求职决策工作台"

---

## 概览：五层 × 三阶段

```
Phase 1 ─ 基础补强 ─ 让单条评估真正有用
Phase 2 ─ 批量队列 ─ 效率翻倍，从一条到一批
Phase 3 ─ 智能化   ─ 从工具到参谋

每条功能标注优先级：P0 必须 / P1 重要 / P2 锦上添花
```

---

# Phase 1 — 基础补强

> 目标：单条评估做到极致，每条评估都是一份可执行的行动指南

## 1.1 评估结果增强

| # | 功能 | 优先级 | 说明 |
|---|------|--------|------|
| 1 | 关键词覆盖率可视化 | P0 | 从简历提取技能 → 与 JD 关键词逐项对比 → 绿色(已覆盖)/红色(缺失)/黄色(可加强)，可视化条展示覆盖率 % |
| 2 | 技能缺口分析 | P0 | 列出 JD 要求但简历没有的技能，每项标注：必需要求/加分项、可替代性评估 |
| 3 | 职级匹配 | P1 | 判断 JD 的级别(P5/P6/P7/P8)是否匹配用户 YOE，输出"偏低/匹配/偏高/需要跃升" |
| 4 | 薪资基准对比 | P1 | 根据岗位+城市+级别，拉取市场薪资分位(25%/50%/75%)，JD 薪资落在哪个区间 |
| 5 | 差异化提示 | P1 | "这份 JD 特别强调 X，但你的简历里只有一句带过"——告诉你哪里要重点补 |
| 6 | 公司背调摘要 | P2 | 企查查/脉脉的公司规模、融资阶段、口碑摘要 |

## 1.2 简历优化直通

| # | 功能 | 优先级 | 说明 |
|---|------|--------|------|
| 7 | 评估页内嵌优化 | P0 | 报告下方直接展示简历中与 JD 不匹配的段落，每条附 AI 改写建议，点击"应用"即更新简历 |
| 8 | HR 视角预览 | P1 | "如果你是这个 JD 的 HR，请点评这份简历的前 3 个亮点和前 3 个疑虑" |
| 9 | 简历版本管理 | P2 | 每次"定向优化"保存为一个版本，可回溯、对比、恢复 |

## 1.3 结果管理基础

| # | 功能 | 优先级 | 说明 |
|---|------|--------|------|
| 10 | 评估笔记 & 标签 | P1 | 每条评估可添加自定义标签(如"重点关注"/"备选"/"保底")和纯文本笔记 |
| 11 | 评分权重自定义 | P2 | 在设置页允许用户调整 7 个维度的权重(如"对我而言薪资更重要→D 模块权重+10%") |

# Phase 2 — 批量 & 队列

> 目标：从一次一条变成一次一批，有队列有进度

## 2.1 批量输入

| # | 功能 | 优先级 | 说明 |
|---|------|--------|------|
| 12 | 多 URL 粘贴 | P0 | 一个 textarea，换行分隔 URL，系统逐个抓取 JD → 加入评估队列 |
| 13 | CSV/JSON 导入 | P1 | 拖拽上传 CSV(公司,角色,URL)或 JSON，解析后加入队列 |
| 14 | 发现页选送 | P1 | `/discover` 页面扫描结果勾选多条 → "批量评估" → 跳转 /evaluate 并自动载入队列 |
| 15 | 书签文件导入 | P2 | 浏览器书签 HTML 文件解析，提取招聘 URL |

## 2.2 队列系统

| # | 功能 | 优先级 | 说明 |
|---|------|--------|------|
| 16 | 队列面板 | P0 | 页面侧边/底部常驻迷你队列，显示：排队中(N) / 处理中(1) / 已完成(N) / 失败(N) |
| 17 | 实时进度 | P0 | 每条任务显示：步骤(抓取→评估→完成)、耗时、当前状态。不再是假动画 |
| 18 | 后台处理 | P0 | 提交队列后可离开当前页面甚至关闭浏览器(Service Worker + IndexedDB)，回来时自动加载结果 |
| 19 | 并行评估 | P1 | 同时评估 2-3 条 JD（受 API rate limit 约束），加速批量处理 |
| 20 | 失败重试 | P1 | 失败的评估显示错误原因，支持单条重试或批量重试 |
| 21 | 队列持久化 | P1 | 刷新页面队列不丢失，存储在 IndexedDB |

## 2.3 批量结果管理

| # | 功能 | 优先级 | 说明 |
|---|------|--------|------|
| 22 | 结果总览表 | P0 | 队列完成后显示汇总表：公司/角色/总分/合法性/状态，可排序可筛选 |
| 23 | 批量加入追踪 | P0 | 勾选多条评估结果 → "一键加入投递追踪" |
| 24 | 批量导出 | P1 | 选中 N 条 → 导出为 CSV / PDF / Markdown 汇总报告 |

# Phase 3 — 智能化

> 目标：AI 不只是打分，而是给出决策建议和自动化工作流

## 3.1 智能分析

| # | 功能 | 优先级 | 说明 |
|---|------|--------|------|
| 25 | 语义匹配引擎 | P1 | 用 embedding 算 JD↔简历的向量相似度，作为关键词匹配的补充维度 |
| 26 | 智能推荐方向 | P1 | 分析评估历史："你评估的 JD 里 70% 是后端但分数偏低，数据工程方向匹配度更高，要试试吗？" |
| 27 | 看板 (Kanban) | P1 | 拖拽式看板：待评估 → 已评估 → 准备投递 → 已投递 → 面试中 → Offer |
| 28 | 对比模式 | P1 | 选 2-3 个 JD 并排对比：分数/薪资/技能要求/福利，高亮最优项 |
| 29 | 市场趋势面板 | P2 | 评估过的 JD 数据聚合：薪资走势、热门技能、热门公司，形成个人求职市场情报 |

## 3.2 自动化

| # | 功能 | 优先级 | 说明 |
|---|------|--------|------|
| 30 | 定时扫描 + 自动评估 | P2 | 每天定时从招聘网站扫描新 JD → 自动评估 → 超过阈值推送通知 |
| 31 | 投递节奏建议 | P2 | 分析投递行为："本周评估 15 个只投了 2 个" / "你已连续 3 天没有新投递" |
| 32 | Chrome 扩展 | P2 | 浏览招聘网站时一键保存 JD → 自动进入评估队列 |
| 33 | Cover Letter 生成 | P2 | 根据 JD + 简历 + 公司信息，生成中文求职信 |

## 3.3 协作 & 分享

| # | 功能 | 优先级 | 说明 |
|---|------|--------|------|
| 34 | 报告分享 | P2 | 生成一个分享链接(可设有效期)，发给朋友/导师帮忙参谋 |
| 35 | AI 参谋对话 | P2 | 在评估报告旁直接与 AI 讨论"这个岗位我要不要投？"——结合评估数据给出建议 |
