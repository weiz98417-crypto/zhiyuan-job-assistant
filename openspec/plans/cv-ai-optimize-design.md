# CV 优化器 — 完整设计方案

> 灵感来源：Suno AI 歌词编辑器的 "Multi-Version → Compare → Pick/Abandon" UX 模式
> 目标：让简历优化的体验从"手动打字"升级为"AI 出方案、我来选"的协作式创作

---

## 一、Suno 核心 UX 模式 → CV 优化器映射

### Pattern 1: 多版本生成（A/B Testing）

Suno 的做法：
- 每次点击 Generate → 同步生成 2 个不同编曲和人声演绎的版本
- 用户逐个试听 → 选择保留一个 → 继续迭代
- 不喜欢的版本直接丢弃

→ **CV 映射**：每个 section 的 AI 优化按钮点击后，生成 **3 个改写方案**（不是 2 个，因为文字比音乐更需要多样性）
- 方案 A：激进化改写（大幅调整结构、补充量化数据、STAR 格式化）
- 方案 B：保守化改写（保留原文结构，精修措辞、增加关键词密度）
- 方案 C：定向化改写（针对当前选中的 JD 做针对性强化）

### Pattern 2: 分段独立编辑（Segment-Level Editing）

Suno 的做法：
- Song Editor 中每个段落（Intro/Verse/Chorus/Bridge）是独立的可编辑单元
- 修改 Verse 2 的歌词不影响其他段落

→ **CV 映射**：5 个 section 各自独立触发 AI 优化，互不干扰
- 每个 section 卡片右下角有独立的 `✨ AI 优化` 按钮
- 同时只展开一个优化面板
- 选择方案后只更新该 section 的内容

### Pattern 3: Generate → Review → Pick/Abandon 循环

Suno 的做法：
```
描述意图 → 生成 → 试听比较 → 选 A / 选 B / 全部丢弃重新生成
    ▲                                              │
    └────────── 调整 prompt 重新生成 ←──────────────┘
```

→ **CV 映射**：
```
用户审阅原文 → 点击 AI 优化 → (可选) 写上优化意图 → 
生成 3 方案 → 并排比较 → 选用方案B / 全部放弃保留原文 / 调整意图重新生成
```

### Pattern 4: 风格提示与内容分离

Suno 的做法：
- Lyrics 框：歌词正文（结构化内容）
- Style 框：音乐风格描述（表现层修饰）
- 两个输入框分离，各自独立迭代

→ **CV 映射**：
- section 原文 = 事实内容（不可随意篡改）
- 优化意图输入框 = 风格修饰（"偏管理方向" / "强调数据成果" / "加上 STAR 结构"）
- AI 在原文基础上+意图指导做改写

### Pattern 5: 创意滑块控制系统

Suno 的做法：
- Weirdness（奇异度）：0=保守，100=实验性
- Style Influence（风格锚定强度）：高=严格遵守描述，低=自由发挥
- Audio Influence（音频特征权重）：平衡参考音频与文字描述

→ **CV 映射**：
- **改写激进程度**：1=只润色措辞 / 5=大幅重构段落 / 10=完全重写（可能改变结构）
- **关键词密度**：1=自然语言 / 5=适度植入 JD 关键词 / 10=最大化关键词覆盖
- 用滑块可视化，而非输入数字——直观、即时的认知模型

### Pattern 6: 持久人设（Persistent Identity）

Suno 的做法：
- Personas 功能让同一"歌手"的声线特征跨项目保持一致

→ **CV 映射**：
- 所有 section 的优化共享一个"简历角色身份"上下文
- 从 UserProfile（设置页）读取：headline、superpowers、targetRoles
- 优化时确保 5 个 section 的语气、叙事线、专业度保持一致

### Pattern 7: 明确可逆转（Clear Abandon Path）

Suno 的做法：
- 任何修改都可撤销，原版永远保留
- Song Editor 的编辑历史可回溯

→ **CV 映射**：
- 原文在优化过程中始终保留
- 用户选择方案后才替换原文
- "放弃"按钮一键回到原文状态
- 版本管理：每次 AI 优化接受后自动保存一个版本快照

### 交互细节

1. **触发** — 每个 section 卡片右下角 `✨ AI 优化` 小按钮，hover 时出现
2. **展开** — 点击后卡片向下展开优化面板，同一时间只允许一个面板打开
3. **意图输入** — 可选文本输入框，告诉 AI 想要什么方向（如"偏管理"、"强调数据成果"）。留空则由 AI 自行判断最佳方向
4. **双滑块** — 
   - 改写激进程度：1(仅润色措辞)～10(完全重写)
   - 关键词密度：1(自然描述)～10(最大化关键词匹配)
5. **生成** — 点击「生成方案」→ 3 秒 loading → 3 个方案同时出现
6. **选择** — 点击「选用此方案」→ 原内容替换 → 自动保存 → 面板收起
7. **放弃** — 点击「放弃，保留原文」→ 面板收起 → 原文不变
8. **重新生成** — 修改意图或滑块 → 再点「生成方案」

### 附加交互

- 如果 CV 页面右侧已选择配对 JD（`selectedReport`），方案 C 自动生成。否则只生成方案 A + B（2 个方案）
- 优化结果区每个方案旁有一个小复制按钮，方便用户部分采纳
- 方案选中后，对应的 section 显示短暂的绿闪动画表示已更新

## 三、API 设计

```
POST /api/cv/optimize-section

Request:
{
  sectionId: "experience",       // section ID
  sectionContent: "原文...",      // current section text
  fullCV: { sections... },       // all sections (for context - keep voice consistent)
  intent?: "强调架构设计",        // optional user intent
  aggressiveness: 3,             // 1-10
  keywordDensity: 5,             // 1-10
  targetJD?: {                   // optional, for option C
    role: "高级后端工程师",
    company: "某科技公司",
    keywords: ["微服务", "Kubernetes", "高并发"]
  },
  userProfile: {                 // from localStorage
    headline: "...",
    superpowers: [...],
    targetRoles: [...]
  }
}

Response (streaming or non-streaming):
{
  success: true,
  data: {
    variants: [
      { label: "激进", content: "改写后的文本...", approach: "大幅重构..." },
      { label: "保守", content: "改写后的文本...", approach: "精修措辞..." },
      // { label: "定向", content: "...", approach: "..." }  ← only if targetJD provided
    ]
  }
}
```

模型：`deepseek-v4-flash`（轻量快速，3 个方案并行生成可以考虑 batch），非流式（生成量不大，2-3 秒可接受）

## 四、版本管理系统

```
localStorage: lingji-ai-cv

{
  activeVersion: "v2",
  versions: {
    "v1": {
      id: "v1",
      label: "初始版本",
      createdAt: "2026-05-01T10:00:00Z",
      sections: [
        { id: "summary", title: "个人概述", content: "..." },
        { id: "experience", title: "工作经历", content: "..." },
        { id: "projects", title: "项目经验", content: "..." },
        { id: "education", title: "教育背景", content: "..." },
        { id: "skills", title: "技能", content: "..." }
      ],
      source: "manual" | "optimized"    // 来自手动编辑 vs AI 优化
    },
    "v2": { ... },
    "v3": { ... }
  }
}
```

UI 交互：
- 页面顶部下拉菜单：「当前版本: v2 · 后端方向 ▾」
- 选项列表：每个版本一行，显示名称 + 创建日期
- 底部「+ 新建版本」按钮 → 弹出命名输入 → 基于当前激活版本创建副本
- 版本切换即时生效，所有 section 内容替换
- 删除版本：至少保留一个版本
- AI 优化后自动创建快照（`v2 → v2-optimized-1700`），可在设置页管理

## 六、下一步：拆 Change

这个方案涵盖两个密切相关的 change：

| Change | 范围 | 依赖 |
|--------|------|------|
| `cv-version-manager` | 版本管理 + 保存机制 + 评估联动 | 无 |
| `cv-ai-optimize` | Suno 式逐段优化 + 滑块 + 多方案选择 | 依赖 cv-version-manager |

或者合为一个 `cv-workbench` 一次搞定。

建议：**先 cv-version-manager（基建），再 cv-ai-optimize（体验层）**。
