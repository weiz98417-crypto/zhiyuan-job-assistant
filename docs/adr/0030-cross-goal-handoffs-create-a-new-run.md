# Cross-goal handoffs create a new Agent Run

A handoff that changes the user's primary goal or Task Program creates a new Agent Run in the same Conversation through Run Admission, carrying only verified and permitted Artifact references into a new Run Contract. It requires the user to have requested that next goal explicitly, either in an existing multi-goal request or through later confirmation; a legal transition-graph edge alone does not authorize it. A handoff that changes only the responsible specialist within the same goal keeps the current Run and rebuilds that specialist's execution context and permissions. We chose this boundary over swapping the agent and tool list inside the old Run for every legal task-transition edge: a JD Evaluation Run cannot truthfully become a Resume Edit Run while retaining its original goal, Contract, and success criteria, and a report's suggestion to edit a resume cannot itself authorize a new task. This clarifies ADR-0027 without changing its governed transition and approval rules.
