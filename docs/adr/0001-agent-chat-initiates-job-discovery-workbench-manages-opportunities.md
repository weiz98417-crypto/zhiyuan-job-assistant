# Agent Chat 发起岗位发现，岗位发现工作台管理机会池

我们决定将岗位发现拆成两个协作入口：Agent Chat 负责通过对话理解用户目标、展示岗位发现确认、启动岗位发现任务，并在会话中呈现本轮前 5 个岗位发现结果卡；岗位发现工作台负责完整管理岗位机会池，包括全部结果、扫描历史、失败来源、高级筛选、持续岗位发现配置以及批量处理。这样保留对话式发起任务的轻量体验，同时避免把 Chat 做成完整列表页，也避免废弃已有 Discover 页、`scan_queue`、`scan_jobs`、JD 抓取保存和评估衔接能力。

我们不选择“Chat 只跳转到工作台”，因为那会削弱 Agent 化体验；也不选择“Chat 承担全部岗位管理”，因为那会复制岗位发现工作台并让会话界面臃肿。岗位发现结果先进入岗位机会池，只有用户明确保存或评估后才进入 JD 库；未来的持续岗位发现也由岗位发现工作台管理，Agent Chat 只负责引导创建或修改。
