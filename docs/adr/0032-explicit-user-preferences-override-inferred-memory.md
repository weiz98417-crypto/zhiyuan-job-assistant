# Explicit user preferences override older and inferred memory

Only the user's own present job-seeking preference, directed to the assistant in the current interaction, becomes the active preference immediately, with its source and time recorded; conflicting older preferences are invalidated in the fact ledger rather than overwritten. Sensitive constraints such as salary floor, work authorization, or health limitations enter active private memory only when the user confirms their use for job seeking. Quotations, hypothetical examples, past preferences, resume or JD text, and interview answers do not become current preferences merely because they contain preference language; ambiguity requires clarification before any active-preference write. Completing a guided questionnaire may record sourced answers, but does not by itself turn a derived preference into a user-confirmed one. Inferred observations or older documents cannot override an explicit correction, while a resume address remains a fact about the resume and is not silently edited into a different city. We chose this precedence so job discovery and Run Context follow what the user currently wants without destroying historical evidence or confusing a document's content with a live preference. Job-discovery prefill still requires the existing user confirmation before a scan starts.
