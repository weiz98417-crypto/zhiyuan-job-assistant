# Agent 质量使用分层 Eval Run 与发布门禁

我们决定不再把 11 类预制事件运行时 E2E 当作业务能力证明，而是建立确定性合同、合法转换路径、真实模型任务质量、浏览器交互和人工抽检组成的分层 Eval Run。安全、权限、数据归属、工具治理、写入读回、内部信息泄漏和空消息协议使用确定性零容忍门禁；独立固定版本的质量 Judge 按任务 rubric 评分，但不能推翻确定性失败，阈值只能在固定校准样本上形成提案并经显式批准后冻结。评测记录必须绑定代码、模型、提示词、工具、fixture 和 Judge 版本，并持久化到现有 Run Review/Eval Candidate 治理链路，从而让失败可复跑、可比较、可晋升为回归样本。
