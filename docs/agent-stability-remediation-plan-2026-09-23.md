# Agent 稳定性修复方案与执行状态

## 已确认的行为

1. 每条用户输入先取得可查询的接收确认；网络中断后用同一个 request ID 查询归属，不能因确认超时就断言消息未送达，也不能重复创建任务。
2. Agent Run 始终属于发起它的对话。切换到新对话时旧任务继续，任务提示、事件和消息只在所属对话显示，返回旧对话可恢复进度。
3. JD 默认对照用户简历；用户明确要求不匹配时，该限制跟随当前 JD 的重做和追问，新 JD 恢复默认。
4. 用户在 Agent 对话里发送一张简历截图并要求评估时，先评估当前截图；没有 JD 也要给出内容、结构、ATS 可读性、证据缺口及具体建议。有 JD 时才附加岗位匹配。评估不自动保存或修改简历。
5. 截图无法识别时，在同一对话说明无法读取图片并邀请粘贴文字继续。契约、数据库、恢复流程的内部技术文案不得代替用户答复，也不得被重复写入对话。
6. 回答与识图统一使用 `deepseek-flash`。`deepseek-v4.1-flash` 返回 400；线上当前有效链路已使用 `deepseek-flash`，因此它不是已证实的这次线上截图故障原因。

## 实施顺序

1. 只读提取线上当前 release 的源码清单、哈希、工作目录与模型名，在隔离目录建立唯一行为基线；逐项对照本地未提交改动，防止覆盖线上特有的 `submit-conversation-turn.ts`。
2. 以接收确认、迟到响应、截图诊断、契约失败三类复现用例固定现状。记录请求耗时、响应大小、request ID、Run ID 和对话归属，避免把风险误报为已证实根因。
3. 将图片识别结果或持久图片工件交给执行侧，设立独立的只读简历诊断任务；当前截图优先于已保存简历，识别失败转为同一对话的补充文字输入。
4. 让创建请求快速返回必要 ID，较大契约和图片保留在服务端；同一个 request ID 的重试只关联同一个 Turn/Run。前端异步状态变更和展示都校验对话归属。
5. 契约失败保留内部证据，恢复动作受预算和幂等约束；面向用户只输出一次可行动的状态说明，不把校验术语当成最终回答，失败后仍可在原对话继续。
6. 从同一源码基线构建 Web 与 Worker，统一模型配置；跑定向测试、构建和真实 Web 多轮验收，再以可追溯源码哈希发布并监测。版本号在发布前按当前线上版本确定。

## 验收场景

- 仅发送简历截图并说“评估这份简历”：收到当前截图的独立诊断，不要求 JD、不读取另一份已存简历替代、不产生修改提案。
- 同一截图识别失败后粘贴简历文字：原对话继续给出诊断，Agent 不结束对话。
- JD 评估时说“不匹配我的简历”，再说“重新走一次”：两次都不做简历匹配；换一份 JD 后恢复默认匹配。
- JD 截图识别失败：只提示补充清晰原图、JD 文字或链接，不输出内部“落库校验”文案。
- 创建请求超时后重查与重发：只出现一个 Turn 和一个 Run，前端展示真实归属状态。
- 旧对话创建请求晚于切换新对话返回：新对话没有旧任务提示；回到旧对话仍能看到进度。
- 契约验证失败且自动恢复两次：对话至多出现一次面向用户的可行动说明，保留继续输入能力，内部事件可查。

## 线上待核查

## 本地修复状态（尚未发布）

- Run 创建和续传回执已去除原始图片、正文与完整契约；相同 request ID 可查询并回放，续传超时也需按原 ID 确认，避免重复任务。
- 浏览器对尚未确认的 Run 创建保留原 request ID 与输入指纹；同一对话重发相同内容时先回查同一请求，发送失败保留草稿。服务端 5xx、网络故障或确认超时不能被当成明确未接收。
- 图片识别、独立 JD 截图入口、回答及自定义岗位页提取统一使用 `deepseek-flash`；独立入口改用长图分段识别及全扫描超时预算。具体线上超时节点仍需生产请求事件证据确认。
- 局部 OCR 超时但其他图片有足够文字时继续评估并提示缺页；简历截图的模型服务故障不再冒充图片模糊，空模型答复不能当作诊断完成，取消 Run 会中断正在进行的模型请求。
- 简历截图和 PDF 的 Agent 评估改为只读；无 JD 可独立诊断，识别失败允许在同一对话粘贴文字继续，不自动写入活动简历。
- JD 禁止匹配的状态按来源识别：同一 JD 的追问继承，新 JD 重置；评估服务按解析后的 JD 正文保存与读取偏好，避免把简历读取和个人记忆注入交给通用模型循环。
- 契约失败对话只保留一次可继续的用户提示，诊断与恢复事件留在内部；前端任务状态按对话隔离，发送失败可重试，停止按钮请求实际取消。
- 客户端新增默认收起的管理抽屉与版本更新页；`V0.10.7` 条目标明待发布，未伪装成已发布版本。
- 本地验证：216 个测试文件、1081 项测试全部通过；`npx tsc --noEmit`、`npm run lint`、`npm run build:production`、`git diff --check` 均通过。Lint 保留仓库既有警告，无错误。
- 真实线上多轮验收和发布尚未执行。SSH 连接在认证前由服务端关闭；恢复访问后，先只读提取当前 release、Web/Worker 工作目录及源码哈希，确认线上特有文件并建立统一构建基线，再进行发布与回归。
