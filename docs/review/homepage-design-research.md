# 今日手账首页升级：开源与成熟产品逆向调研

- 调研日期：2026-10-07
- 调研对象：纸鸢 Agent「今日手账」首页（`/`）
- 目的：在动手改代码前，确定首页的信息架构、视觉层级和可落地的迭代范围
- 原则：本报告只做调研和方案，不包含实现改动；所有外部结论均链接到官方文档、官方页面或官方开源仓库

## 结论先行

当前首页已经有完整的数据骨架，但它把新闻、指标、漏斗、待办和快捷操作都渲染成同一套 `PaperCard`，用户第一眼看不出“今天最应该做什么”。截图中的大面积背景和细边框让页面有手账氛围，却没有形成主次，因此更像一组并列的模块，而不是一个会帮用户安排求职节奏的首页。

建议采用 **“今日行动台”** 方向：保留暖纸、朱砂、手写标题和背景图，把首屏改成一个明确的「今日焦点」入口；下面用可扫描的行动队列、进展摘要和新闻/目标企业动态承接数据。视觉上借鉴 Linear 的聚焦排序、Notion 的模块化首页、GitHub Projects 的多视图和 Plane 的卡片/视图组合，先做一套有固定默认顺序的首页，再把用户自定义顺序作为后续能力。

推荐优先级：

1. P0：首屏主任务（今日焦点）+ 待办优先级 + 可信的进展摘要。
2. P0：修正数据语义，再做视觉增强；尤其不能让“已发现”和“已评估”显示同一个数字。
3. P1：新闻降级为可折叠/横向摘要，避免它占据首屏核心位置。
4. P1：增加紧凑/舒展密度切换、空状态引导和最近活动时间线。
5. P2：允许隐藏、排序和保存首页模块；不在第一版引入自由拖拽网格。

## 1. 当前实现审计

### 当前页面组成

`src/app/page.tsx:56-87` 在客户端并行拉取 applications、reports 和 offers，再从本地 Dexie 读取面试草稿。页面依次渲染：

1. `journal-heading`：问候语和“今日手帳”标题（`src/app/page.tsx:176-184`）。
2. 行业快讯和目标企业动态，首屏顶部两列并排（`src/app/page.tsx:186-190`）。
3. 五个指标卡：已评估、已投递、面试中、Offer、平均匹配分（`src/app/page.tsx:192-204`；实现见 `src/components/home/HeroMetrics.tsx:67-93`）。
4. 转化漏斗和待办提醒（`src/app/page.tsx:206-210`）。
5. 有数据时显示管线总览（`src/app/page.tsx:212-213`）。
6. 四个快捷操作和每日鼓励语（`src/app/page.tsx:215-261`）。

所有卡片都经过 `PaperCard`：暖色半透明 surface、细边框、统一圆角和轻微阴影（`src/components/design/PaperCard.tsx:14-35`；令牌在 `src/app/globals.css:33-105`）。标题只在 `.journal-heading` 中有一条朱砂左边线和渐变（`src/app/globals.css:343-353`）。整个工作台根据路径使用固定背景图和覆盖层（`src/components/shell/WorkbenchShell.tsx:145-154,255-258`）。

### 做得好的地方

- 颜色和字体已经形成可识别的纸鸢品牌：暖白纸面、朱砂行动色、LXGW 文楷标题和 Noto Sans 正文，适合“手账”而不是通用 SaaS。
- 首屏数据来自服务端，错误和加载骨架存在，且移动端网格会折叠为单列或多列（`src/app/page.tsx:159-172`）。
- 待办有明确入口：面试跟进、即将面试、评估后未投递，点击可回到 `/tracker` 或 `/interview`（`src/components/home/TodoReminders.tsx:43-103`）。
- 快捷操作覆盖评估、追踪、简历和 Agent 四个核心入口，适合作为后续主任务卡的次级操作。

### 造成“毛坯感”的根因

1. **没有主叙事。** 首屏先出现两块新闻，用户还没看到自己的行动；问候语只是标题，没有把“今天做什么”变成一个可点击决定。
2. **层级同质化。** 指标、新闻、漏斗、待办、管线都用相同 `PaperCard` 外壳和相近标题字号，卡片数量多但没有一个视觉锚点。
3. **数据密度不平衡。** 统计数字很小，新闻和待办文本占据较多纵向空间；截图中背景很抢眼，信息反而被稀释。
4. **信息重复。** 指标、漏斗和管线都在讲投递状态，但没有一个明确的“变化/原因/下一步”关系。
5. **漏斗语义存在风险。** `已发现` 和 `已评估` 都使用 `evaluated + applied + interviewing + offers`（`src/app/page.tsx:132-139`），这会让视觉升级放大错误进展感。应先定义“发现”数据源，再将阶段设计成互斥或明确的累计口径。
6. **新闻缺少上下文动作。** `IndustryNews` 和 `CompanyNews` 只展示来源、标题/摘要、时间（`src/components/home/IndustryNews.tsx:56-127`、`src/components/home/CompanyNews.tsx:70-124`），没有标注“为什么和我的目标有关”或“从新闻进入岗位/公司”。
7. **空状态没有路径感。** 大部分模块仅显示“暂无”，未告诉用户完成哪个设置或操作后会出现内容；首页在新用户阶段因此更像空白仪表盘。

## 2. 官方产品与开源项目逆向

下列观察来自 2026-10-07 抓取的官方页面/源码说明；视觉建议是对信息架构和交互模式的借鉴，不复制品牌资产。

### A. Linear：先给“最重要的事”，再展开全部工作

- 官方资料：[My issues – Linear Docs](https://linear.app/docs/my-issues)
- 官方页面明确把 My Issues 定义为“curated view”，并分成 assigned、created、subscribed、recent activity 四个标签；assigned 列表按 urgent、SLA、blocker、cycle、backlog 等焦点顺序分组，再按优先级排序。
- 官方资料还提供 display options、keyboard shortcut 和 command menu，说明首页不是静态列表，而是一个可以快速聚焦和切换视图的工作入口。

**可借鉴：** 把今日手账首屏从“所有模块并列”改为“今日最值得处理的一件事 + 其余行动按紧迫度分组”。可以先显示“今天有面试”“面试后 9 天未跟进”“高匹配 JD 待评估”等 1 个主任务和 3 个次任务；所有其他数据仍可展开查看。

**不宜照搬：** Linear 的优先级和 SLA 适用于团队 issue；求职任务还需要解释原因和证据，不能只用颜色或数字排序。

### B. Notion：模块化 Home，用户可控制显隐和顺序

- 官方资料：[Navigate Notion with the sidebar / Home and My Tasks](https://www.notion.so/help/home-and-my-tasks)
- 官方说明 Home 包含 Upcoming events、Recents、Favorites、Agents、Teamspaces、Shared pages、Private pages 和 Notion apps；My Tasks 与 Inbox 在固定位置提供跨页面任务和通知聚合。
- 官方说明允许用户对 Home 模块执行 Move up、Move down、Hide section，且 Inbox 支持按通知类型过滤和批量操作。

**可借鉴：** 将“今日焦点、待办、最近活动、进展、行业/目标企业动态”设计为模块，而不是把每个模块写死成永远相同的高度。第一版可只提供“隐藏新闻/显示新闻”和固定两种密度；后续再持久化顺序。

**不宜照搬：** Notion 首页承载的是内容空间，模块非常多；纸鸢首页应优先保证求职动作，不能以“可配置”掩盖默认路径不清晰。

### C. GitHub Projects：一份数据，多种视图和可解释字段

- 官方资料：[About Projects – GitHub Docs](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects)
- 官方资料说明 Projects 可以通过 filtering、sorting、slicing、grouping 创建多个视图，并支持 table、kanban、timeline-style roadmap 三种布局；custom fields 可补充日期、数字和单选元数据，Insights 可基于项目数据制作图表。
- 官方资料还说明项目模板可以携带 views、custom fields、workflows 和 insights，减少每次重复配置。

**可借鉴：** 把 applications 当作同一条求职管线，首页提供“今日行动”视图，追踪页提供“按状态的看板”视图，分析页提供“漏斗/趋势”视图；三者共享同一字段和口径。首页卡片应显示状态、公司、岗位、匹配分、下一动作和更新时间，避免只显示一个孤立数字。

**不宜照搬：** 自由字段和大量图表会提高维护成本；第一版只保留对行动有直接帮助的 `nextAction`、`dueAt`、`reason` 三个派生字段。

### D. Plane（开源）：用布局和工作单元建立产品层次

- 官方产品页：[Plane Open Source](https://plane.so/open-source)
- 官方源码仓库：[makeplane/plane](https://github.com/makeplane/plane)
- Plane 官方页面将 work items、cycles、modules、pages、intake、estimates、REST API 和五种 layout views 作为产品能力，并以“现代 UI + 多布局”作为开源项目的核心卖点；官方页面同时给出 AGPL-3.0 和 Docker/Kubernetes 自托管信息。

**可借鉴：** 首页可以采用“一个主工作单元 + 多种信息密度”的卡片体系：主任务卡（高对比）、行动列表（中密度）、统计胶囊（低高度）、新闻条（可折叠）。卡片不是装饰容器，而是带状态、估算、负责人/下一动作的工作单元。

**不宜照搬：** Plane 的项目管理对象和求职对象不同，不能把首页做成完整看板；求职用户需要情绪支持、解释和隐私边界。

### E. Outline（开源）：用“最近、收藏、搜索”降低内容入口成本

- 官方源码仓库：[outline/outline](https://github.com/outline/outline)
- 仓库 README 将 Outline 定位为“beautiful, realtime collaborative, markdown compatible”知识库，并提供架构、前端测试、开发和部署入口。
- 从其公开应用结构可以看到，知识型产品依赖稳定的侧栏层级、搜索和最近内容，而不是把所有文档摘要塞入首页。

**可借鉴：** 在今日手账底部增加“最近活动/最近处理的岗位”时间线，并将搜索、命令面板和快捷操作放在稳定位置；首页只显示少量摘要，详情回到原工作区。

**不宜照搬：** Outline 的核心是文档浏览，纸鸢的首页应围绕行动而不是内容归档。

### F. shadcn/ui：卡片的结构化层次来自 anatomy，而非更多装饰

- 官方组件文档：[Card](https://ui.shadcn.com/docs/components/base/card)
- 官方文档把 Card 拆成 CardHeader、CardTitle、CardDescription、CardAction、CardContent、CardFooter，并说明组件用于承载一个有标题、说明、内容和操作的单元。
- 官方示例的视觉重点是间距、标题/说明层级和可选操作位；卡片本身没有依赖强渐变或复杂插画才能成立。

**可借鉴：** 给纸鸢首页定义三种卡片层级：`feature`（主任务，标题+原因+主按钮）、`standard`（数据/列表，标题+操作+内容）、`compact`（指标/新闻胶囊）。这样在保留 PaperCard 的材质时，也能产生真实的视觉层次。

**不宜照搬：** shadcn 是组件基座，不是完整首页范式；圆角、阴影和颜色仍应遵循纸鸢令牌。

## 3. 跨项目归纳出的设计原则

| 原则 | 页面表现 | 对今日手账的含义 |
|---|---|---|
| 先聚焦，再浏览 | 首屏只有一个最重要动作，其余内容分组或折叠 | “今日焦点”必须在新闻之前，并且有明确 CTA |
| 同一数据，多种视图 | 列表、看板、时间线共享数据源 | 首页只展示行动视图，详情页保留完整漏斗/看板 |
| 模块可控 | 用户能隐藏、排序或切换密度 | 先做默认顺序和隐藏新闻，暂不做自由拖拽 |
| 卡片有 anatomy | 标题、说明、内容、操作位置固定 | 不再让所有卡片只有一个标题和一组数字 |
| 状态有原因 | 数字旁边有变化、来源、下一动作 | “面试中 0”要能引导准备；“待跟进”要写明逾期几天和入口 |
| 装饰服务内容 | 背景、动画和插画强化层级 | 降低背景对比，朱砂只用于 CTA/风险/选中态 |

## 4. 推荐方案：今日行动台（MVP）

### 首屏草图（信息架构）

```text
┌──────────────────────────────────────────────────────────────┐
│  下午好，周三加油                 今日行动台        [⌘K]   │
│  你有 1 件最值得先处理的事                                  │
├───────────────────────────────┬──────────────────────────────┤
│ 今日焦点（feature card）       │ 本周进展（compact metrics）  │
│ 评估「XX 公司 · AI PM」         │ 评估 16  投递 1  面试 0      │
│ 匹配 86 · 原因/证据 2 条         │ Offer 2  平均匹配 3.5       │
│ [开始处理] [查看原因]            │ [查看管线]                  │
├───────────────────────────────┴──────────────────────────────┤
│ 接下来要做（按紧迫度）                         [查看全部]   │
│ ① 面试后 9 天未跟进 · TDCX                         [跟进]   │
│ ② 14 天未投递 · XX 岗位                             [评估]   │
│ ③ 明天 10:00 面试 · XX 公司                         [准备]   │
├───────────────────────────────┬──────────────────────────────┤
│ 最近活动 / 求职节奏             │ 行业与目标企业动态           │
│ 时间线：评估→投递→面试→反馈     │ 横向摘要，默认展示 3 条        │
│ [打开投递追踪]                  │ [刷新] [展开全部]             │
├───────────────────────────────┴──────────────────────────────┤
│ 管线概览：已评估 → 已投递 → 面试中 → Offer      [查看分析]   │
└──────────────────────────────────────────────────────────────┘
```

### 视觉方向

- **主卡对比度：** 首屏只有“今日焦点”使用更明显的朱砂淡底或纸张插页效果；其他卡片用较弱边框和更紧凑 padding。
- **背景克制：** 保留当前工作台背景图，但将首页内容区域加一层更稳定的暖白雾面，避免照片纹理穿过文字；背景只负责情绪，不负责信息层级。
- **排版节奏：** 标题用 LXGW 文楷，正文维持 Noto Sans；主任务标题 20–24px，模块标题 13–14px，说明和时间 12px；数字使用 tabular-nums，避免平均分长小数。
- **状态色：** 朱砂=当前行动/选中；琥珀=逾期/风险；绿色=已完成/Offer；灰色=无数据。不要用多种彩色渐变表达不同模块。
- **动效：** 首屏主卡和列表只做 150–300ms 的进入/状态变化；遵守现有 `prefers-reduced-motion` 规则，避免每张卡独立漂浮。
- **图标和插画：** 继续使用 Lucide 线性图标；若增加插画，只放在新用户空状态或主任务卡角落，不用大图占据数据区域。

### 信息和数据要求

1. 先定义可证明的 `nextAction`：`evaluate`、`follow_up`、`interview_prep`、`review_offer`、`complete_profile`。
2. 每个主任务必须有 `reason`（为什么现在做）、`source`（来自哪个 application/interview/report）和 `dueAt`；缺少数据时显示可操作的设置/创建入口。
3. 修正漏斗口径：`发现` 必须来自岗位发现记录或明确的 source；`评估` 只计评估完成；投递/面试/Offer 使用互斥状态或明确累计说明。
4. 新闻统一为“来源 + 标题 + 与目标的关系 + 时间”；暂时没有关系解释时，显示“行业参考”而不是制造个性化暗示。
5. 首页请求可按一个 dashboard endpoint 聚合，或至少并行请求并对局部失败降级；行业新闻失败不能让整个首页进入 ErrorState。

## 5. 迭代范围与验收

### Phase 0：数据可信度（P0）

- 修正 `已发现/已评估` 的统计口径并补回归测试。
- 给待办定义稳定排序：今天/逾期 > 未来 7 天 > 普通；同优先级按更新时间。
- 为空数据、局部新闻失败和本地面试草稿分别设计状态，不用统一“大空白”。

**验收：** 每个首页数字都能回到一个业务记录或明确口径；同一用户刷新前后排序稳定；局部 API 失败时其他模块仍可用。

### Phase 1：今日行动台（P0）

- 新增 `今日焦点` 主任务卡和“接下来要做”行动列表。
- 将新闻从首屏第一位置移至行动列表之后；默认只显示 3 条，并提供展开。
- 将五个指标压缩为“本周进展”摘要，保留到追踪/分析页查看完整趋势。
- 为 `PaperCard` 增加 feature/standard/compact 三种层级（API 设计先于视觉细节）。

**验收：** 1440px 首屏可看到主任务、主按钮和至少 2 条下一行动；新用户首屏有一个可完成的开始入口；移动端主任务先于新闻，且不需要横向滚动。

### Phase 2：个性化与节奏（P1/P2）

- 支持隐藏/显示新闻、切换舒展/紧凑密度，设置保存到用户偏好。
- 增加最近活动时间线和“本周完成了什么”摘要。
- 对模块顺序采用固定白名单拖拽，而不是一开始允许任意布局。
- 观察首页关键指标：首屏 CTA 点击率、从首页开始的有效动作、待办完成率、新闻展开率、空状态转化率。

## 6. 风险与防护

| 风险 | 可能表现 | 防护 |
|---|---|---|
| 视觉升级掩盖错误数据 | 数字更醒目但口径不对，用户误判求职进展 | 先完成 Phase 0；每个数字显示口径或来源提示 |
| 信息过载 | 把新闻、指标、待办都塞入首屏，用户更难决定 | 主任务只保留一个；其余模块折叠/延后 |
| 个性化造成空首页 | 用户隐藏太多模块后不知道下一步 | 保留不可隐藏的主任务和安全恢复默认 |
| 背景降低可读性 | 纸张图片和文字对比不足，尤其在暗色模式 | 内容雾面层、对比度检查、暗色截图验收 |
| 复杂动效影响性能 | 首页首屏加载变慢或低端设备掉帧 | 只动画主卡/列表，背景不做 JS 动画，关注 LCP |
| 暗示数据个性化 | 新闻标题被误读为与用户目标强相关 | 没有匹配证据就明确标记“行业参考” |
| 求职隐私泄露 | 公司、薪资和简历信息在公共环境被直接展示 | 主卡默认只显示必要字段，详情页再展开敏感信息 |

## 7. 待确认的产品决策

建议先确认以下决策，再进入视觉稿和代码：

1. 是否接受“今日焦点”作为首页唯一主入口，而不是保留新闻置顶？
2. 第一版是否保留当前背景图，只增加雾面层和卡片层级？如果要更花哨，优先选择纸张插画/贴纸式点缀，还是选择大面积摄影背景？
3. 主任务的来源优先级是否定为：临近面试 > 逾期跟进 > 高匹配未处理 JD > 完善画像？
4. 新闻默认展示 3 条并可展开，是否符合“首页少看、详情多看”的取舍？
5. 是否先把首页目标定为“今天完成一个有效动作”，并用 CTA 点击/待办完成率衡量，而不是继续增加卡片数量？
