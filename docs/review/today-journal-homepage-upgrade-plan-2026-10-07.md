# 今日手账首页升级方案（评审稿）

- 日期：2026-10-07
- 状态：待评审，暂不改代码
- 依据：`docs/research/today-journal-homepage-research-2026-10-07.md`
- 设计目标：同时升级信息架构、行动流和美术表达

## 1. 一句话方向

把“今日手账”从一个平铺数据看板升级成“**纸鸢晨报 · 今日行动台**”：用户打开页面先看到今天最值得处理的事，再看到支撑判断的机会管线、节奏数据和外部风向。

“花哨”在这里不是增加装饰数量，而是让注意力、材质、色彩和动效都有明确秩序，形成每天愿意回来的仪式感。

## 2. 目标与非目标

### 目标

- 5 秒内回答：我目前处在哪个求职阶段？今天最应该做什么？
- 让 1 个主行动和最多 3 个次行动成为页面视觉焦点。
- 让指标说明节奏和瓶颈，而不是只报总数。
- 把纸鸢的暖纸、朱砂、手账感升级为完整的材质和版式语言。
- 复用真实服务端数据，保证数据口径可解释、可追溯。
- 桌面端有编辑台般的层次，移动端仍保持行动优先。

### 非目标

- 不在本轮重做岗位发现、简历编辑、追踪器或新闻系统。
- 不新增没有明确决策价值的数据采集。
- 不用装饰替代核心流程可靠性，也不引入假数据填充视觉空白。

## 3. 信息架构重排

### 推荐顺序

```text
页面壳层
  └─ 日期 / 问候 / 今日进度
主舞台：今日焦点
  ├─ 主任务（今天优先处理什么）
  ├─ 主 CTA（直接进入对应模块）
  └─ 一句可解释的状态摘要
行动队列
  ├─ 待跟进
  ├─ 即将面试
  └─ 评估后未投递
求职节奏
  ├─ 阶段路径：评估 → 投递 → 面试 → Offer
  ├─ 本周动作与上周对比
  └─ 当前瓶颈提示
外部风向
  ├─ 行业快讯
  └─ 目标企业动态
快捷入口 / 每日收束
```

### 桌面线框

```text
┌──────────────────────────────────────────────────────────────┐
│  周三 10 月 7 日       今日手账                  [刷新数据]  │
├──────────────────────────────────────────────────────────────┤
│  今日焦点主舞台（约 2/3 宽）          │ 今日进度（约 1/3 宽） │
│  “先跟进 XX 的面试结果”                │ 3/5 项已完成          │
│  原因：已超过 3 天未联系                │ 评估 12 · 投递 5      │
│  [去跟进] [查看机会]                    │ 面试 2 · Offer 1       │
├────────────────────────────────────────┼───────────────────────┤
│  今天要做（带动作按钮的 1~3 条）        │ 阶段路径 / 当前瓶颈    │
│  ① 跟进公司 A [处理]                    │ 评估 → 投递 → 面试 →… │
│  ② 准备公司 B 面试 [准备]               │ “投递转化停滞”          │
├────────────────────────────────────────┴───────────────────────┤
│  外部风向：行业快讯横向条  ·  目标企业动态  ·  查看全部         │
├──────────────────────────────────────────────────────────────┤
│  快速进入：评估 JD / 查看追踪 / 优化简历 / AI 顾问              │
└──────────────────────────────────────────────────────────────┘
```

### 移动端线框

```text
日期 / 问候
今日焦点主卡（主 CTA 固定可见）
今日进度条
今天要做（最多 3 条）
阶段路径（横向滚动）
外部风向（横向滚动）
快速入口（2×2）
```

移动端不把五项指标全部保留为五张卡；它们折叠为一条“进度摘要”，点击后展开细节。

## 4. 核心模块改造

### 4.1 今日焦点主舞台（新增首页编排层）

主舞台不是新增一套业务数据，而是对现有待办和管线做优先级编排：

- 优先级 1：今天面试或未来 48 小时面试。
- 优先级 2：面试后超过 3 天未跟进。
- 优先级 3：评估超过 7 天未投递。
- 无待办时：给出“保持节奏”的轻量建议和主 CTA，例如“评估一份新 JD”。

每个主任务必须包含：对象、原因、预计动作、跳转目标。主 CTA 使用 WarmButton 或等价的高对比按钮，不能只做整卡链接。

### 4.2 今日进度摘要（替代首屏五张平铺指标）

保留现有已评估、已投递、面试中、Offer、平均匹配分口径，但改成：

- 一个环形或横向节奏条：本周已完成动作 / 本周目标（若没有目标，不伪造分母）。
- 三个最重要的数字：正在推进、需要行动、最近新增。
- 其余指标收进“展开详情”，保持信息完整但降低首屏噪音。
- 每个数字附语义标签，例如“投递转化比上周少 2 个”，而不是只放 ↑2。

### 4.3 行动队列（重做待办）

将现有 `TodoReminders` 从只读列表升级为动作队列：

- 每行显示优先级色标、公司/职位、原因、相对时间和动作按钮。
- 默认最多 3 条，剩余内容通过“查看全部”进入对应模块。
- 完成后即时折叠并给出短暂完成反馈；如果后端没有完成接口，第一期只做跳转和已查看态，不伪造完成写入。
- 对无目标公司的新闻空态保留“去设置添加”，但视觉上作为次级 onboarding，不抢主舞台。

### 4.4 阶段路径与瓶颈

把 `PipelineFunnel` 和 `MiniPipeline` 合并成一个阶段模块：

- 横向阶段路径用于恢复上下文，点击阶段进入 `/tracker?status=...`。
- 显示当前数量、最近 7 天变化和下一阶段转化；没有真实阶段数据时显示“暂无数据”，不把相同口径包装成不同阶段。
- “瓶颈”只在有证据时出现，例如已评估增长而已投递没有增长；否则显示“数据不足，继续积累”。
- 保留管线总览的筛选入口，减少重复卡片。

### 4.5 外部风向

新闻从首屏主内容降为轻量信息带：

- 行业快讯和目标企业动态合并为一个“外部风向”区域，默认展示 3 条摘要。
- 使用横向滚动卡或窄栏，避免连续六条文本把首屏撑高。
- 每条内容显示来源、时间和外链；如果无法转成行动，保持为背景信息，不伪装成核心指标。
- 加载、失败和无目标公司的状态都给出清晰动作。

### 4.6 快速入口与每日收束

- 快速入口保留四项，但降低为页面末端的“工具架”，图标和标签做成书签/索引条。
- 鼓励语保留，但放在页尾纸签位置，不与主任务争夺首屏注意力。

## 5. 美术与视觉系统

### 5.1 视觉概念

主方向：**晨报式纸面 + 编辑台式层叠**。

用户感觉像打开一本当天的工作手账：有日期栏、主稿、批注、书签和轻微纸张差异；信息层级像编辑台，关键动作清楚、辅助内容安静。

### 5.2 色彩角色

沿用现有令牌，不先改全局品牌色：

- 暖白瓷：页面底色和大面积留白。
- 深墨：正文、数字和主要标题。
- 朱砂：主 CTA、待跟进、关键节点和风险标记。
- 浅青/鼠尾草绿：已完成、稳定推进、正向反馈，控制在少量语义位置。
- 米灰/纸褐：分隔、纸张层级和背景装饰。

朱砂只负责“现在要注意/要行动”，不再把所有标题和图标都染成同一主色。

### 5.3 层级、形状和材质

- 主舞台使用一张较大、略有纸张边缘和内嵌批注的主卡；辅助卡采用更轻的底色和更短的阴影。
- 卡片不全部使用同一半径：主卡偏纸页比例，列表卡偏便签比例，阶段路径偏窄条。
- 使用 1px 纸边、轻微噪点、折角/书签/印章等局部元素；装饰不覆盖可读内容。
- 阴影用暖纸色低透明度，不使用深黑浮层。
- 标题继续使用手写/楷体，数据和按钮使用清晰无衬线，形成“编辑标题 + 工具正文”的对比。
- 给数字增加 tabular-nums 和足够留白，避免卡片像密集后台表格。

### 5.4 图形和插画

- 主舞台可使用一枚小型纸鸢线稿、日期印章或进度印记作为品牌锚点。
- 阶段路径使用线稿节点和朱砂标记，不使用厚重柱状图填满空间。
- 新闻区域使用来源徽章或小型剪报标签，避免大面积图片导致视觉噪音。
- 插画只表达状态和情绪，不制造虚构岗位信息。

### 5.5 动效节奏

- 首屏加载：主舞台先出现，辅助模块随后以 80~120ms 间隔淡入；减少全页面同时闪烁。
- 阶段路径：节点按顺序轻微描边，不做连续循环动画。
- 主 CTA hover：纸张轻抬 2px，朱砂边缘加深；不要使用夸张缩放。
- 待办完成/已查看：行高收拢、印章淡入，300ms 内结束。
- 尊重 `prefers-reduced-motion`，现有全局规则继续生效。

## 6. 状态设计

| 状态 | 页面表达 | 可行动作 |
|---|---|---|
| 首次使用、无应用 | 主舞台解释产品价值，给“评估第一份 JD”主 CTA | `/evaluate` |
| 有评估、无投递 | 显示评估数量和未投递瓶颈，优先列出可继续处理的岗位 | `/tracker` |
| 有面试待跟进 | 主舞台切换为跟进任务，朱砂强调时效 | `/tracker` 或 `/interview` |
| 全部顺利 | 轻量完成印记和下一步探索入口，避免空白或夸张庆祝 | `/evaluate` / `/discover` |
| 主数据加载中 | 先渲染主舞台骨架和日期，数字区使用与最终布局一致的 skeleton | 无 |
| 主数据失败 | 保留页面壳层，明确“求职数据未加载”，提供重试 | 重试 |
| 新闻失败 | 不影响主数据，新闻区显示失败原因和刷新 | 刷新 |
| 目标公司未设置 | 新闻区给设置入口，不把它升级成全屏阻断 | `/settings` |

## 7. 数据与实现边界

### 现有数据可直接复用

- `applications`：公司、职位、状态、日期、匹配分、更新时间。
- `reports`：评估数量。
- `offers`：Offer 数量。
- `db.interviews`：面试日程草稿。
- 新闻接口：外部风向内容。

### 建议新增的最小派生字段

- `priorityReason`：由现有规则生成的可读原因。
- `actionLabel` 与 `actionHref`：主 CTA 和队列动作。
- `lastActivityAt`：统一使用 `updatedAt`/`updated_at`/`date` 的回退口径。
- `stageDelta`：只有前后周期都有有效数据时显示差值。

这些字段优先在首页编排层派生，不立即改数据库；只有验证首页确实需要跨页面一致的优先级后，再考虑服务端统一。

### 必须修正或澄清的口径

- “已发现”和“已评估”不能继续用相同数字冒充两个漏斗阶段；没有发现数据就合并为“已进入管线”。
- 趋势缺少前周期数据时显示“数据不足”，不显示误导性的 0 或负向结论。
- 新闻是背景信息，接口失败不能让主工作台进入错误态。

## 8. 分阶段开发计划（确认后执行）

### Phase 0：方案冻结与数据核对

- 确认主方向、首屏 CTA、主色角色和移动端优先级。
- 用真实账号数据核对待办排序和漏斗口径。
- 产出低保真线框和状态清单。

### Phase 1：信息架构重排

- 新增首页编排层和今日焦点主舞台。
- 将待办升级为带动作的行动队列。
- 合并阶段路径与管线总览，移除重复展示。
- 保持 API 和真实数据边界不变。

### Phase 2：视觉与交互实现

- 实现主舞台纸面层级、语义色和阶段线稿。
- 加入加载/空态/错误态和轻量动效。
- 完成桌面与移动端断点调整，并验证深色模式。

### Phase 3：验收与调优

- 用有数据、无数据、仅评估、面试待跟进、无目标公司五种夹具验收。
- 检查核心动作点击路径、键盘可达性、对比度和 reduced-motion。
- 对真实数据进行一次首屏 5 秒理解测试，再决定是否继续加装饰。

## 9. 风险与不做事项

- **风险：**主舞台优先级规则误判。缓解：首期只使用现有明确触发条件，并显示原因。
- **风险：**视觉层叠影响可读性。缓解：装饰只在背景和边缘，正文区域保持稳定对齐。
- **风险：**新增图表制造伪精确感。缓解：没有真实分母就不用百分比和目标进度。
- **风险：**新闻抢回首屏注意力。缓解：限制条数和高度，所有外部信息放在行动区之后。
- **不做：**整站换肤、引入重型图表库、增加虚构 AI 总结、重写后端数据模型、重新部署上线。

## 10. 验收标准

### 信息架构

- [ ] 用户不滚动即可看到今日主任务、原因和主 CTA。
- [ ] 主任务最多一个，次任务最多三个；每项都有明确跳转目标。
- [ ] 从首页进入评估、追踪、面试和简历模块不超过一次点击。
- [ ] 阶段路径和管线筛选不重复、不产生矛盾数字。

### 美术

- [ ] 首屏有一张明确主舞台，辅助卡视觉重量低于主舞台。
- [ ] 朱砂只用于行动/风险/当前节点，完成态使用独立语义色。
- [ ] 纸张、书签、线稿或印章至少形成两种可复用的品牌元素，而非一次性装饰。
- [ ] 页面在浅色和深色模式下都有足够对比度，移动端不出现横向溢出。

### 数据与可靠性

- [ ] 所有数字来自现有服务端或明确的本地面试草稿，不引入假数据。
- [ ] 主数据失败时仍保留可重试页面壳层；新闻失败不阻断主工作台。
- [ ] 无有效数据时展示可行动空态，而不是空白卡片。
- [ ] 关键状态和动作可通过键盘访问，并遵守 reduced-motion。
