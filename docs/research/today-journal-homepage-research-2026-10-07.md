# 今日手账首页升级研究记录

- 日期：2026-10-07
- 范围：当前首页实现、数据来源、成熟求职/生产力产品、开源 Dashboard 模式
- 结论用途：为首页信息架构和视觉美术升级提供可审阅证据
- 实施状态：仅研究与方案，未修改生产代码

## 1. 研究问题

首页需要同时回答两件事：

1. 用户打开后能否在几秒内恢复求职上下文，并知道下一步做什么？
2. 页面是否有足够的视觉层次、情绪和品牌记忆，像一个愿意每天打开的个人工作台，而不是数据组件集合？

本次研究把“花哨”拆成可验证的设计问题：注意力顺序、主次层级、状态表达、动作密度、材质与品牌一致性、动效节奏和空态质量。

## 2. 当前实现证据

### 2.1 页面结构

`src/app/page.tsx` 当前顺序为：问候/标题 → 行业快讯与目标企业动态 → 五项指标 → 转化漏斗与待办 → 管线总览 → 快速操作 → 每日鼓励。

现有结构已经覆盖较完整的求职信息，但首屏把新闻、指标和主任务放在同一层级，用户第一眼看不到“今天最值得做的事”。

### 2.2 数据来源与口径

首页并行读取：

| 来源 | 当前用途 |
|---|---|
| `/api/data/applications` | 岗位、公司、状态、日期、匹配分、投递管线 |
| `/api/data/reports` | 已评估数量 |
| `/api/offers` | Offer 数量 |
| Dexie `db.interviews` | 本地面试日程草稿与待办 |
| `/api/news/industry` | 行业快讯 |
| `/api/news/company` | 目标企业动态 |

页面没有依赖首页专用假数据，这是必须保留的信任边界。

### 2.3 主要体验问题

- 五个指标卡、新闻卡、漏斗卡和待办卡使用相近的 `PaperCard` 视觉重量，导致层级扁平。
- “转化漏斗”的“已发现”和“已评估”目前使用相同计算口径，不能作为真实阶段转化来解释。
- 指标只给出数量和周差值，没有把数字翻译成判断，例如“评估增加但投递停滞”。
- 待办能列出事项，但动作按钮、优先级和完成反馈不够突出。
- 新闻占据首屏前段，却没有直接转成岗位、公司或跟进动作。
- 背景纸纹、卡片和标题各自成立，没有组成一套完整的纸鸢视觉叙事。
- 空态、加载态和错误态有基础实现，但缺少明确的下一步和品牌化呈现。

## 4. 证据合成

研究对象虽然视觉风格不同，但有四个共同点：

1. 首页是工作中枢，第一动作比总数更重要。
2. 指标必须关联阶段、趋势或建议，单独的数字价值有限。
3. 主区、辅助区、背景信息区有明显的视觉重量差。
4. 视图服务于恢复上下文，减少用户在多个页面之间重新组织信息。

因此本项目的升级方向不是增加更多卡片，而是建立一条可视的“今日节奏”：今日焦点 → 需要处理的机会 → 管线瓶颈 → 外部风向 → 进入下一工作模块。

## 5. 设计取舍

### 选择

- 保留暖纸、墨色、朱砂和手账字体作为品牌基础。
- 将首屏主舞台让给今日行动，而不是新闻或五项指标。
- 使用一张有层级的主卡配合较轻的辅助卡，避免均匀平铺。
- 让朱砂表达行动和风险，增加少量浅青/鼠尾草绿表达稳定和完成。
- 通过纸张层叠、书签、细线、印章和局部插图增加美术识别度。
- 复用现有服务端数据，新增数据字段前先证明对行动决策有帮助。

### 暂不选择

- 不做满屏玻璃拟态、霓虹渐变或模板化 SaaS 仪表盘。
- 不为了视觉效果引入虚构趋势、虚构岗位或虚构 AI 建议。
- 不把新闻扩成内容社区，也不让首页承担完整岗位发现流程。
- 不在没有真实数据口径的情况下绘制“精确转化率”或伪实时图表。
