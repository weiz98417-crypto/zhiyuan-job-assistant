# 全局导航与应用外壳的产品构造

纸鸢求职助手不是单页聊天工具，而是包含 Agent、职位发现、JD 评估、求职画像、简历管理、投递追踪、面试准备、Offer 评估、数据分析、个人设置和后台治理的完整应用。全局导航与应用外壳决定用户能否在这些模块之间保持方向感，也决定登录态、用户信息、主题、管理员入口和移动端导航如何统一。

这个系统的产品目标是：把多页面求职流程组织成一个稳定的工作空间，而不是一组分散页面。

## 1. 产品定位

在纸鸢里，用户的一次求职动作经常跨多个页面：

```text
Agent 识别 JD
  -> JD 管理生成报告
  -> 简历管理定向优化
  -> 投递追踪记录状态
  -> 面试准备沉淀故事
  -> Offer 评估做最终判断
  -> Analytics 查看整体转化
```

如果没有稳定外壳，用户每次页面切换都会丢失对产品结构的理解。AppShell 的任务不是“放一个侧边栏”，而是把求职流程分组、突出当前页面、保留用户入口、给管理员展示治理能力，并让桌面端和移动端都有可用的导航。

## 2. 入口和关键文件

| 模块 | 文件 | 作用 |
|---|---|---|
| 根布局 | `src/app/layout.tsx` | 注入字体、主题 Provider、AuthGate 和全局样式。 |
| 权限外壳门 | `src/components/shell/AuthGate.tsx` | 登录/注册页不使用 AppShell，其他页面包裹 AppShell。 |
| 应用外壳 | `src/components/shell/AppShell.tsx` | 侧边导航、移动端底部导航、用户信息、admin 入口、退出登录、主题切换。 |
| 导航项 | `src/components/shell/NavItem.tsx` | 根据当前 pathname 判断 active 状态。 |
| 当前用户接口 | `src/app/api/users/me/route.ts` | 返回用户 id、用户名、显示名、角色、状态、tokenVersion。 |
| 退出登录接口 | `src/app/api/auth/logout/route.ts` | 清除 `auth_token` Cookie。 |
| 主题 Provider | `src/components/providers/ThemeProvider.tsx` | 给 AppShell 提供 light/dark 切换能力。 |

AppShell 是前端展示层，不替代服务端权限判断。后台接口仍必须用 `getCurrentUser()` 和角色校验保护。

## 3. 根布局

`src/app/layout.tsx` 做了几件全局事情：

- 设置 HTML 语言为 `zh-CN`。
- 使用 `Noto_Sans_SC` 作为正文字体。
- 引入 `LXGW WenKai` 作为显示字体。
- 设置页面 metadata：标题为“筝筝纸鸢 — AI 求职助手”。
- 用 `ThemeProvider` 包住全应用。
- 用 `AuthGate` 决定是否套 AppShell。

根布局还设置 `body` 为 `h-full overflow-x-hidden`，避免多页面工作台出现横向溢出。

## 4. AuthGate 的实际边界

`AuthGate` 的逻辑很简单：

```text
如果 pathname 是 /login 或 /register
  -> 直接渲染 children
否则
  -> 用 AppShell 包裹 children
```

这意味着登录页和注册页使用全屏布局，不显示侧边栏；业务页面统一显示应用外壳。

需要注意的是，当前 `AuthGate` 本身没有主动校验登录态。真正的用户校验在各 API、页面或中间层里完成。AppShell 会调用 `/api/users/me` 读取用户信息，但这个读取失败只会让用户区域不展示，不等同于服务端鉴权。

这个边界很重要：前端外壳负责体验，服务端负责权限。

## 5. 导航信息架构

桌面端导航不是按代码目录排序，而是按求职流程分组。

### 5.1 顶部固定入口

| 路径 | 名称 | 图标 | 作用 |
|---|---|---|---|
| `/` | 今日手帳 | Home | 回到每日工作台。 |

### 5.2 准备阶段

| 路径 | 名称 | 产品含义 |
|---|---|---|
| `/agent` | 纸鸢Agent | 对话式任务入口，承接跨模块请求。 |
| `/discover` | 职位发现 | 扫描和发现候选岗位。 |
| `/evaluate` | JD 管理 | 管理和评估岗位 JD。 |
| `/profile` | 求职画像 | 沉淀用户能力、目标、偏好和底线。 |
| `/cv` | 简历管理 | 管理简历、优化板块、导出文件。 |

### 5.3 行动阶段

| 路径 | 名称 | 产品含义 |
|---|---|---|
| `/tracker` | 投递追踪 | 跟踪投递、回应、面试和结果。 |
| `/interview` | 面试准备 | 管理故事库、问答和复盘。 |

### 5.4 收尾阶段

| 路径 | 名称 | 产品含义 |
|---|---|---|
| `/compare` | Offer 评估 | 比较薪资、风险和选择。 |
| `/analytics` | 数据分析 | 分析求职漏斗和整体进展。 |

### 5.5 底部入口

| 路径 | 名称 |
|---|---|
| `/settings` | 个人设置 |

这种分组让用户知道每个功能处于求职生命周期的哪个位置：准备、行动、收尾。

## 6. 侧边栏结构

桌面端侧边栏固定在左侧：

```text
fixed left-0 top-0 bottom-0 w-56
```

结构从上到下是：

1. Brand：`筝筝纸鸢` 和 `AI 求职手帳`。
2. 今日手帳入口。
3. 三组阶段导航。
4. 个人设置。
5. 用户信息。
6. 管理员入口。
7. 退出登录。
8. 主题切换。

主内容区对应使用：

```text
lg:ml-56
```

避免桌面端内容被固定侧栏遮挡。

## 7. 当前页面高亮

`NavItem` 使用 `usePathname()` 判断 active：

```text
pathname === href
或 href 不是 "/" 且 pathname.startsWith(href)
```

这样 `/tracker?status=applied` 或 `/admin/users` 这类子路径仍能高亮对应入口。

Active 状态会改变：

- 背景色。
- 文字色。
- 图标色。
- 字重。
- 右侧小圆点。

导航高亮的产品价值是让用户知道自己当前在哪个求职阶段，而不只是知道 URL。

## 8. 移动端导航

移动端不显示桌面侧栏，而是底部 Tab Bar：

```text
lg:hidden fixed bottom-0 left-0 right-0
```

当前移动端只取前 5 个入口：

```text
今日手帳
纸鸢Agent
职位发现
JD 管理
求职画像
```

这是一个明确取舍。移动端底部导航空间有限，优先保留准备阶段和核心入口；简历、投递、面试、Offer、Analytics 等页面仍可通过其他入口或链接进入，但不在底部第一层展示。

移动端底部还额外添加了 `h-16` padding，避免页面内容被底部导航遮挡。

## 9. Agent 工作区特殊布局

AppShell 对 `/agent` 做了特殊处理：

```text
isWorkspacePage = pathname === "/agent"
```

如果是 Agent 页面，主内容容器使用：

```text
w-full max-w-none
```

其他页面使用：

```text
max-w-[1600px]
```

这个设计是因为 Agent Chat 属于工作区页面，需要更宽的对话和工具结果空间；普通页面则保持较强的内容约束，便于阅读和扫描。

## 10. 用户信息和退出登录

AppShell 挂载后调用：

```text
GET /api/users/me
```

成功时得到：

- `id`
- `username`
- `displayName`
- `email`
- `role`
- `status`
- `tokenVersion`

侧边栏底部显示：

- 显示名首字作为头像。
- 显示名。
- 角色：管理员或成员。

退出登录调用：

```text
POST /api/auth/logout
```

服务端会清除 `auth_token` Cookie：

- `httpOnly`
- `sameSite=lax`
- `path=/`
- `maxAge=0`
- secure 由 `shouldUseSecureAuthCookie()` 决定

然后前端跳转到 `/login`。

## 11. 管理员入口

只有当前用户 `role === "admin"` 时，AppShell 才展示后台入口：

| 路径 | 名称 | 作用 |
|---|---|---|
| `/admin/agent-runs` | Agent 运行监控 | 查看 Agent 运行证据和状态。 |
| `/admin/agent-reviews` | Agent 复盘治理 | 管理 Agent 复盘和质量问题。 |
| `/admin/users` | 管理后台 | 用户与权限管理。 |
| `/admin/insights` | 团队洞察 | 团队层面的数据洞察。 |
| `/admin/memory` | 记忆治理 | 治理记忆系统和长期资产。 |

这里的“只展示给 admin”是前端体验层控制，不是安全边界。对应后台 API 仍必须做服务端角色校验。

## 12. 主题切换

AppShell 通过 `useTheme()` 获取：

- `theme`
- `toggleTheme`

当前主题是 light 时，按钮展示 Moon 图标和“深色模式”；当前主题不是 light 时，展示 Sun 图标和“浅色模式”。

这个能力属于全局外壳，因为用户希望任何业务页面都能保持同一主题，不需要每个页面自己实现。

## 13. 动画和 Toast 容器

AppShell 用 `ToastProvider` 包住整个应用外壳，让所有页面都能使用统一 toast。

主内容区域用 `framer-motion` 做轻量页面进入动画：

```text
initial: opacity 0, y 8
animate: opacity 1, y 0
duration: 0.4
ease: [0.19, 1, 0.22, 1]
```

动画不是核心业务能力，但它让多页面切换更像同一个工作空间，而不是硬切页面。

## 14. 产品边界

| 边界 | 原因 |
|---|---|
| AppShell 不负责服务端鉴权 | 前端隐藏 admin 入口不能替代 API 角色校验。 |
| `/login` 和 `/register` 不显示 AppShell | 认证页需要独立全屏布局。 |
| 移动端只显示 5 个主入口 | 底部导航空间有限，避免塞满所有模块。 |
| `/agent` 使用更宽布局 | Agent 工作区需要展示对话、工具、状态和结果。 |
| 用户信息接口失败时不阻断页面渲染 | 业务页面的访问控制应由后端或路由层处理。 |
| 退出登录只清除 auth cookie | 其他本地缓存清理由设置或数据管理功能负责。 |

## 15. 当前实现的限制

当前外壳还有几个可见限制：

- `AuthGate` 名字容易让人误解为完整鉴权，但它实际只决定是否显示 AppShell。
- 移动端导航只取前 5 项，用户从移动端进入 CV、Tracker、Interview 的路径不如桌面直观。
- `AppShell` 读取 `/api/users/me` 后没有显式处理 `status`，比如 inactive 用户的前端提示需要依赖其他层。
- Admin 链接使用 `<a>` 而不是统一 `NavItem`，因此后台子页面高亮体验和主导航不同。

这些限制属于产品和工程演进点，不影响当前多页面主流程可用。

## 16. 验收口径

全局外壳验收时，要看：

- `/login`、`/register` 不显示侧栏和底部导航。
- 普通业务页面显示桌面侧栏或移动底栏。
- 当前路径能正确高亮导航项。
- `/agent` 使用全宽工作区布局。
- `/api/users/me` 成功时显示用户信息。
- admin 用户能看到后台入口，member 用户看不到。
- 退出登录后 auth cookie 被清空并跳转 `/login`。
- 主题切换在不同页面保持一致。

## 17. 产品总结

全局导航与应用外壳是纸鸢多页面产品成立的基础。它把求职生命周期组织成准备、行动、收尾三个阶段，把用户身份、主题、管理员治理、移动端入口和页面内容统一到一个工作空间里。

它的价值不在于“有导航”，而在于让用户在复杂求职流程里始终知道自己在哪里、下一步可以去哪里、哪些入口属于自己当前权限。
