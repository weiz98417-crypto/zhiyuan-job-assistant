# 纸鸢求职助手面试教练、故事库与复盘系统的产品构造

纸鸢求职助手的面试系统，不是题库，也不是让大模型随便问用户几道题。它是一条从目标岗位材料绑定、面试问题生成、单轮回答评分、追问推进、故事沉淀到复盘总结的完整链路。

因此，“面试故事库与复盘看板”不应该单独写成另一个系统。故事库、模拟记录、复盘面板都服务于同一件事：把用户已有经历转成可面试表达的资产，并在每一轮问答后留下可复用证据。

## 1. 产品定位

用户进入面试准备阶段时，真正需要的不是“多来几道题”，而是：

- 题目要贴合当前 JD 和简历。
- 回答后要知道结构、具体程度、亮点和时间控制哪里有问题。
- 面试官追问要基于上一轮回答，而不是随机跳题。
- 用户真实项目要沉淀成 STAR 故事。
- 多轮问答要能形成复盘，而不是让用户重新粘贴前面所有回答。
- 如果用户切换 JD 或简历，系统要知道是继续当前会话，还是重开一轮。

纸鸢的面试系统承担的是“把求职材料转成面试表达能力”的角色：

```text
JD / 简历 / 目标公司
  -> 面试计划快照
  -> 问题生成
  -> 用户回答
  -> 结构化评分
  -> 追问与问题图
  -> 故事库与历史记录
  -> 复盘与下一轮准备重点
```

## 2. 为什么不能只做题库

普通题库只能回答“可能会问什么”，但纸鸢要解决的是“我应该怎么用自己的经历回答这个岗位的问题”。

如果只做题库，会出现几个问题：

- 题目和目标 JD 脱节，用户背了很多泛化问题。
- 用户回答完后只得到鼓励，没有可操作的评分。
- 追问不能沿着用户刚才回答里的细节展开。
- 同一段项目经历无法沉淀，下次换公司又从头整理。
- 复盘依赖用户重新整理聊天记录，系统无法自动提取证据。

所以当前系统以“会话状态”为核心，而不是以“题目列表”为核心。

## 3. 页面入口与代码边界

当前面试主入口是 `/interview`，核心文件包括：

| 能力 | 项目文件或接口 | 产品含义 |
|---|---|---|
| 面试主页面 | `src/app/interview/page.tsx` | 展示面试准备、统计、故事、历史记录和日程 |
| 启动面板 | `src/app/interview/InterviewLaunchPanel.tsx` | 选择 JD、简历、模式、难度和关注点 |
| 模拟记录 | `src/app/interview/PracticeRecords.tsx` | 展示历史问答记录和评分结果 |
| 问题列表 | `src/app/interview/QuestionList.tsx` | 承载生成的问题集合 |
| 复盘展示 | `src/app/interview/InterviewRecapReview.tsx` | 展示结构化复盘结果 |
| Agent 面试历史 | `src/app/interview/AgentInterviewHistory.tsx` | 展示 AgentChat 里的面试状态 |
| 面试会话状态 | `src/lib/agent/interview-session-state.ts` | 维护计划快照、问题图、转写、评分和复盘 |
| 面试引擎 | `src/lib/agent/interview/engine.ts` | 处理面试模式和 Agent 运行逻辑 |
| 生成问题 API | `src/app/api/agent/coach/generate-questions/route.ts` | 根据 JD/简历生成面试题 |
| 回答评分 API | `src/app/api/agent/coach/score-answer/route.ts` | 对用户回答进行结构化评分 |
| 故事库 API | `src/app/api/stories/route.ts` | 保存用户 STAR 故事 |

这些文件说明：面试系统不是一个孤立页面，而是页面、Agent 会话状态、模型 API、故事资产、复盘结构共同组成的产品链路。

## 4. 面试计划快照

`buildInterviewPlanSnapshot()` 会把当前面试使用的材料冻结下来：

```text
InterviewPlanSnapshot
  snapshotId
  source
    jdId
    resumeId
  jdSnapshot
    company
    role
    body
  resumeSnapshot
    title
    body
  mode
  difficulty
  focusAreas
  allowFollowUps
  createdAt
```

这个快照非常关键。用户在准备过程中可能继续修改简历，也可能切换 JD。如果没有快照，当前面试问答会被后续材料变化污染。

测试 `interview-session-state.test.ts` 明确验证了：active AgentChat 的快照是当前会话事实来源，后续准备配置变化不能静默替换正在进行的面试材料。

## 5. 面试会话状态

面试状态不是简单 messages，而是：

```text
InterviewSessionState
  planSnapshot
  status
  questionGraph
  currentQuestionId
  transcript
  scoreArtifacts
  recap
  rebindHistory
```

其中最重要的是 `questionGraph`。它把主问题、追问、探针问题连接起来，而不是把所有内容当成平铺聊天记录。

```text
Q1 主问题
  -> 用户回答
  -> 追问 Q1.1
     -> 用户回答
Q2 主问题
  -> 用户回答
```

这使得系统能知道某个追问是基于哪一个主问题产生的，也能在复盘时把回答、分数、追问表现归到正确位置。

## 6. 问题生成

`/api/agent/coach/generate-questions` 使用 DeepSeek 生成面试题。它接收：

- `jdText`
- `cvText`
- `company`
- `role`
- `mode`
- `count`

当前生成要求覆盖四类题目：

| 类别 | 含义 |
|---|---|
| `behavioral` | 行为面试 |
| `technical` | 技术或专业能力 |
| `case-study` | 案例分析 |
| `culture` | 文化匹配 |

每道题必须包含：

- `category`
- `question`
- `context`
- `storyHint`
- `source`
- `weaknessNote`

如果有 JD，题目要引用 JD 中的具体要求；如果有简历，题目要针对简历可能存在的弱项。这样生成的问题才是岗位相关的，而不是通用题库。

## 7. 回答评分

`/api/agent/coach/score-answer` 对用户回答按四个维度评分：

| 维度 | 含义 |
|---|---|
| `structure` | 结构完整度 |
| `specificity` | 具体程度 |
| `highlight` | 亮点突出 |
| `timing` | 时间控制 |

不同面试模式有不同权重。例如：

- `behavioral` 更均衡地看结构、具体、亮点和时间。
- `structured-sme` 提高具体程度权重。
- `founder` 更重视亮点突出。
- `stability` 更重视结构和时间控制。

输出结果包括：

```text
dimensions
overall
suggestions
segmentFeedback
```

这让用户知道问题出在哪里：是回答没有结构，是细节不够，还是没有突出个人贡献。

## 8. 评分 artifact

评分结果不会只停留在模型文本里。`updateInterviewStateWithToolResult()` 会把 `score_interview_answer` 的结构化结果保存成 `scoreArtifacts`，并挂到当前问题节点上。

每个评分 artifact 包含：

- `id`
- `questionNodeId`
- `answerTurnIds`
- `score`
- `sourceTool`
- `createdAt`

这样复盘时不需要重新解析聊天文本，也不需要用户重新提交回答。系统可以直接根据已记录的问题、回答和评分生成复盘。

## 9. 追问与控制轮次

面试系统区分真实回答和控制类输入。

例如用户说“下一题”“跳过”“给个示范”“不会答”，系统不应该把这些内容当成对当前问题的正式回答。`isInterviewControlTurn()` 会识别这类输入，避免它们污染 `answerTurnIds`。

这解决了真实对话中的一个高频问题：用户在面试过程中会请求提示、示范或跳题，如果系统把这些控制意图当成回答，后续评分和复盘都会失真。

## 10. 复盘生成

`buildInterviewRecapFromState()` 会从会话状态里生成复盘，而不是直接相信用户粘贴的总结文本。

复盘包含：

- `overallVerdict`
- `strengths`
- `weaknesses`
- `followUpPerformance`
- `evidenceFromAnswers`
- `weakSpots`
- `nextPracticePlan`
- `questionFeedback`
- `sourceTurnIds`

系统会统计：

- 已回答的问题数。
- 主问题和追问数量。
- 平均评分。
- 高分维度和低分维度。
- 得分较低的问题。
- 每道题的回答摘录。

测试里特别验证了一个边界：复盘不能让用户重新粘贴前面所有答案，系统必须从已存储 turns 和 scores 里构建。

## 11. 故事库

故事库由 `/api/stories` 提供读写。它保存的是用户真实经历的结构化表达：

```text
title
situation
task
action
result
tags
```

这个结构对应面试表达里最常用的 STAR 逻辑，但产品上它不是“写作方法说明”，而是资产沉淀：

- 同一个项目故事可以在不同岗位下调整重点。
- 用户可以从面试问答中提炼出可复用故事。
- 面试准备不再每次从零回忆经历。
- 后续 JD 评估和面试题生成可以引用这些故事。

所以故事库属于面试系统内部的资产层，不是另一个独立产品。

## 12. 材料切换与重绑

面试过程中，用户可能说：

```text
换成这份简历继续
切换到腾讯 AI 产品经理 JD
这个 JD 也有数据分析要求
```

项目里有 `interview-rebind-policy` 相关测试，覆盖：

- 没有明确 JD/简历引用时继续当前会话。
- 明确切换 JD 时记录 rebind。
- 模糊说“另一份简历”时要求澄清。
- 重开面试和继续当前会话要区分。

`recordInterviewRebind()` 会把切换事件写入 `rebindHistory`，包含 from、to、reason 和 createdAt。

这个能力的产品意义是：面试系统必须尊重当前会话事实，不能因为用户提到另一个 JD 就静默换材料。

## 13. 用户链路

完整链路如下：

```text
用户选择目标 JD 和当前简历
  -> 系统生成面试计划快照
  -> 系统生成岗位相关问题
  -> 用户回答当前问题
  -> 系统按维度评分
  -> 系统基于回答产生追问或推进下一题
  -> 评分 artifact 绑定到问题节点
  -> 用户将优秀表达沉淀成故事
  -> 用户请求复盘
  -> 系统从状态里生成结构化复盘
```

这条链路里，最重要的是材料、问题、回答、评分、复盘之间的连续性。只要中间断了，面试系统就会退化成普通聊天。

## 14. 失败模式

| 失败点 | 典型表现 | 正确处理 |
|---|---|---|
| 没有 JD 或简历 | 题目泛化 | 明确 source 为 general，降低上下文依赖 |
| DeepSeek 未配置 | API 返回未配置 key | 提示配置缺失，不生成假题目 |
| 模型返回 JSON 解析失败 | 无法解析 questions 或 score | 返回失败，不写入状态 |
| 用户控制输入被误当回答 | “下一题”进入评分 | 过滤控制轮次 |
| 追问挂错主问题 | Q3 的追问挂到 Q9 | 通过 questionGraph parentId 绑定 |
| 用户切换材料不清楚 | “换另一份简历”无法定位 | 需要澄清，而不是随机切换 |
| 复盘没有回答证据 | 只输出鼓励文字 | 从 transcript 和 scoreArtifacts 生成证据 |

## 15. 测试与证据

当前项目里有多组测试证明该系统的产品边界：

- `src/__tests__/interview-session-state.test.ts`：验证快照冻结、问题图、评分 artifact、复盘和 rebind history。
- `src/__tests__/interview-rebind-policy.test.ts`：验证 JD/简历切换语义，不让系统静默换材料。
- `src/__tests__/interview-agent-prompt.test.ts`：验证 active interview session state 是 Agent 的事实来源。
- `src/__tests__/interview-agent-prompt.test.ts` 还检查 `questionGraph` 等状态字段，避免 Agent 把面试当普通问答。

这些测试说明：面试系统的关键不是题目数量，而是状态可信、材料稳定、评分可追溯、复盘有证据。

## 16. 产品总结

纸鸢的面试系统可以拆成四层：

```text
材料层：JD、简历、公司、岗位、模式和难度
会话层：planSnapshot、questionGraph、transcript、rebindHistory
评分层：scoreArtifacts、维度评分、回答证据
资产层：故事库、历史记录、复盘、下一轮准备重点
```

它的产品价值是把用户真实经历训练成面试表达，而不是让用户背题。故事库和复盘都属于这个链路的一部分，所以不应被拆成另一个孤立文档。
