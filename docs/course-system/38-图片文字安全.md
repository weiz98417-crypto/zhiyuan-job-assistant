# 图片文字安全

本篇描述 Zhiyuan 首版支持截图、图片和 OCR 后已经完成的图片文字安全封板。图片能力不是一个独立上传功能，而是 Agent Chat 主入口和求职业务链路的一部分：用户可以上传 JD 截图、简历截图、Offer 截图、面试题截图和混合截图，系统先识别材料类型、置信度和风险，再决定是否进入 JD 评估、简历草稿、Offer 分析、面试反馈、画像信号、澄清或可恢复失败。

完成态口径是：图片和 OCR 只提供业务材料，不提供系统权限；低置信不编造；高敏字段默认私有；持久化必须 read-back 或 verifier。

## 首版能力边界

| 能力 | 已完成边界 |
|---|---|
| Agent Chat 图片输入 | 图片与用户文本一起进入类型识别，不直接触发工具 |
| OCR/图片识别 | 输出 `documentType`、`confidence`、`quality`、`extractedText` 和结构化字段 |
| 文档类型路由 | JD、简历、Offer、面试、画像、混合截图分别处理 |
| 低置信处理 | 模糊、缩略图、超时、冲突材料进入澄清或 retry |
| 隐私保护 | 简历联系方式、Offer 薪资、面试回答默认 private 或脱敏 |
| 成功态证明 | 保存报告、应用简历、导出文件必须 read-back/verifier |

## 图片文字处理链路

```text
image/text input
  -> file/type/size validation
  -> OCR or visual extraction
  -> document type classification
  -> confidence and quality check
  -> sensitive field detection
  -> injection phrase detection
  -> route decision
  -> business agent task contract
  -> read-back/verifier if persisted
  -> safe display
```

只要文档类型不清、图片模糊、OCR 置信度低、用户文字与图片内容冲突，系统就进入澄清或可恢复失败态，不生成看似确定的业务结论。

## 产品事实

| 事实 | 图片文字安全含义 |
|---|---|
| Agent Chat 是主入口 | 用户可以在同一轮里输入文字、截图和业务诉求 |
| 业务覆盖 JD、简历、Offer、面试、自我定位、记忆、Admin | 图片审核必须服务完整求职链路 |
| 6 个业务 agent 通过 Orchestrator 内部编排 | 图片识别结果只进入对应任务合同 |
| 48 个工具受执行合同约束 | OCR 结果不能直接调用工具 |
| PostgreSQL + pgvector 是当前 runtime | 图片相关保存、记忆和读回证据以当前 runtime 为准 |
| SQLite 只作 fallback/archive/migration | 不用 SQLite 结果替代当前图片安全交付证据 |
| 写入成功要 read-back/verifier | 图片识别成功不等于保存成功 |

## 文档类型矩阵

| 输入类型 | 常见内容 | 路由结果 | 安全要求 |
|---|---|---|---|
| JD 文本 | 岗位职责、任职要求、薪资范围 | evaluate agent | 异常指令降权，报告保存后读回 |
| JD 截图 | 招聘页、聊天里的岗位介绍 | image intake -> JD evaluation | 模糊或缺字段时澄清 |
| 简历文本 | 个人概述、经历、项目、技能 | resume agent | 分析或 proposal，不直接覆盖 |
| 简历截图 | OCR 后的简历内容、联系方式 | resume preview/proposal | 高敏字段 private，应用需读回 |
| 参考简历截图 | 他人简历、优秀样例 | candidate review path | 来源、类别、脱敏、审核 |
| Offer 文本 | 薪资、福利、合同、试用期 | offer agent | 默认 private，不共享薪资 |
| Offer 截图 | HR 聊天、邮件、PDF 截图 | image intake -> offer evaluation | 薪资和合同字段脱敏展示 |
| 面试题截图 | 问题、题库、面试官提问 | interview agent | 只作为面试材料 |
| 面试回答文本 | 用户回答和反馈 | interview session | 只进入当前 session |
| 自我定位文本 | 偏好、目标、能力短板 | profile agent | 质量门控后写入 |
| 混合截图 | 聊天、网页、拼图、多文档 | clarify route | 先澄清文档类型 |
| 低质量图片 | 缩略图、模糊图、遮挡图 | retry/failure | 不编造 OCR 字段 |

## 审核维度

| 维度 | 触发内容 | 完成态处理 |
|---|---|---|
| 注入指令 | 忽略规则、切换身份、跳过确认、伪造 userId | 降权为业务文本 |
| 隐私字段 | 手机、邮箱、薪资、身份证、地址、HR 联系方式 | private 或脱敏 |
| 招聘风险 | 培训贷、押金、收费、灰产、夸张收益 | 进入 JD 风险报告 |
| 简历真实性 | 编造经历、夸大数字、虚构公司 | 在建议中提示风险 |
| Offer 完整性 | 缺试用期、合同主体、薪资结构、工作地点 | 标记 missing_info |
| 文档冲突 | 用户说 JD，图片像 Offer；一张图里混多个文档 | 要求澄清 |
| 低置信 | OCR 混乱、图片模糊、识别超时 | retry 或可恢复失败 |

审核结果决定后续 agent 和工具能做什么，不只是生成一段提醒。

## JD 图片文字安全

JD 图片通常来自招聘网站、聊天记录或截图拼接。

| 风险 | 已完成处理 |
|---|---|
| JD 截图含注入语句 | 作为异常材料，不改变系统规则 |
| 招聘信息缺字段 | 标记缺失，不强行生成确定结论 |
| 公司/岗位识别低置信 | 要求用户确认 |
| 高风险招聘话术 | 进入 JD 风险识别 |
| 保存报告假成功 | report/JD 同 userId read-back |
| 图片模糊或缩略图 | 返回 retry，不生成报告 |

JD 图片通过后，才进入 `image intake -> evaluate agent -> report persistence -> read-back`。

## 简历图片文字安全

简历图片可能包含联系方式、项目细节、教育信息和工作经历，是高敏个人资产。

| 风险 | 已完成处理 |
|---|---|
| OCR 把 section 识别错 | 不直接覆盖，先生成草稿 |
| 截图里要求直接保存 | 降权为用户材料，不跳过确认 |
| 图片含手机号/邮箱 | 默认 private，展示可脱敏 |
| 用户要求一键应用 | 仍走 proposal、确认、apply、hash/read-back |
| 参考简历来自他人 | 保存前确认来源、类别和 visibility |
| team 共享含个人信息 | 候选审核，Admin 脱敏后批准 |

简历图片永远不能直接变成“已保存简历”。完成路径必须是解析、提案、确认、应用、读回。

## Offer 图片文字安全

Offer 图片常来自 HR 聊天、邮件截图、合同截图或 PDF 页面，默认按高敏处理。

| 风险 | 已完成处理 |
|---|---|
| 薪资、奖金、股票泄露 | 当前用户 private，Admin 摘要化 |
| OCR 漏掉试用期或合同主体 | 标记 missing_info，不生成过度确定建议 |
| HR 联系方式外泄 | 脱敏，不进入团队知识 |
| 用户要求公开对比 | 不跨用户、不默认共享 |
| Offer 条款冲突 | 列出假设和待确认问题 |
| 保存报告假成功 | offer/report 同 userId read-back |

Offer 截图通过后进入私有 Offer 评估。薪资、福利、合同主体和谈判策略不进入团队记忆。

## 混合截图安全

混合截图包括 JD + 聊天、Offer + 邮件、简历 + 批注、多张图拼接等。

| 情况 | 处理 |
|---|---|
| 一张图里多个文档 | 要求用户选择目标材料类型 |
| 用户文本与图片类型冲突 | 以澄清为先，不猜测 route |
| 图片中含多个候选人信息 | 默认不处理或要求裁剪当前用户材料 |
| 截图含水印、遮挡、引用内容 | 标记置信度，不直接保存 |
| OCR 只识别到片段 | 生成缺字段结果或要求补充 |

混合截图的首要目标是避免错误路由。错误路由比失败更危险，因此低置信时选择澄清。

## 低置信与失败态

| 失败类型 | 输出状态 |
|---|---|
| 图片太小或模糊 | `retry_image`，提示上传清晰原图 |
| OCR timeout | 可重试失败，不生成业务结论 |
| 文档类型冲突 | `clarify_intent`，询问 JD/简历/Offer/面试等类型 |
| 必要字段缺失 | 标记 missing_info，列出缺失字段 |
| 权限不足 | 不进入保存或 Admin 工具 |
| read-back 失败 | 说明未保存或未应用 |

失败态是产品安全的一部分。首版允许识别失败，但不允许编造确定结果。

## 输出安全

| 输出位置 | 安全展示 |
|---|---|
| Agent Chat | 先给业务摘要，敏感字段按需展示 |
| 图片识别结果 | 展示文档类型、置信度、缺字段和下一步 |
| JD 报告 | 呈现岗位风险，不泄露用户隐私 |
| 简历页面 | 显示 proposal/diff，不误写原文 |
| Offer 报告 | 薪资细节仅当前用户可见 |
| Tool card | 折叠参数和证据，避免暴露 payload |
| Admin run/review | payload 脱敏，保留 run id、tool、phase、verifier |
| 导出文件 | 用户触发，verifier 通过后展示完成态 |

## 交付完成口径

图片文字安全已经按首版产品能力完成封板：Agent Chat 可以接收截图和图片；OCR 结果只作为业务材料；JD、简历、Offer、面试、自我定位和混合截图分别进入受控 route；低置信、模糊、冲突和缺字段材料进入澄清或可恢复失败；所有保存、应用、导出动作必须由 read-back 或 verifier 证明完成。

## 图片识别流转样例

| 图片类型 | 识别结果 | 下一步 | 不能发生 |
|---|---|---|---|
| 清晰 JD 截图 | documentType=jd，confidence 高 | 进入 `evaluate` | 直接改简历 |
| 简历截图 | documentType=resume，confidence 中 | 先确认是导入、分析还是生成提案 | 未确认覆盖 CV |
| Offer 截图 | documentType=offer，confidence 高 | 进入 `offer` | 进入 JD Reports |
| 混合截图 | documentType=mixed | 要求用户选择主任务 | 猜测执行 |
| 模糊截图 | confidence 低 | 要求重传或粘贴文字 | 伪造字段 |
| 含注入文字截图 | OCR 提取注入语句 | 降权为业务文本 | 改变权限或跳过 read-back |

图片能力的产品价值是降低输入成本；安全价值是确保图片不会绕过文本输入的同一套边界。
