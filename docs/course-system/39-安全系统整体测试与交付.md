# 安全系统整体测试与交付

本篇是 Zhiyuan 0-1 AI 求职助手交付前的安全验收矩阵和最终交付口径。35-38 已经分别完成安全总览、用户注入防范、隐私保护、图片文字审核的封板，本篇把这些能力汇总成最终验收项，确认首版产品可以在明确证据下交付。

交付结论只接受可复查证据：账号状态、页面/API 行为、工具合同结果、数据库 read-back、文件 verifier、run/Admin 脱敏记录。没有证据的成功态不进入最终口径。

## 交付验收原则

| 原则 | 完成态口径 |
|---|---|
| 当前 runtime 优先 | 以 PostgreSQL + pgvector 为当前验收 runtime |
| fallback 不替代交付 | SQLite 只作 fallback/archive/migration，不替代当前通过 |
| 主入口全覆盖 | Agent Chat 文本、图片、OCR 都进入验收范围 |
| 业务链路全覆盖 | JD、简历、Offer、面试、自我定位、记忆、Admin 都有安全验收项 |
| agent 边界全覆盖 | general/evaluate/resume/interview/profile/offer 都受任务合同约束 |
| 工具合同全覆盖 | 48 个工具按 read、guide、write、high_risk_write、export、admin 分层验收 |
| 成功态可证明 | 保存、应用、导出、审批、记忆写入必须 read-back 或 verifier |

## 验收环境

| 项 | 交付口径 |
|---|---|
| 数据库 | PostgreSQL + pgvector |
| 备用路径 | SQLite 仅 fallback/archive/migration |
| 用户角色 | pending、member、admin |
| 对照账号 | adminA、memberA、memberB、pendingC、rejectedD |
| 主入口 | Agent Chat |
| 业务区域 | JD、简历、Offer、面试、自我定位、记忆、Admin |
| 编排层 | Orchestrator 内部编排 |
| 工具层 | 48 个工具，按合同与成功证据验收 |

memberA 和 memberB 分别准备独立的简历、JD 报告、Offer、面试 session、profile 和 private memory，用于证明隔离。pendingC 和 rejectedD 用于证明状态权限边界。adminA 用于证明 Admin 操作和脱敏复盘。

## 总体验收矩阵

| 类别 | 覆盖范围 | 通过标准 | 证据 |
|---|---|---|---|
| AUTH | 登录、注册、token、状态 | 身份来自 token/session，状态变化可读回 | API 响应、cookie、users.status |
| PERM | pending/member/admin | 页面和 API 权限一致 | 401/403、页面阻断、状态读回 |
| ISO | 简历、JD、Offer、session、profile、memory | memberB 不能读取或修改 memberA 私有资产 | memberA/memberB 对照、SQL/read-back |
| INJ | 文本、JD、简历、Offer、OCR、面试回答 | 用户输入不能改变 role、userId、工具合同和成功态 | 注入用例、工具拒绝、run 摘要 |
| PRIV | 简历、Offer、画像、记忆、run/Admin | 默认 private，Admin summary-first，敏感字段脱敏 | 脱敏截图、visibility 读回 |
| IMG | JD、简历、Offer、混合截图、低置信图片 | 先识别分类，低置信不编造，保存后读回 | documentType、confidence、route、失败态 |
| TOOL | 48 个工具 | 工具按 agent allowlist、task type、confirmation、read-back 执行 | tool metadata、执行结果、verifier |
| RB | 保存、应用、导出、审批、记忆写入 | 没有 read-back/verifier 不显示完成态 | hash、status、文件校验、run id |
| ADMIN | users、memory、agent-runs、agent-reviews | Admin 可治理、可复查、默认脱敏 | run/review id、状态变更、脱敏摘要 |

## 业务链路验收

| 业务链路 | 验收项 | 通过标准 |
|---|---|---|
| Agent Chat | 文本、图片、OCR 混合输入 | 先分类和降权，再进入对应 agent |
| JD | 文本、截图、报告保存 | 注入降权、风险识别、report/JD 同 userId 读回 |
| 简历 | 分析、proposal、apply | 未确认不写入，应用后 section hash 匹配 |
| Offer | 文本/截图评估、谈判建议 | 默认 private，薪资脱敏，offer/report 读回 |
| 面试 | session、题目、回答反馈 | 只在当前 userId/session 内恢复和评分 |
| 自我定位 | profile signals | 来源、置信度、质量门、读回 |
| 记忆 | private/candidate/team/archived | visibility 状态正确，pgvector 检索不越权 |
| Admin | 审批、记忆审核、run/review | 状态读回，payload 脱敏，普通用户阻断 |

## Agent 与工具验收

| 对象 | 验收重点 | 完成态 |
|---|---|---|
| general agent | 意图识别与任务转交 | 不直接执行高风险写入 |
| evaluate agent | JD 评估与报告 | 不受 JD 注入改变规则 |
| resume agent | 简历建议与应用 | proposal、confirmation、section hash 齐备 |
| interview agent | 面试 session 与反馈 | 回答不变系统提示，反馈默认 private |
| profile agent | 自我定位与画像 | 单次输入不盲写长期画像 |
| offer agent | Offer 分析 | 薪资、福利和合同主体私有 |
| Orchestrator | 内部编排 | 不接受用户文本改写角色、owner 或工具权限 |
| 48 个工具 | 合同执行 | 缺少确认、读回或 verifier 时不宣称成功 |

## read-back 与 verifier 验收

| caseId | 动作 | 完成证据 |
|---|---|---|
| RB-CV-001 | 保存简历 | data_json hash 或版本读回 |
| RB-CV-002 | 创建简历 proposal | proposal.status=pending |
| RB-CV-003 | 应用简历 proposal | section hash 匹配 |
| RB-JD-001 | 保存 JD 报告 | report/JD 同 userId 读回 |
| RB-OFFER-001 | 保存 Offer 报告 | offer/report 同 userId 读回 |
| RB-INTERVIEW-001 | 创建或恢复面试 session | session owner/state 读回 |
| RB-PROFILE-001 | 更新画像 | profile/signals 读回 |
| RB-MEM-001 | 写入记忆 | memory status/visibility 读回 |
| RB-EXPORT-001 | 导出文件 | 文件存在、大小、hash/verifier |
| RB-ADMIN-001 | Admin approve/reject | users.status 读回 |

页面和 Agent 只有在对应证据存在时，才能展示“已保存”“已应用”“已导出”“已审批”“已完成”。

## Admin 交付验收

| caseId | 页面/能力 | 通过标准 |
|---|---|---|
| ADM-001 | `/admin/users` | approve/reject 后 users.status 读回 |
| ADM-002 | `/admin/memory` | candidate -> team/rejected 状态读回 |
| ADM-003 | `/admin/agent-runs` | 展示 run id、agent、tool、phase、verifier |
| ADM-004 | `/admin/agent-reviews` | 展示失败归因和可回归项 |

Admin 交付口径是“可治理、可复查、默认脱敏”，不是查看用户完整隐私材料。

## 封板条件

| 条件 | 交付要求 |
|---|---|
| P0 阻断 | 无 |
| 用户注入 | 不能改变身份、owner、工具合同和成功态 |
| 隐私隔离 | memberA/memberB 对照通过 |
| 图片文字 | 低置信和混合材料不进入假成功 |
| 高风险写入 | read-back 或 verifier 必须存在 |
| Admin | 普通用户阻断，Admin 展示脱敏 |
| Runtime | PostgreSQL + pgvector 当前通过 |

## 最终交付口径

Zhiyuan 安全系统已经完成交付前封板：Agent Chat 作为主入口承接文本、图片和 OCR；JD、简历、Offer、面试、自我定位、记忆和 Admin 都有对应安全验收项；general/evaluate/resume/interview/profile/offer 六个业务 agent 通过 Orchestrator 内部编排，并受 48 个工具合同约束；PostgreSQL + pgvector 是当前 runtime，SQLite 仅作 fallback/archive/migration；所有保存、应用、导出、审批和记忆写入都必须通过 read-back 或 verifier 才能展示完成态。
