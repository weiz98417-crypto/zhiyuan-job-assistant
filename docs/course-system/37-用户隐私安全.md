# 用户隐私安全

本篇描述 Zhiyuan 在交付前已经完成的用户隐私安全封板。隐私安全不是只隐藏手机号和邮箱，而是把 AI 求职助手里的数据资产先分级，再按 owner、visibility、runtime 和展示面隔离，确保简历、Offer、职业画像、记忆、run 记录和 Admin 视图都在明确边界内流转。

完成态口径是：默认私有、最小展示、可控共享、可复查但不裸露、保存与导出可证明。

## 项目事实

| 事实 | 隐私安全含义 |
|---|---|
| Agent Chat 是主入口 | 用户会在同一入口提交文本、截图、简历、Offer 和面试材料 |
| 业务覆盖 JD、简历、Offer、面试、自我定位、记忆、Admin | 隐私分级要覆盖从采集到复盘的完整求职资产 |
| 6 个业务 agent 是 general/evaluate/resume/interview/profile/offer | 每个 agent 只能读取当前用户和当前任务允许的数据 |
| Orchestrator 是内部编排层 | 编排上下文不能扩大 userId、visibility 或 Admin 权限 |
| 工具体系有 48 个工具 | 读、写、导出和 Admin 工具都要遵守 owner 与成功证据 |
| PostgreSQL + pgvector 是当前 runtime | 行级归属、向量检索和 read-back 证据以当前运行态为准 |
| SQLite 只作 fallback/archive/migration | 不用 SQLite 结果替代当前隐私隔离通过 |
| 写入成功要 read-back/verifier | 保存、导出、审批和记忆晋升都要有证据 |

## 数据资产分级

| 等级 | 数据资产 | 默认策略 |
|---|---|---|
| S0 公开业务知识 | 通用岗位知识、公开 JD 术语、非个人行业信息 | 可进入团队知识，但仍保留来源 |
| S1 求职过程数据 | 目标岗位、投递状态、JD 报告、面试计划 | 当前 userId 私有 |
| S2 高敏个人资产 | 简历正文、项目经历、手机号、邮箱、Offer 薪资 | 当前 userId 私有，展示时按需脱敏 |
| S3 决策与画像资产 | 职业定位、能力短板、偏好、面试反馈、谈判策略 | 当前 userId 私有，写入需质量门和读回 |
| S4 安全与复盘资产 | tool payload、run step、错误摘要、Admin 操作 | Admin 可治理，敏感字段脱敏 |
| S5 共享候选资产 | 参考简历、优秀表达、可复用求职方法 | 脱敏、候选状态、Admin 审核后才可 team 可见 |

分级结果决定数据能否被保存、检索、展示、导出、共享和复盘。任何没有明确共享路径的数据，都按 private 处理。

## 隐私隔离主链路

```text
auth token / session
  -> userId / role / status
  -> API route authorization
  -> repository scope(userId, visibility)
  -> PostgreSQL row ownership
  -> pgvector metadata filter
  -> read-back with owner/status
  -> safe display
  -> Admin summary-first review
```

核心 API 不信任客户端 `user_id`。即使请求体、工具参数或 OCR 文本里出现另一个用户 ID，服务端仍使用 token/session 中的 userId 作为 owner。

## Runtime 口径

| Runtime | 交付角色 |
|---|---|
| PostgreSQL + pgvector | 当前 LAN runtime，隐私隔离、记忆检索和 read-back 证据以它为准 |
| SQLite | 只作 fallback/archive/migration，不作为当前交付通过证据 |

隐私验收必须基于 PostgreSQL + pgvector 的当前运行态。SQLite 数据存在不代表当前产品隔离已经通过。

## 默认可见性策略

| 产品对象 | 默认可见性 | 共享条件 |
|---|---|---|
| 简历 | private | 用户主动导出，或参考简历脱敏后进入候选审核 |
| 简历 proposal | private | 只有 owner 可确认和应用 |
| JD 报告 | private | 用户主动导出或分享文件 |
| Offer | private | 默认不共享薪资、福利、合同主体 |
| 面试 session | private | 不默认共享 |
| 职业画像 | private | 仅用于当前用户推荐和 Agent 上下文 |
| 私有记忆 | private | owner 可检索 |
| 共享候选记忆 | candidate | Admin 审核前不可被其他用户检索 |
| 团队知识 | team | 必须脱敏、分类、审核、状态读回 |
| run/Admin 证据 | admin/review | 可复盘，敏感字段脱敏 |

## 简历隐私

简历是最高风险个人资产之一，包含经历、项目、教育、联系方式、成果数字和职业叙事。

| 隐私风险 | 完成态控制 |
|---|---|
| 跨用户读取简历 | `cv_data` 查询带当前 userId |
| Agent 写入错误 owner | repository 层带 userId，不信任参数 owner |
| 未确认覆盖简历 | proposal -> confirm -> apply -> read-back |
| 修改后假成功 | section hash 读回一致才显示已应用 |
| 参考简历误共享 | 先确认来源、类别、visibility，再进入审核 |
| Admin 看到完整原文 | summary-first，手机号、邮箱、身份证、内部项目名脱敏 |

简历相关输出可以服务当前用户的编辑和优化，但不能被默认沉淀成团队样例。

## Offer 隐私

Offer 涉及薪资、奖金、股票、社保、公积金、试用期、合同主体、地点、汇报关系和谈判空间。

| 隐私风险 | 完成态控制 |
|---|---|
| 薪资被其他用户读取 | offers/offer_reports 按 userId 范围读取 |
| Offer 进入团队记忆 | 默认禁止，除非用户提交脱敏候选并审核通过 |
| Admin 页面裸露薪资 | 展示摘要、区间或遮罩字段 |
| 谈判策略被复用 | 私有 report，不默认共享 |
| 保存错公司或岗位 | offer/report read-back 校验 owner、company、role |
| 导出假成功 | 文件 verifier 通过才算完成 |

Offer 分析可以给当前用户明确建议，但不把完整薪资结构写入公共知识或 run 可见 payload。

## 职业画像与面试隐私

职业画像和面试反馈记录的是能力短板、偏好、表达方式、风险承受度和未来方向，属于 S3 决策资产。

| 数据 | 隐私边界 |
|---|---|
| profile | 当前用户私有 |
| profile_signals | 当前用户私有，写入前有来源和质量判断 |
| 自我定位回答 | 只作为画像信号候选，不因单次输入永久写死 |
| 面试 session | 当前 userId 私有，恢复上下文需 owner 匹配 |
| 面试回答 | 只用于当前 session 评分和反馈 |
| 面试反馈 | 可写 private memory，不默认 team |

画像更新必须有来源、置信度、质量判断和读回。面试材料不能被默认拿给其他用户做样例。

## 记忆隐私

| 记忆状态 | 可见性 | 检索规则 |
|---|---|---|
| private | owner 私有 | pgvector 检索必须带 owner/visibility |
| candidate | 候选审核 | 仅 owner/Admin 可见，不能被普通团队检索 |
| team | 团队可见 | 必须脱敏、审核、状态读回 |
| archived | 归档 | 不参与默认检索 |
| rejected | 拒绝共享 | 不进入团队检索 |

共享不是从“写入”开始，而是从“脱敏、候选、审核、状态读回”开始。未审核内容即使已经存储，也不能被其他用户检索。

## run 与 Admin 隐私

run 和 Admin 视图用于交付复盘、失败归因和安全验收，但它们不能变成隐私仓库。

| 视图 | 可见内容 | 必须脱敏或隐藏 |
|---|---|---|
| `/admin/users` | 用户状态、审批所需字段、token 版本信息 | password_hash、secret、完整敏感资料 |
| `/admin/memory` | 摘要、来源、状态、风险标签 | 未脱敏原文、个人联系方式 |
| `/admin/agent-runs` | run id、agent、tool、phase、verifier、失败类型 | 完整 payload、base64、薪资细节、简历原文 |
| `/admin/agent-reviews` | 失败归因、改进建议、eval candidate | 敏感输入正文 |
| `/admin/insights` | 团队层统计和趋势 | 单个用户隐私资产 |

Admin 看到的是治理证据，不是用户的完整求职档案。

## 脱敏规则

| 内容 | 展示方式 |
|---|---|
| 图片 base64 | `[image]` |
| 邮箱 | `[email]` |
| 手机号 | `[phone]` |
| secret/API key/token | `[secret]` |
| 身份证、精确地址 | `[sensitive_id]`、`[address]` |
| 完整薪资结构 | 当前用户可见；Admin 侧摘要化 |
| 简历原文 | 当前用户可见；Admin 侧 summary-first |
| 错误堆栈 | 保留类型、phase、定位和 run id，去除 payload |

脱敏不能把证据删到不可复查。run/review 仍要保留 tool、phase、failure type、verifier、owner 范围和安全摘要。

## 共享晋升流程

```text
private material
  -> user intent to share
  -> classification
  -> de-identification
  -> candidate status
  -> Admin review
  -> status read-back
  -> team visibility
```

只有完成这条链路的数据，才可以作为团队知识。参考简历、优秀表达、失败样本和求职方法都必须走同一套状态机。

## 验收矩阵

| caseId | 场景 | 通过标准 |
|---|---|---|
| PRIV-CV-001 | memberB 读取 memberA 简历 | 失败或返回 memberB 自己的数据 |
| PRIV-CV-002 | memberB apply memberA proposal | 失败，不改变 memberA 简历 |
| PRIV-JD-001 | memberB 查询 memberA report_num | 404、空结果或 owner 不匹配 |
| PRIV-OFFER-001 | memberB 查询 memberA Offer | 404、空结果或 owner 不匹配 |
| PRIV-SESSION-001 | memberB 恢复 memberA 面试 session | 失败或空结果 |
| PRIV-PROFILE-001 | memberB 读取 memberA profile | 不返回 memberA 画像 |
| PRIV-MEM-001 | private memory 检索 | 只有 owner 可见 |
| PRIV-MEM-002 | candidate memory 检索 | 非 owner 和非 Admin 不可见 |
| PRIV-MEM-003 | team memory 检索 | 只返回审核通过的脱敏内容 |
| PRIV-RUN-001 | Admin 查看 run | payload 脱敏，证据保留 |
| PRIV-ADMIN-001 | Admin 用户页面 | 不展示 password_hash 和敏感原文 |
| PRIV-EXPORT-001 | 导出简历或报告 | 当前用户触发，verifier 通过 |

## 完成标准

1. 简历、JD、Offer、面试、画像、记忆都按 userId 或 visibility 建立边界。
2. 核心 API 不信任客户端 `user_id`。
3. PostgreSQL + pgvector 是当前隐私验收 runtime。
4. SQLite 只保留 fallback/archive/migration 角色。
5. private/candidate/team/archived/rejected 状态可读回。
6. Admin 视图 summary-first，并对敏感字段脱敏。
7. run/review 保留复盘证据，同时不裸露隐私 payload。
8. 保存、导出、审批和记忆晋升都有 read-back 或 verifier。

## 交付完成口径

Zhiyuan 的隐私安全已经按求职数据资产完成封板：用户的简历、Offer、画像、面试反馈和私有记忆默认只归当前 userId；团队共享必须经过脱敏、候选、Admin 审核和状态读回；run/Admin 提供可复查证据但不裸露敏感原文；PostgreSQL + pgvector 承载当前隔离与检索证据，SQLite 不作为当前交付通过依据。

## 隐私分级样例

| 内容 | 隐私级别 | 默认处理 |
|---|---|---|
| 当前简历全文 | 高 | private，仅当前 userId 可读 |
| Offer 薪资和福利 | 高 | private，不进入团队知识 |
| 面试回答 | 高 | 当前 interview session 内使用 |
| 职业偏好 | 中 | private profile signal，可撤回 |
| JD 原文 | 中 | 用户范围内保存，公共来源需标注 |
| 通用简历表达规则 | 低 | 可进入 team_pending，审核后 team |
| run 证据 | 中 | 摘要、tool、phase、verifier，可脱敏复查 |

隐私安全的关键是“先分级，再流转”。没有分级，就无法决定哪些内容能展示、能保存、能共享。
