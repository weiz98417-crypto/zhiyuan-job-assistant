## 0.15.0 地基车（Spec 24 f-factuality-gate + Spec 25 g-knowledge-registry）

**f 产物事实校验**（ADR-0041）：
1. **与 A1 的关系**：前序计划 A1 已把 LLM 评分器（faithfulness/幻觉）接进 eval 编排层（release 门禁阻断），但生产 verify 位置仍无校验（llm-scorers 自述「仅在 eval 样本集运行」）。本条把评分器推进 `optimize_resume_section` / 简历生成的生产验证位，并新增 A1 没有的确定性检查。
2. 数字溯源规则引擎：优化/生成产物中每个数字必须能溯源到原简历、参照 JD 或用户确认记录；不可溯源的内容**不得进入简历草稿工件**；带具体违规反馈自动重试一次，仍失败该 section 保持原文、提案说明原因。
3. faithfulness 低分降级为「仅供参考」提案（软门）；格式守门不变、先行。
4. ATS 规则化：联系方式格式、section 完整性、格式风险（特殊字符/日期不一致）转确定性规则；量化数据与岗位关键词保留 LLM 判断。
5. PDF 反测进 CI：generate-cv-pdf 渲染 → 解析回文本 → 对照结构化源，数字/关键词丢失即 fail。
6. promptfoo 红队：核心集 ~30 用例（提示注入/PII）进每次 PR CI；全量 200+ 发布前跑。JD 与简历按不可信输入处理。

**g 知识注册表**（C6）：
1. 统一注册表：所有 prompt 片段与领域数据（modes/、registry/agents/*/agent.md、skills/、interview-prep/、服务内嵌字符串）登记版本、来源、行数、last-reviewed；服务内嵌 prompt（出题 3 行/评分 2 行/ATS 1 条）全部迁入。
2. 中文为唯一事实源：`modes/` 顶层的英文镜像由脚本从对应中文生成（LLM 翻译+人工过目 diff 入库；英文独有文件标注 legacy 保留），加 drift 检测护栏（风格同 verify:tokens）。modes 目录真实结构、8 处加载点清单与 frontmatter/YAML 兼容策略见 Spec 25。
3. 删除死接线与重复：jd-signals.ts 从未触发的 `detectSignals` 函数删除、23 条词表以 glossary 语义迁入注册表（不并入 risk-intel——风险判定与速查词汇消费语义不同）；COMPANY_MODE_MAP 双份合一；A-G 权重三处（agent.md/scoring-dimensions.yml/evaluation-scoring.ts）收敛到注册表单源。
4. 清环境混淆：服务端 prompt 构建中的 `fetch localhost:3000` 自调用（resume-agent.ts:34 / evaluate-agent.ts:78）与 buildSystemPrompt 里的 localStorage 读取（interview-agent.ts:126）。

**门禁**：数字溯源正反例单测；ATS 规则单测；PDF 反测回归；drift 护栏；promptfoo 核心集绿；合并前后各跑一次 eval harness 记录基线。

## 0.16.0 评分车（0.16a · Spec 26 h-interview-rubric）

1. rubric 移植（ADR-0042）：LuJie evaluation-rubric 按纸鸢方言改写（保留 0-4 锚点/证据引用/三态区分结构），Apache-2.0 致谢进 NOTICE。评分输出必须引用回答原文；无引用作废重评。
2. **veto 代码纪律（沿前序计划 A1）**：评分器只产出规范 veto 代码（如 `missing_evidence_citation`），不输出自由文本——`HARD_VETO_PATTERNS`（staging-judge.ts:34-50）会静默丢弃不含已知词根的自由文本 veto；随本批扩展该正则。
3. 30 个锚定校准样例（4 维×5 档×主力岗位族）：LLM 起草 + 人工校对，进 eval fixtures 成为回归测试——同一答案重跑，档位波动 >±1 档即 fail。
4. 延迟入账：单场分数只进复盘报告；同一弱项跨 ≥3 场持续才提炼趋势事实入私人记忆分区（ADR-0034 治理，用户可纠正可清除）。
5. 逐题复盘固定格式：题目/回答摘要/有效证据（带引用）/主要缺口/三态判定（不会 vs 没说清 vs 未呈现）/更好的回答结构（给提升思路不代写，信息不足输出「需要你补充」）。

**门禁**：锚定样例回归全绿；veto 路径测试（含代码不被正则丢弃断言）；趋势入账治理测试（3 场阈值、分区、可清除）；eval harness 基线对比。

## 0.17.0 题库车（0.16b · Spec 27 i-question-bank-engine）

1. 题库 schema（Postgres 新表 + pgvector embedding 列，复用 reference-resume-vector 检索模式；**Postgres-only，不做 SQLite 降级**——本地开发统一 Postgres，2026-10-03 用户确认）：题目（题干/考查点/岗位族/轮次/难度/出处标签/答案要点）+ 面经条目（公司/岗位/轮次/日期/原文链接/标签，表先建空、采集按 ADR-0043 后置）。
2. 岗位族两级分类：一级 AI 产品/算法做深；二级通用技术岗 + AI 业务岗（AI 运营/AI 售前等）同 schema 扩展。
3. 出题引擎深接口：输入「岗位族×轮次×难度 + 简历/JD 上下文」→ 输出带出处标签的题目卡；内部 = SQL 过滤 → 向量召回 → LLM 定制改写。调用方（面试教练、JD 评估 F 板块·面试准备、岗位精选点评）只见这一个接口。
4. 种子题库：LLM 生成 + 出处标签，一级岗位族每族 150-200 道主问题，二级每族 50-80 道；10% 人工抽检记录在案。JavaGuide/doocs 语料作二级扩展（license 干净，署名遵守 CC-BY-SA/NOTICE）。
5. 状态机单写者（ADR-0044）：durable 引擎为面试状态唯一写者，questionGraph 降为纯投影，删除从消息正则推断题型的逻辑；行为等价验收沿用源码契约测试重定向模式。**砍法预案：本列车超期时此项第一个后置，但不得拆出第三种变体。**

**门禁**：出题引擎测试（过滤/难度分布/出处必带/去重）；状态机行为等价；种子抽检 10% 记录；eval harness 基线。

## 0.18.0 飞轮车（Spec 28 j-salary-benchmark + Spec 29 k-outcome-feedback-loop）

**j 薪资基准**（ADR-0043）：
1. 岗位机会表加薪资区间字段：从 JD 文本确定性正则抽取（与 JD 风险引擎同路数）。
2. 基准条目 schema：城市×岗位族×年限段 → P25/P50/P75，带来源（静态参考/实时聚合）、样本量、时间窗。
3. 覆盖规则：样本量 ≥30 且 12 个月内的 JD 才计入聚合；达标显示「实时聚合·N 条样本」，未达标显示静态 seed 带「静态参考」标注。JD 评估 D 板块引用必带来源，估算不计入总分。
4. 两套静态数据合一（salary-benchmarks.ts 并入 risk-intel 46 条为统一 seed）。

**k 投递回流**：
1. 投递状态变更（投递→笔试→面试→offer/拒）作为确定性完成事件即时写记忆账本（复用 M5 管线，JD 评估完成同款）。
2. 拒信解析一期只做用户粘贴文本 → 封闭原因标签集（简历不匹配/已招满/薪资不匹配/流程无回应/其他+自由文本）→ 用户确认 → 入账。不做邮箱集成。
3. 面试复盘「有效证据」沉淀为经历故事册候选，用户确认入库。
4. prefFit 用真实反馈替换恒 50：用户拿到面试的岗位特征加权；样本 <5 时保持 50 但显示「数据不足」标注。

**门禁**：薪资阈值单测（<30 样本必须静态标注）；拒信标签正反例；回流治理测试（未确认不入账）；prefFit 样本阈值测试；eval harness 基线。

## 风险与依赖

- 最大风险：0.16b 体量最大（schema + 种子 + 引擎 + 状态机收敛），超期预案已定（砍状态机收敛后置，不拆变体）。
- 评分锚定的校准质量取决于人工校对投入（30 样例约 1-2 天）；样例不合格会让 0.17 回流数据失真——先过 0.16a 门禁再开 0.17。
- 种子题库质量靠 10% 抽检兜底；LLM 生成题目必须带出处标签，无标签不入库。
- 0.17 薪资聚合早期样本不足，静态 seed 长期是默认显示——这是预期行为不是缺陷。
- promptfoo 全量集只在发布前跑，CI 只跑核心集，避免 PR 流水线变慢。
- Spec 20-22 已合并（9dd741b/2d5dfd0/d2c52c6），Spec 23（扫码登录）仍为设计稿未实施——0.15 开工无现实冲突，但动 scan/JD 相关文件前留意 spec 20/21 刚落地的读回调与投递确认代码。
