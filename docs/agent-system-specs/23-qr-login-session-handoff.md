# Spec 23: QR Login Session Handoff For Browser Tools

**Target label:** `proposed`（设计轮候选，未定稿——本 spec 先冻结问题边界与约束，方案在专门设计轮定）  
**Depends on:** Spec 16、ADR-0008/0009（Run Gate 治理语义）、ADR-0033（敏感数据的清除先例）；批次第二期

## Problem Statement

浏览器工具的第一期范围是匿名页面（Spec 16 Out of Scope 明确不做登录态），而允许清单里的五大招聘站几乎全部内容都在登录墙后——治理链路完整但能力被登录墙锁死。开源世界已验证可行模式：扫码登录交接 + storageState 会话保持（MediaCrawler，53k star，中文平台事实标准；注意其许可证禁止商用，只能借模式不能抄代码）、反指纹层（Patchright/Camoufox）。这些证明「做得到」，剩下的是工程与治理决策。

## Solution（方向，待设计轮定稿）

用户在对话中发起「连接某招聘站」→ 系统弹出受控浏览器窗口（有头、非 agent 控制）→ 用户自行扫码/登录 → 登录后的 storageState 加密落库 → 之后的无人值守浏览器会话注入该 storageState。登录会话的每一次使用都是写意图治理下的工具尝试；会话数据按记忆清除同等的标准对待（用户可删除，删除要跨层读回验证）。

## Key Questions For The Design Round

1. **存储**：storageState 是凭据。加密方案（密钥管理）、存放位置（独立表 vs 对象存储）、保留期、以及用户删除时跨层清除的验收边界。
2. **治理**：注入登录态的浏览器会话里，「写动作」的边界要不要比匿名会话更严？登录态下的自动操作等于以用户身份行动——默认全部过 Run Gate，还是维持现有读/写分级？
3. **风控与合规**：目标站点的服务条款边界；检测对抗（是否引入 Patchright 级别的补丁）不做预设，作为观察项。
4. **会话生命周期**：过期检测（401/登录页跳转的特征）、失效后的用户提示与重新交接流程、多站点多会话的归属模型（每用户 × 每站点一份）。
5. **投放顺序**：优先哪个站点（以匿名可达性与用户价值排序，不预设 BOSS 直聘）。

## Out of Scope（本 spec 不做任何实现）

- 不实现存储、注入、交接 UI 的任何部分。
- 不引入 MediaCrawler 代码（许可证禁止商用）或任何验证码自动破解组件。
- 不改变 Spec 16 匿名会话的治理分级。

## Further Notes

- 2026-10-02 与用户定：第一期保持匿名范围，本能力立为第二期第一个设计轮。解锁的真实价值：浏览器工具的问答与抽取覆盖主要招聘站内容；岗位发现扫描的登录态来源质量。
- 设计轮产出应为：加密存储 ADR + 治理分级决策 + 本 spec 升级为 ready-for-agent。
