# Spec 12: User Memory Governance

**Target label:** `ready-for-agent`
**Depends on:** Specs 08–11、ADR-0028、ADR-0032、ADR-0034

## Problem Statement

用户不知道系统从闲聊、任务结果和行为反馈中记住了什么，也难以把错误记忆纠正为当前事实。偶然提及的个人信息、一次忽略岗位或模型推断若直接成为活跃记忆，可能扭曲推荐；管理员若默认看到私人记忆，则会暴露超出团队治理所需的信息。

## Solution

提供用户本人管理私人记忆的入口，展示内容、来源和状态，分开处理确认、记忆纠正与记忆清除。闲聊个人事实只进入 30 天待确认列表；用户可以关闭自动发现，或主动提出“请记住”并当场确认。写入和读取统一遵守当前明确求职偏好、敏感信息准入、复核期限与角色权限，后台只治理团队共享候选和脱敏指标。

## User Stories

1. 作为求职者，我希望在记忆管理页查看自己的私人记忆、来源和状态，从而知道系统在使用哪些事实。
2. 作为求职者，我希望闲聊中偶然提到的个人事实先成为个人记忆候选，从而不会在未经确认时改变推荐。
3. 作为求职者，我希望待确认候选集中显示并只收到轻提示，从而不被每一句话打断。
4. 作为求职者，我希望直接说“请记住”时当场确认具体事实，从而能主动保存重要信息。
5. 作为求职者，我希望 30 天未确认的闲聊候选自动清除，从而不积累长期悬置的个人信息。
6. 作为求职者，我希望首次使用时了解默认开启的自动候选发现，并能关闭它，从而控制闲聊是否产生新候选。
7. 作为求职者，我希望关闭自动发现后已有未确认闲聊候选立即清除，从而使开关立即生效。
8. 作为求职者，我希望关闭开关后仍能主动请求记住某条事实，从而保留单次选择权。
9. 作为求职者，我希望纠正一条错误记忆时写入我确认的新事实并使旧事实失效，从而让系统使用当前信息且保留历史证据。
10. 作为求职者，我希望删除与纠正呈现为不同操作，从而明确何时保留历史、何时执行跨层清除。
11. 作为求职者，我希望当前明确求职偏好优先于旧记忆和模型推断，从而让岗位发现遵守我现在的目标。
12. 作为求职者，我希望引用材料、简历字段、问卷推断和假设不被当作我当前确认的偏好，从而避免错误筛选。
13. 作为求职者，我希望一次忽略岗位只形成低权重短期排序信号，从而不会把该公司自动加入黑名单。
14. 作为求职者，我希望城市、薪资等易变偏好每 90 天提醒复核，逾期暂停用于自动筛选，从而避免旧条件长期限制机会。
15. 作为求职者，我希望密码、密钥和证件号码永不进入长期记忆，从而降低敏感信息暴露。
16. 作为求职者，我希望薪资底线、工作许可和健康限制只在我主动告知并确认用于求职后进入私人分区，从而控制其用途。
17. 作为求职者，我希望其他用户和管理员默认看不到我的私人记忆，从而保持个人资料私密。
18. 作为求职者，我希望个案排障时能限定授权范围和有效期，并看到审计记录，从而可控地获得支持。
19. 作为管理员，我希望只审核团队共享候选并查看脱敏治理指标，从而完成质量治理而不接触私人原文。
20. 作为 Agent，我希望只读取已准入且对当前任务有权限的记忆，从而不会用候选、过期偏好或其他用户的数据做决策。

## Implementation Decisions

- 用户记忆管理入口以所属用户为边界展示私人事实、来源证据、状态、待确认候选及其到期时间，并提供确认、记忆纠正、记忆删除请求和自动发现开关。聊天中的明确删除请求打开同一范围确认流程，不直接执行清除。
- 已读回验证的任务结果和用户明确表达的当前求职偏好按各自证据门禁成为活跃事实；闲聊个人事实与可溯源推断仅为个人记忆候选，确认前不得进入 Agent Run Context、推荐或自动筛选。
- 自动发现默认开启，首次使用说明其作用。关闭后立即清除未确认的闲聊候选，既有活跃事实保留；主动“请记住”可单次发起内容确认，任务业务记录继续保留。
- 闲聊候选创建满 30 天仍未确认则清除，不自动转活跃。该期限不作用于团队共享审核队列，也不替代原始 Conversation 自身的保留规则。
- 记忆纠正将旧事实置为失效，并以用户确认的新内容、来源及时间创建活跃事实；不修改简历原文。记忆清除遵循 Spec 11，不能通过普通事实更新代替。
- 用户当前明确求职偏好覆盖冲突的旧记忆与推断；引用、假设、过去偏好、简历或 JD 文本、面试回答及问卷完成均不能伪装为当前用户确认。模糊表达先澄清。
- 密码、密钥与证件号码永不准入长期记忆。薪资底线、工作许可、健康限制等敏感求职事实要求用户主动提供并确认用于求职，只写入私人记忆分区；不能从闲聊或材料中推断确认。
- 单次忽略或点击只能形成低权重短期排序信号；重复且一致的行为可提出待确认偏好，但不能自行创建公司黑名单或覆盖明确偏好。城市、薪资等易变活跃偏好每 90 天请求复核；逾期未确认即暂停自动筛选，稳定经历事实无统一过期日。
- 私人事实和会话观察仅由所属用户查看与纠正。管理员默认只处理团队共享候选及脱敏指标；个案支持访问须用户授予明确范围和有效期，所有访问留下审计。
- 记忆分区约束所有 Agent 读写；会话观察须先经过候选和准入决策，不能直接提升为活跃长期事实。团队共享材料的审核流程与个人记忆候选相互独立。

## Testing Decisions

- 以“用户入口或 Agent 会话 → 记忆管理页 → Agent/推荐读回”为主要 seam，验证候选形成、当场确认、纠正、开关、30 天到期及刷新后状态一致；不以页面控件隐藏或内部函数调用作为权限判据。
- 对用户明确偏好、叙述、引语、假设、简历原文、问卷推断及敏感事实使用同组对照输入，断言仅获准事实变为活跃且影响后续任务。
- 用两位用户、管理员和限时授权支持身份检查列表、操作和 Agent 检索：私人原文不跨用户或默认进入后台，授权到期后无法继续访问，审计仅记录允许的范围。
- 从一次忽略、重复一致反馈和明确排除公司三个用户行为出发，验证短期信号、待确认偏好及硬约束的区别；模拟 90 天到期，断言自动筛选暂停但历史记录仍可查看。
- 复用已有路由认证、双用户隔离、候选记忆策略和反馈提升场景的测试模式；断言真实可见行为及持久读回，不锁定内部提示词或状态计算细节。

## Out of Scope

- 不改变原始业务记录的保留或删除规则，也不把记忆纠正变成简历修改。
- 不让管理员普遍浏览或编辑私人记忆。
- 不将一次岗位反馈自动转成公司黑名单、明确求职偏好或永久记忆。
- 不在本 spec 中实现团队共享材料的全部质量审核规则。

## Further Notes

- 本 spec 的个人记忆候选和团队审核候选使用不同准入、期限和权限语义；界面与审计必须保持区分。
- 会话观察记忆、旧客户端偏好及旧后台治理入口均需经过上述权限与准入检查，不能成为旁路。
