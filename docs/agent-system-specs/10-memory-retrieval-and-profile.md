# Spec 10: Memory Retrieval And Job-Seeking Profile

**Target label:** `ready-for-agent`
**Depends on:** Specs 08–09, ADR-0028, ADR-0032, and ADR-0034

## Problem Statement

求职者即使已经纠正偏好，也可能看到旧信息影响岗位筛选；相关经历还可能因单一路径召回不足而被遗漏。当前已有向量与全文融合、HNSW 索引和结构化画像的基础实现，但尚不能证明实体关联、五因子重排、分区权限、候选隔离及偏好时效在所有读取入口一致生效。

## Solution

建立统一的记忆检索与求职画像读取 seam。长期事实使用向量、BM25 词项匹配与实体关联混合召回，并以既有五因子规则重排；结构化求职画像按字段精确读取。所有路径先验证用户归属、记忆分区、事实有效期和确认状态，再将有来源的结果提供给 Run Context、岗位发现及其他获授权的 Task Program。

## User Stories

1. 作为求职者，我希望系统能找到与当前问题相关的经历，即使用词和旧记录不同，从而获得更贴合的建议。
2. 作为求职者，我希望最新明确偏好优先于旧记忆和推断，从而岗位筛选符合现在的目标。
3. 作为求职者，我希望未确认的个人记忆候选不影响推荐，从而可以先审阅再使用。
4. 作为求职者，我希望过时或已纠正的事实不再参与当前回答，从而不必反复纠正系统。
5. 作为求职者，我希望城市和薪资等易变偏好每 90 天收到复核提示，从而确认自动筛选仍符合现状。
6. 作为求职者，我希望到期未复核的易变偏好暂停自动过滤，而履历等稳定事实不被统一过期，从而减少漏掉机会的风险。
7. 作为求职者，我希望一次忽略岗位只轻微影响短期排序，从而不会无意中排除整家公司。
8. 作为求职者，我希望简历中写的城市仍作为简历内容保留，而不会自动改写我的当前意向城市。
9. 作为运营人员，我希望检索结果带有来源、状态和得分依据，从而能分析不相关或错误推荐。
10. 作为安全负责人，我希望所有召回分支均执行同样的用户与分区授权，从而不会从向量或缓存旁路泄露私人事实。
11. 作为评测人员，我希望有固定的相关性基线和困难查询样本，从而能判断改动是否改善召回而未破坏偏好优先级。
12. 作为实现 Agent，我希望只通过统一读取接口构造 Run Context，从而不在每个 Task Program 重做记忆筛选。

## Implementation Decisions

- 长期事实召回融合 HNSW 向量检索、BM25 词项匹配与 entity 关联，再使用既有五因子重排。当前向量与全文融合属于基础实现，不等于 BM25、entity 关联和完整重排已交付。
- 统一读取入口对每条候选结果先验证用户归属、记忆分区读权限、活跃有效期、确认状态及清除抑制，再参与召回、融合、重排或缓存；任何一个召回分支都不得先取越权结果再依赖最终展示过滤。
- 检索结果提供事实标识、来源、有效时间、分区和相关性证据，供授权的 Run Context 构建与诊断使用；私人原始内容不得流入未授权 Agent 或用户安全视图。
- 结构化求职画像以 topic 与 sub-topic 字段保存和按 SQL 精确读取，不通过向量相似度猜测城市、薪资底线或公司排除项。画像字段必须绑定对应事实来源、确认状态和有效期。
- 用户当前明确求职偏好高于旧事实、推断、行为反馈和文档内容。新偏好使冲突的旧事实失效；简历或报告原文不因此自动修改。岗位发现发起扫描前仍执行既有用户确认。
- 城市、薪资等易变活跃偏好每 90 天提示复核；到期未重确认时停止用于自动筛选。稳定经历事实不设统一过期时间，但证据冲突仍按事实账本处理。
- 一次忽略或点击仅生成低权重、短期排序信号；重复一致的信号交给 Spec 09 形成个人记忆候选，不能直接变成明确偏好、公司黑名单或硬过滤。
- 检索缓存与画像投影必须随事实失效、候选状态、分区授权、复核状态和记忆清除改变而失效；清除流程仍由独立 spec 拥有。

## Testing Decisions

- 在统一记忆读取 seam 使用固定查询、事实、来源和权限 fixture 验证召回、排序、结构化字段及可解释输出；以外部结果与授权边界为断言，不固定内部向量距离。
- 用现有记忆评测 harness 记录 hit@k 和任务相关性基线，再比较混合召回与五因子重排；覆盖同义改写、关键词精确命中、实体关联、矛盾事实和空结果。
- 验证候选、失效事实、被抑制内容、跨用户事实及不可读记忆分区在向量、词项、实体和缓存各路径均不可进入 Run Context。
- 覆盖明确新偏好与旧偏好、推断、履历内容及行为信号冲突；断言当前用户意愿优先，单次忽略不形成公司黑名单。
- 使用时间推进验证 90 天复核提示、到期后的自动过滤暂停、用户再次确认后恢复，以及稳定经历事实不被统一过期。
- 在岗位发现短链路验证画像预填、用户确认、扫描条件和结果；在刷新与 worker 恢复后验证读取语义一致。
- 复用现有事实账本、记忆 eval harness 与 Agent 记忆上下文测试形态，补充真实 Postgres 索引及权限边界验证。

## Out of Scope

- 不在本 spec 中决定个人记忆候选的提取、确认或 30 天期限；这些由 Spec 09 负责。
- 不在本 spec 中实现用户记忆管理界面、管理员访问授权或定向记忆清除。
- 不根据岗位反馈直接改写简历、报告或其他原始 Artifact。
- 不把结构化求职画像作为会话层观察或原始聊天记录的替代物。

## Further Notes

- 本 spec 使用 Spec 08 的事实、分区和来源，以及 Spec 09 的准入状态；二者未完成前，检索结果不得成为新的生产权威。
- 检索质量指标不能覆盖用户归属、权限、确认状态或清除抑制等确定性失败。
- 生产切换与全局 Eval Run 仍由现有发布规范治理；本 spec 只提供记忆检索与画像的专项验收证据。
