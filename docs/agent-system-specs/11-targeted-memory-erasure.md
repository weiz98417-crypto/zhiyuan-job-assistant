# Spec 11: Targeted Memory Erasure

**Target label:** `ready-for-agent`
**Depends on:** Specs 08–10、ADR-0028、ADR-0033；恢复门禁按 Spec 13 验收

## Problem Statement

用户要求删除一条记忆时，现有事实失效或旧后台删除都无法清除会话观察、历史事实、向量片段和摘要中的派生副本。用户也可能只是叙述“我忘记了曾在某公司工作”；若系统把这类话误认成删除指令，会丢失仍有用的信息。一次表面成功的删除还可能被保留的原始材料或备份恢复重新写回记忆。

## Solution

提供由用户明确发起、先展示内容与范围、再经用户确认的定向记忆清除流程。确认后立即阻止目标记忆参与读取和新写入，清除各记忆层的关联内容并逐层读回；未完成的操作明确保持待处理或失败状态。原始聊天、简历、报告等业务记录依其自身规则保留，清除流程使用不含被删文本的抑制记录阻止自动再提取，并在备份恢复后重放已完成的清除。

## User Stories

1. 作为求职者，我希望闲聊中的“我忘记了……”被当成叙述，从而不会意外删除我的记忆。
2. 作为求职者，我希望引用、假设和上传材料中的删除措辞不触发清除，从而能安心讨论这些内容。
3. 作为求职者，我希望明确提出记忆删除请求后先看到匹配的具体记忆，从而知道系统准备处理什么。
4. 作为求职者，我希望目标含糊时先澄清，从而不会删除同名公司或相近经历的其他事实。
5. 作为求职者，我希望确认卡列出记忆层派生内容和会保留的原始记录，从而理解操作的实际范围。
6. 作为求职者，我希望在确认之前没有任何记忆被改动，从而可以安全取消请求。
7. 作为求职者，我希望确认后目标立即停止影响 Agent 回答和岗位推荐，从而不必等待后台清理完成。
8. 作为求职者，我希望历史事实、证据、向量片段、会话观察、反思、摘要及缓存中的对应内容被清除，从而不会在其他入口再次出现。
9. 作为求职者，我希望共享观察或摘要只移除目标内容，从而保留不相关的求职事实。
10. 作为求职者，我希望清除失败或尚未读回时看到真实状态，从而不会误以为所有记忆已清除。
11. 作为求职者，我希望以后重新请求记住同一事实时能明确解除抑制，从而保留主动恢复的选择。
12. 作为求职者，我希望原始简历和报告不会因清除记忆而被悄悄修改，从而继续使用我的业务记录。
13. 作为求职者，我希望从备份恢复服务后已清除的记忆不会复活，从而可以信任先前的清除结果。
14. 作为管理员，我希望旧删除入口在完整清除不可用期间明确拒绝清除请求，从而不会把归档或单表删除冒充清除。
15. 作为审计人员，我希望只看到请求人、范围标识、状态与时间，从而能核查操作且不再次保存被删文本。

## Implementation Decisions

- 只有用户当前明确提出的记忆删除请求，或用户在记忆管理入口发起的删除，才能创建清除意图；普通叙述、引语、假设、历史材料和模型推断均不能授权清除。
- 清除前必须解析唯一目标并展示匹配内容、关联范围和原始记录保留边界；目标不唯一时保持澄清状态，只有用户对该范围的确认才能开始执行。
- 确认首先建立持久的读取与写入抑制，再清理长期事实账本、旧记忆条目与证据、向量和搜索片段、结构化画像、会话观察与反思、摘要以及仍在使用的客户端缓存。对共享内容只删除目标片段或从允许的来源重建。
- 清除流程必须能断点继续并处理重复确认；每一层记录完成状态，通过读回确认目标在可检索内容中已消失后才报告完成。任一层失败时保持抑制并显示待处理或失败，不返回清除成功。
- 原始 Conversation、简历、报告及其他业务记录不在定向记忆清除范围内。其后续任务读取不得静默把已清除内容重新提取成记忆；仅保留不含被删文本的来源及目标抑制标识。用户后来明确要求重新记住时，经过内容确认才能解除相应抑制。
- 事实账本中的 `DELETE` 决策仅使旧事实失效；记忆纠正仅使旧事实失效并加入有来源的新事实。这两种操作均不得调用或标记为记忆清除。
- 审计记录仅含必要的身份、范围标识、状态、时间和失败阶段，不保存被清除内容。既有后台删除入口继续明确拒绝完整清除请求；归档与拒绝保留为独立治理动作。
- 生产备份不能被用户界面描述为立即物理清除；恢复时已完成清除记录必须先重放，记忆读取和提取须在重放读回成功后开放。具体恢复门禁由 Spec 13 管理。

## Testing Decisions

- 以“用户请求或管理页操作 → 范围确认 → 清除结果 → Agent 检索读回”为主要外部行为 seam；测试叙述、引语、假设、含糊目标、取消、重复确认和并发请求，断言确认前无副作用。
- 在覆盖旧记忆、事实账本、向量、画像、会话与缓存的受控数据集上清除一项混合来源事实，验证目标不再可见、不再被推荐引用，而同一共享摘要中的无关事实及原始业务记录仍可读取。
- 注入单层清理或读回失败，验证界面不宣布完成、抑制继续生效，恢复后可重试并最终读回完成；审计输出不能包含被删文本。
- 以恢复后的真实数据库和会话读取验证清除重放门禁；先前清除的目标不能被备份或保留原文重新生成。真实数据库和发布环境验收细节见 Spec 13。
- 既有旧删除入口的权限、明确拒绝及归档回归测试可作为过渡行为先例；测试断言应以可观察结果为准，不依赖内部清理函数的调用顺序。

## Out of Scope

- 不在本 spec 中定义原始聊天、简历、报告或账户的删除流程。
- 不把事实矛盾消解、记忆纠正、管理员归档等同于清除。
- 不在本 spec 中承诺现存备份立即物理删除；保留期限与生产核验归 Spec 13。

## Further Notes

- 当前旧后台删除入口已有拒绝完整清除的过渡保护；本 spec 的完成标准是跨层清除与读回，而非仅有该保护。
- 会话层采用用户为 resource、Conversation 为 thread 的映射；目标清除必须覆盖对应观察和反思，不能只处理长期事实。
