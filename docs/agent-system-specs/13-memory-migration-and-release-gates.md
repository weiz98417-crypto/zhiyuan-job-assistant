# Spec 13: Memory Migration And Release Gates

**Target label:** `ready-for-agent`
**Depends on:** Specs 05–07、08–12、ADR-0028、ADR-0033、ADR-0034

## Problem Statement

旧记忆同时存在于多个存储中，部分内容缺少可核查的来源或用户确认。直接搬入新记忆事实账本会把推断和敏感内容伪装成可信事实；只通过模拟数据库或单层测试，也不能证明跨层清除、恢复防复活及生产备份期限真实可行。缺少统一发布门禁时，用户可能在新旧记忆语义之间遇到不同结果。

## Solution

按证据级别保守迁移旧记忆，在真实 PostgreSQL 与 pgvector 上演练写入、检索、权限、清除和恢复，并将生产备份现状的只读核验、30 天最长保留目标及恢复重放列为发布前置条件。迁移和新运行时通过版本化门禁后才能成为权威记忆来源；发布负责人根据证据决定切换，失败时保持受支持的旧运行组合和已实施的删除保护。

## User Stories

1. 作为求职者，我希望自己明确确认的旧事实和已验证任务结果在升级后仍可使用，从而不必重复提供信息。
2. 作为求职者，我希望旧推断先进入待确认候选，从而不会因为迁移就被当成我的意愿。
3. 作为求职者，我希望来源不明及敏感旧内容不自动成为活跃记忆，从而避免难以察觉的隐私和推荐错误。
4. 作为求职者，我希望迁移后旧系统已清除的事实不会再出现，从而使删除请求继续有效。
5. 作为求职者，我希望恢复备份后先前的记忆清除仍然有效，从而不会看到已经删除的内容复活。
6. 作为求职者，我希望生产切换后 Agent 和记忆管理页看到同一状态，从而能信任确认、纠正与删除结果。
7. 作为运维人员，我希望迁移前有可验证备份、可重跑迁移和恢复演练，从而能够安全处理失败。
8. 作为运维人员，我希望知道线上备份的真实位置、保留期限和恢复行为，从而能证明 30 天目标是否满足。
9. 作为评测人员，我希望在真实 PostgreSQL、pgvector 和会话存储上验证用户隔离与跨层清除，从而发现模拟环境遗漏的问题。
10. 作为评测人员，我希望记录迁移前后的记忆检索与矛盾消解基线，从而能判断升级是否改善智能性而未降低安全性。
11. 作为发布负责人，我希望每项硬门禁都有可复查证据，从而在不满足条件时阻止启用新记忆运行时。
12. 作为管理员，我希望迁移后只能治理团队共享候选和脱敏指标，从而不会因历史数据搬迁获得私人记忆访问权。
13. 作为实现 Agent，我希望旧存储的停用条件明确，从而不会在新账本旁继续维护会重复写入的旧记忆路径。

## Implementation Decisions

- 迁移前先获取并验证备份；迁移为可重跑的增量操作，按所属用户、来源证据和目标状态建立稳定映射，重复执行不得生成第二份活跃事实或覆盖已清除状态。
- 用户明确确认且证据可信的事实、经读回验证的任务事实可迁为活跃；可溯源推断迁为 30 天待确认候选；来源不明或敏感旧内容不自动迁入活跃记忆。模型置信度、历史点击或旧状态字段均不能冒充用户确认。
- 旧记忆、会话观察、画像与新记忆事实账本的来源关系须可追踪；保留的业务记录与记忆数据分开迁移。迁移时遵守 Spec 11 的清除抑制，禁止把已清除内容再次提取或激活。
- 新 schema、向量扩展、HNSW 索引、用户归属、分区权限及必要约束必须在真实 PostgreSQL 环境核验；会话层先验证用户 resource、Conversation thread 与 Agent Run 的对应关系，不匹配则在 M5 决策点采用已保留的替代路线。
- 迁移与读路径切换需可观察、可回退且不能出现双重写入权威；在新记忆读取成为事实源前，比较旧新结果的证据、状态和用户可见差异，并明确退出旧存储的条件。
- 生产备份目标最长保留 30 天；发布前只读核验实际备份副本、保留策略与恢复步骤。若现状不能满足目标或无法证明恢复清除重放，阻止记忆运行时发布，不对用户声称备份已即时物理清除。
- 清除操作保留不含原文的持久重放记录。任意备份恢复后先重放已完成清除并逐层读回，成功之前禁止开放记忆读取、提取或候选晋升。
- 发布门禁至少包括迁移证据分级、用户与管理员权限、候选准入、敏感信息阻断、纠正、跨层清除、恢复防复活、矛盾消解、检索质量和回退演练；确定性失败不能由质量评分覆盖。

## Testing Decisions

- 用包含两位用户、明确确认事实、已验证任务事实、可溯源推断、未知来源与敏感内容的受控旧库，执行迁移、重复迁移与读回；逐项核对归属、来源和目标状态。
- 在真实 PostgreSQL/pgvector 上通过用户 API 与 Agent 检索入口测试，覆盖事实账本、旧记忆、向量、会话观察及画像的同一目标；跨层清除后逐层读回，并验证其他用户和无关事实保持可用。
- 制作带已清除内容的备份，演练恢复、清除重放、读回和重新开放读取的顺序；故意让重放失败，验证服务保持关闭记忆读取与提取的状态。
- 先用现有记忆评测集记录检索 hit@k、相关性与矛盾消解基线，再对新路径使用同组样本评估；同时测候选误入、敏感信息误写和跨用户泄漏，后者为硬失败。
- 在生产等价环境核验扩展、索引、schema 迁移、会话映射、备份恢复和发布开关；发布证据包含执行时间、版本、环境、结果、失败与回退记录。现有迁移 fixture、用户隔离、路由行为和记忆评测模式可复用，但静态源码断言不能代替真实数据读回。
- 对生产备份的只读核验记录实际位置、保留天数、清理执行和恢复顺序；若目标 30 天或清除重放不能证明，发布门禁失败。

## Out of Scope

- 不在本 spec 中实施未经确认的历史数据回填为活跃记忆。
- 不以模拟 PostgreSQL 查询或单张表删除证明跨层清除完成。
- 不在本 spec 中直接操作生产备份、部署或切换流量；这些动作需依发布流程与门禁单独执行。
- 不把 0.10.8 的既定发布范围扩大为未通过门禁的新记忆运行时。

## Further Notes

- Spec 11 定义用户可见清除语义，Spec 12 定义准入与权限；本 spec 定义迁移、真实环境验证及发布条件，三者缺一不可。
- 具体测试入口和生产切换批次仍待最终确认；上述硬门禁不因入口选择而放宽。
