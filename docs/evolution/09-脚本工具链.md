## 2. 核心脚本详解

### 2.1 db-write.mjs

**用途**：Agent 写入 SQLite 的桥接层。封装 `better-sqlite3`，提供三个 action。

```bash
# 写入/更新应用记录
node scripts/db-write.mjs --action upsertApp --data '{"num":42,...}'

# 写入/更新报告元数据
node scripts/db-write.mjs --action upsertReport --data '{"report_num":42,...}'

# 写入 JD
node scripts/db-write.mjs --action insertJD --data '{...}'
```

**安全特性**：
- 输入净化：控制字符过滤（`[\x00-\x08\x0b\x0c\x0e-\x1f]`）
- score 格式校验：必须 1.0-5.0
- date 格式校验：必须 YYYY-MM-DD
- SQLITE_BUSY 指数退避重试（100ms→400ms→2s, 3 次）
- 错误日志自动写入 `data/db-write-errors.log`

**Fallback**：如果脚本不可用，回退到 TSV 写入 `batch/tracker-additions/`

### 2.2 scan-risks.mjs

**用途**：风险检测引擎 Layer 1 — 确定性正则匹配。

```bash
# 文本输入
node scripts/scan-risks.mjs --jd-text "JD正文..."

# 文件输入
node scripts/scan-risks.mjs --jd-file ./jds/001-bytedance.md
```

**流程**：
1. 读取 `risk-intel-triggers.yml`（35 条正则）
2. 对 JD 文本逐个执行 `new RegExp(pattern, 'gi')`
3. 去重：同 signal+severity 保留最长 excerpt
4. 输出 JSON `[{signal, excerpt, severity}, ...]`
5. 无匹配 → `[]`
6. triggers.yml 缺失 → `[]`（不崩溃）
7. JD < 50 字符 → `[]`（空输入 guard）

### 2.3 validate-output.mjs

**用途**：LLM 输出在持久化前的最后一道校验。

```bash
node scripts/validate-output.mjs --data '{
  "overall_score": 4.2,
  "date": "2026-05-09",
  "status": "Applied",
  "report_path": "reports/042-bytedance-2026-05-09.md"
}'
# Exit 0 = 通过, Exit 1 = 失败
```

**校验规则**：

| 字段 | 规则 | 失败动作 |
|------|------|---------|
| `overall_score` | 1.0 ≤ score ≤ 5.0, 数字类型 | 报告拒绝, 重新生成 |
| `date` | YYYY-MM-DD, 合法日期 | 报告拒绝, 重新生成 |
| `status` | 在 states.yml 中, 或已知别名 | 自动修正为规范值 |
| `report_path` | `reports/NNN-slug-YYYY-MM-DD.md` | 报告拒绝 |

**降级策略**：
- `states.yml` 缺失 → 跳过状态校验（不崩溃），使用硬编码 fallback
- 别名自动映射（如 "已投递" → "Applied"）

### 2.4 check-onboarding.mjs

**用途**：入职数据完整性检查。CV/profile 为空时硬阻断评估。

```bash
node scripts/check-onboarding.mjs
# Exit 0 = 通过, Exit 1 = 阻断
```

**检查项**：
1. `cv.md` 存在且 >50 有效字符，不含占位符标记
2. `config/profile.yml` 存在且姓名不是模板示例
3. `modes/_profile.md` 存在

**多语言占位符检测**：
- 中文：请在此处填写、在此输入、填写你的
- 英文：TODO: fill、Your experience here、Paste your CV
- 日文：ここに入力
- 韩文：여기에 입력

**示例姓名检测**：
- 张三、李四、王五、Your Name、姓名、Max Mustermann、山田太郎

### 2.5 next-report-num.mjs

**用途**：原子报告编号分配，防止并行 Agent 覆盖文件。

```bash
node scripts/next-report-num.mjs
# 输出: 42
```

**实现**：`mkdirSync` 文件系统原子锁
1. 扫描 `reports/` 找到最大编号 N
2. 尝试 `mkdirSync(reports/.locks/NNN)`
3. 成功 → 返回 NNN（原子获取）
4. 失败（EEXIST）→ NNN++ 重试
5. 大于 1 小时的锁目录自动清理

### 2.7 scan.mjs

**用途**：零 token 门户扫描器。直接调用 ATS API，不使用 LLM。

```bash
node scan.mjs                  # 扫描所有 api 标记的公司
node scan.mjs --dry-run        # 预览模式
node scan.mjs --company Cohere # 单公司扫描
```

**支持的 ATS**：
- ✅ Greenhouse (boards.greenhouse.io)
- ✅ Ashby (jobs.ashbyhq.com)
- ✅ Lever (jobs.lever.co)

**不支持（需 Playwright）**：
- ❌ Boss直聘、拉勾、猎聘、51job、智联招聘
- ❌ LinkedIn、Indeed

`portals.yml` 的 `scan_method` 字段控制：`api` → 扫描；`playwright` → 跳过
