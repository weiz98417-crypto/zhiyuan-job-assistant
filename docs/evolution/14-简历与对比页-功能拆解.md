# 14 — 简历管理 & Offer 对比页功能拆解

## CV 管理页 (`/cv`)

| # | 功能 | 实现 | 数据源 |
|---|------|------|--------|
| 1 | 简历查看 | Markdown 渲染 `cv.md` | 文件系统 (Read tool) |
| 2 | 简历编辑 | 富文本/Markdown 编辑器 | 前端状态 → Write 回写 |
| 3 | PDF 生成 | `/api/cv/generate-pdf` (server-side Playwright) | `templates/cv-template.html` |
| 4 | 简历模板 | `cv-template.html` (Space Grotesk + DM Sans 字体) | ATS 兼容格式 |
| 5 | 简历版本管理 | `ReferenceResume` (对比参考) | SQLite reference_resumes 表 (via API) |
| 6 | 简历搜索 | FTS5 全文搜索 | SQLite FTS |
| 7 | 锁定字段 | `useLockedFields` hook (简历部分字段锁定) | SQLite locked_fields 表 (via API) |

### PDF 生成流程

```
cv.md → Agent 读 mode → 填充 {{PLACEHOLDERS}}
  → /tmp/cv-{name}-{company}.html
  → POST /api/cv/generate-pdf (server-side, no client Playwright dependency)
  → output/cv-{name}-{company}-{date}.pdf
```

`cv-template.html` 使用 ATS 兼容格式：
- Space Grotesk (标题) + DM Sans (正文)
- A4 纸张，0.5in 边距
- 无图片、无表格、无复杂 CSS（ATS 解析器兼容）

### 锁定字段

`useLockedFields` hook 允许用户在编辑时锁定某些字段（如姓名、邮箱），防止误修改。状态存储在 SQLite 的 `locked_fields` 表中，通过 API 读写。

## Agent 驱动的简历优化流 (核心新增)

### optimize_resume_section → save_resume_section 闭环

用户通过 Agent 对话触发简历优化，不再依赖独立的前端 OptimizePanel：

```
用户: "帮我把字节 AI PM 的简历经历 section 改成 STAR 格式"
  → Agent tool: optimize_resume_section(company, role, section, targetJD)
    → 读取当前 cv.md + JD 关键词
    → DeepSeek/Claude 生成优化版本（定向版 + 通用版双方案）
    → 返回优化文本到聊天界面
  → 用户确认后 → Agent tool: save_resume_section(section, content, target)
    → 写入 SQLite cv_sections 表
    → 更新锁定状态
  → Agent: "经历 section 已保存定向版。需要我继续优化技能 section 吗？"
```

### Judge Engine: 4 维度优先级模型

Agent 评估 JD 时使用 judge-engine.ts 的四维优先级模型：

| 维度 | 权重 | 说明 |
|------|------|------|
| 匹配度 (Match) | 40% | 技能、经验与 JD 要求的匹配程度 |
| 成长性 (Growth) | 25% | 岗位对公司/个人职业发展的价值 |
| 风险 (Risk) | 20% | 996、外包、试用期过长等 red flags |
| 薪酬 (Comp) | 15% | 薪资范围、福利、五险一金 |

每维度 1-5 分，加权计算综合分数。评估结果存入 SQLite reports 表。

### ATS 兼容性检查

`/api/cv/ats-check` (Agent tool: `ats_check`):
- 上传简历文本/HTML → 模拟 ATS 解析
- 检测：关键字缺失、格式混淆、表格/图片问题
- 输出：可解析性评分 + 逐项修复建议
- 支持中文 ATS 平台（Boss直聘、拉勾、智联）

## CV 数据 API 层级

| Endpoint | Method | 功能 |
|----------|--------|------|
| `/api/cv/data` | GET | 获取完整简历数据（所有 section） |
| `/api/cv/data` | PUT | 更新简历 section（支持锁定检查） |
| `/api/cv/dna` | GET | 获取简历 DNA 指纹（技能向量 + 经验图谱） |
| `/api/cv/optimize-section` | POST | Agent tool 后端：优化单个 section |
| `/api/cv/ats-check` | POST | ATS 兼容性扫描 |
| `/api/cv/generate-pdf` | POST | 服务端 PDF 生成 |
| `/api/cv/import` | POST | 从文件/URL 导入简历 |
| `/api/cv/import-reference` | POST | 导入参考简历用于风格对齐 |

所有端点读写 SQLite 数据库，前端不直接操作 IndexedDB。

## Offer 对比页 (`/compare`)

| # | 功能 | 实现 | 数据源 |
|---|------|------|--------|
| 1 | Offer 选择 | 多选已获 Offer 的应用 | SQLite applications 表 (via API) |
| 2 | 雷达图 | `RadarChart` 组件 (6 维可视化) | 前端计算 |
| 3 | 逐项对比表 | 薪资/福利/通勤/成长/稳定性/WLB | SQLite (via API) |
| 4 | 综合推荐 | 加权评分 → 排名 | 前端计算 + Agent 分析 |
| 5 | 薪资计算器 | 税前→税后转换 (含五险一金) | 前端公式 |

### 雷达图 6 维度

| 维度 | 数据来源 |
|------|---------|
| 薪资 | offer 中的薪资字段 |
| 福利 | 五险一金/公积金/年终 |
| 通勤 | 工作地点 + 用户位置 |
| 成长 | 岗位级别 + 公司规模 |
| 稳定性 | 公司融资阶段/上市状态 |
| WLB | 加班信号 + 工作模式 |

`RadarChart` 使用 SVG 绘制，支持 2-5 个 offer 同时对比。

### Agent 驱动的深度对比: compare_offers_deep

新增 Agent tool `compare_offers_deep`，超越前端雷达图的静态对比：

```
用户: "对比我拿到的字节和美团的 offer"
  → Agent tool: compare_offers_deep(offerIds[])
    → 读取 SQLite applications 表中的 offer 详情
    → 6 维打分 + 加权推荐
    → 谈判策略生成（如："字节薪资高但公积金低，可拿美团 offer 谈"）
    → 实际收入计算（税前→税后→公积金→可支配）
  → Agent 输出结构化对比报告到聊天界面
```

### 薪资计算器

```
税前月薪 × N 个月 = 税前年薪
- 五险一金个人部分 (约 10.5% + 公积金 5-12%)
- 个税 (累进税率)
= 税后年薪
+ 公积金账户 (公司+个人缴存，可取)
= 实际收入
```
