## 2. 技术选型

### 2.1 Agent 层

| 组件 | 选型 | 理由 |
|------|------|------|
| AI 引擎 | **Claude (Anthropic API)** | 评估深度最高，中文理解顶级 |
| Agent 框架 | **无框架 —— 纯 Mode 文件驱动** | Markdown 即指令，零代码引擎，极致灵活 |
| 评分系统 | **modes/scoring-dimensions.yml** | YAML 定义 A-G 7 维度，中英文统一权重 |
| 语言路由 | **CLAUDE.md 内联路由表** | 根据 JD 语言自动选择 modes/ 或 modes/zh/ |

### 2.2 前端

| 组件 | 选型 | 理由 |
|------|------|------|
| 框架 | **Next.js 16 + React 19** | App Router, Server Components |
| 样式 | **Tailwind CSS 4 + CSS 变量** | DESIGN.md 定义的设计令牌 |
| 动画 | **Framer Motion** | 页面过渡、卡片入场动画 |
| 字体 | **LXGW WenKai (标题) + Noto Sans SC (正文)** | "手帐"设计理念 |
| Agent 对话 | **DeepSeek API (SSE 流式)** | 低成本、中文顶级 |
| 数据库 | **better-sqlite3 (WAL模式)** | 零配置、单文件、高并发读 |

### 2.3 脚本工具链

| 组件 | 选型 | 理由 |
|------|------|------|
| 运行时 | **Node.js 22 (.mjs 模块)** | 项目统一运行时 |
| PDF 生成 | **Playwright** | HTML → PDF，CSS 精确控制 |
| YAML 解析 | **js-yaml** | 配置文件和知识库解析 |
| SQLite 驱动 | **better-sqlite3** | 同步 API，WAL 模式，性能好 |

## 3. 关键技术决策

### 3.1 数据层：SQLite 单文件

**选择 SQLite 而非 PostgreSQL/MySQL。**

理由：
- 单人项目，零运维负担
- WAL 模式支持并发读写
- 单文件方便备份和迁移
- `better-sqlite3` 同步 API 简化脚本逻辑
- `ON CONFLICT` 原生支持 upsert（去重）

### 3.2 Agent 引擎：无代码引擎

**选择纯 Mode 文件（Markdown 指令）而非编程 Agent 框架。**

理由：
- Mode 文件即系统提示词——Agent 读取并执行
- 改 prompt 不需要改代码，不需要重新部署
- 多个 Mode 之间共享 `_shared.md` 的评分逻辑
- `scoring-dimensions.yml` 是评分维度的权威源

代价：
- 没有类型安全——LLM 输出需要 `validate-output.mjs` 校验
- 没有回归测试——依赖手动 snapshot 验证

### 3.3 两层风险检测

**选择正则字面匹配 + LLM 语义补充，而非纯 LLM。**

理由：
- 正则匹配是确定性的，零误判，零 LLM 调用
- LLM 覆盖正则无法捕获的语义变体
- 两层合并去重，保留最高严重度

### 3.4 Agent 互通：SQLite 桥接

**选择 API route + fetch，而非共享内存或消息队列。**

理由：
- SQLite 已是共享数据源
- `/api/agent/claude-activity` 服务端查询 SQLite
- 客户端 `fetch()` 获取，不需要新基础设施
- 总改动 ~40 行代码
