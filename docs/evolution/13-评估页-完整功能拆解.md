## 评估架构

```
用户输入 JD (URL/文本/截图)
        │
        ▼
┌───────────────────────────────────────────────┐
│             评估管道 (3-step pipeline)          │
│                                                │
│  Step 1: JD 内容获取                           │
│  ├─ URL → /api/agent/fetch-jd → Playwright    │
│  ├─ 截图 → OCR (粘贴/拖拽/文件选择)            │
│  └─ 文本 → 直接使用                            │
│                                                │
│  Step 2: 风险扫描 (并行)                       │
│  └─ /api/agent/scan-risks                     │
│      └─ 检测 black-market 信号 (外包/卖人头等)  │
│      └─ 返回风险信号数组 + 严重等级             │
│                                                │
│  Step 3: 完整评估 (7板块)                      │
│  └─ DeepSeek: 7 板块评估 + 风险整合            │
│      └─ SSE 流式输出: A → B → C → D → E → F → G│
│                                                │
│  输出: 评估报告 (A-G 板块 + 风险表 + 分数)      │
│        → 写入 repository (applications + reports + jds) │
└───────────────────────────────────────────────┘
```

### Agent 工具调用路径

两种评估入口：

| 入口 | 工具 | 流程 |
|------|------|------|
| **Agent 对话** | `evaluate_jd` | 基本 JD 评估（7 板块，不包含风险扫描） |
| **Agent 对话** | `evaluate_jd_full` | 完整评估管道：抓取 → 风险扫描 → 评估 → 存储 |
| **Agent 对话** | `analyze_jd_risks` | 独立风险扫描（不包含完整评估） |
| **评估页面** | 页面导航 → Agent 对话 | 推荐用户转到 Agent 对话中进行评估 |

## 功能拆解

### 1. 评估入口导航

评估页面 (`src/app/evaluate/page.tsx`) 本身不再承载评估功能，而是作为导航入口：

- 展示 JD 统计（总数/报告数/平均分，优先来自 `/api/data/jds` 与 `/api/data/reports`）
- 引导用户到 Agent 对话页面 `/agent` 进行实际评估
- 提供三个子页面入口：历史评估、JD 管理、报告浏览
- 服务端 API 不可用时才回退 Dexie 本地缓存；正常情况下数量以 repository API 为准

```
/evaluate
  ├─ /evaluate/history  -- 历史评估列表 (reports 表)
  ├─ /evaluate/jds      -- JD 管理 (jds 表)
  └─ /evaluate/reports  -- 报告浏览 (reports 表)
```

### 2. OCR 图片识别

**支持三种输入方式**：
- 粘贴 (Ctrl+V)：监听 `ClipboardEvent`，提取 `image/png` 或 `image/jpeg`
- 拖拽 (Drag & Drop)：`onDragOver`/`onDrop` 事件，提取 `File` 对象
- 文件选择：`<input type="file" accept="image/*">` 点击触发

**处理流程**：
```
图片 → FileReader.readAsDataURL() → Base64
  → 5MB/文件限制, 最多 10 张
  → 队列管理 (QueueItem: id/file/previewUrl/base64/status/retries)
  → 逐张 OCR 识别
  → 拼接文本 → 填入 JD 输入框
```

**状态管理**：
| 状态 | 含义 |
|------|------|
| `upload` | 等待上传 |
| `processing` | OCR 识别中 |
| `confirm` | 显示识别结果，等待确认 |

### 3. JD 内容抓取 (`/api/agent/fetch-jd`)

当用户提供 JD URL 时，后端使用 Playwright 抓取页面正文：

```
POST /api/agent/fetch-jd
Body: { "url": "https://..." }

响应:
{
  "success": true,
  "data": {
    "text": "JD 正文内容...",
    "title": "页面标题"
  }
}
```

**抓取规则**：
- 使用 Playwright browser 实例
- 提取页面正文文本（去除导航/页脚）
- 自动清理格式化空白

### 4. JD 风险扫描 (`analyze_jd_risks` + `/api/agent/scan-risks`)

**Agent 工具**: `analyze_jd_risks` (`src/lib/agent/tools/action/analyze-jd-risks.ts`)

**API 端点**: `POST /api/agent/scan-risks`

**调用方式**：
- Agent 对话中通过 `analyze_jd_risks` 工具触发
- 后端调用 `scripts/scan-risks.mjs` (child_process.spawn)
- 由 `risk-intel-triggers.yml` 定义检测规则

**输入**：
```json
{
  "jd_text": "完整的 JD 描述文本（最少 20 字符）"
}
```

**输出** (风险信号数组)：
```json
[
  {
    "signal": "外包/卖人头",
    "excerpt": "与甲方团队协同工作...",
    "severity": "critical"
  },
  {
    "signal": "薪资面议（无范围）",
    "excerpt": "薪资待遇：面议",
    "severity": "medium"
  }
]
```

**严重等级**：
| 等级 | 含义 | 权重 |
|------|------|------|
| `critical` | 严重风险（如外包/卖人头/虚假职位） | 10 |
| `high` | 高风险（如竞业限制过于严格） | 4 |
| `medium` | 中风险（如薪资面议/试用期过长） | 2 |
| `low` | 低风险（如JD描述模糊） | 1 |

**风险评分算法**：
```typescript
const totalWeight = signals.reduce((sum, s) => sum + SEVERITY_WEIGHT[s.severity], 0);
const level = isCritical ? "🔴 严重"
  : totalWeight >= 6 ? "🔴 高风险"
  : totalWeight >= 2 ? "🟡 中风险"
  : "🟢 低风险";
```

**风险 Badge CSS 样式** (用于内联报告渲染):
```css
.risk-badge.risk-critical { background: #fee2e2; color: #991b1b; }
.risk-badge.risk-high     { background: #ffedd5; color: #9a3412; }
.risk-badge.risk-medium   { background: #fef9c3; color: #854d0e; }
.risk-badge.risk-low      { background: #f0fdf4; color: #166534; }
```

### 5. 完整评估管道 (`evaluate_jd_full` + `/api/agent/evaluate-pipeline`)

**Agent 工具**: `evaluate_jd_full` (`src/lib/agent/tools/action/evaluate-jd-full.ts`)

**API 端点**: `POST /api/agent/evaluate-pipeline`

这是 JD 评估的**主路径**，将原来需要 3 次单独调用（抓取 + 风险 + 评估）合并为 1 次管道调用。

**管道流程** (SSE 事件流)：

```
POST /api/agent/evaluate-pipeline
Body: { "jd_text": "...", "jd_url": "https://..." }

SSE 事件序列:
  ├─ { type: "phase", phase: "fetching" }          -- 抓取 JD
  ├─ { type: "phase", phase: "scanning_risks" }     -- 风险扫描
  ├─ { type: "risks", risks: [...] }                -- 风险信号结果
  ├─ { type: "phase", phase: "evaluating_section", section: "A" }
  ├─ { type: "section", section: "A", data: {...} } -- 板块 A 完成
  ├─ ... (B → C → D → E → F → G 逐板块流式输出)
  ├─ { type: "score", overall: 4.2, scores: {...} } -- 最终分数
  └─ { type: "done", data: { reportData } }         -- 完整数据
```

**管道内部调用**：
1. `fetch-jd` → 抓取 JD 正文（如果有 URL 且无文本）
2. `scan-risks` → 风险扫描（并行，与后续评估独立）
3. DeepSeek 7 板块评估（将风险结果注入评估上下文）

**持久化路径**：
- `evaluate_jd_full` 作为 Agent 主工具，评估完成后通过服务端接口把结果保存到 repository；当前 LAN 写入 PostgreSQL。
- `/api/agent/persist-eval` 写入 `applications`、`reports`，并在 `jdText` 足够长时写入 `jds`。
- `/api/report/save` 用于人工确认保存场景，可根据 `actions.saveJD` 与 `actions.addToTracker` 写入 JD 库和追踪表。
- `reports.report_num` 是报告公开编号；`jds.report_id` 存储对应的 `report_num`，用于 JD 库跳转到报告库。
- JD 单独保存时走 `createJD()`，该函数先 `POST /api/data/jds`，失败时才写 Dexie。

**7 板块评估** (与 DeepSeek 交互)：

| 板块 | 内容 | 输出格式 |
|------|------|---------|
| A | 职位概览：Archetype 分类、领域、职级 | 表格 |
| B | 简历匹配：JD 要求逐条对照 + 缺口分析 | 表格 |
| C | 职级策略：中国职级对应、晋升路径 | 结构化文本 |
| D | 薪资分析：竞争力评估、市场对比（含数据来源） | 表格 |
| E | 定制化方案：简历修改建议 | 结构化文本 |
| F | 面试准备：STAR+R 故事框架 | 表格 |
| G | 职位合法性评估：风险判定 + 建议 | 表格 |

### 6. 评估结果展示 (`ReportBlocks` 组件)

完整的 7 板块渲染（A-G），加上**风险提示**：

- **风险提示表格**（置顶，仅当检测到风险信号时显示）：
  - 🛡️ 标题 + 风险等级 badge
  - 逐条风险信号 + 原文摘录 + 严重等级
  - 使用风险 Badge CSS 渲染：红色(critical) / 橙色(high) / 黄色(medium) / 绿色(low)

- **板块 A-G** 依次渲染，每个板块可折叠

### 7. 流式评估

SSE (Server-Sent Events) 实时流式传输评估结果：
- 连接: `fetch()` + ReadableStream（不使用 EventSource 以支持 POST）
- 每个板块 (A-G) 完成后推送一个 `section` 事件
- 前端实时渲染 ReportBlocks，逐板块出现
- 支持中途断开（前端 AbortController）

### 8. 历史评估列表 (`/evaluate/history`)

数据来源：优先 `/api/data/reports`，返回 `reports` 表；API 不可用时 fallback 到 Dexie。

展示字段：编号 | 日期 | 公司 | 岗位 | 分数 | 风险等级 | 操作（查看/删除）

### 9. JD 管理 (`/evaluate/jds`)

数据来源：优先 `/api/data/jds`，返回 `jds` 表；API 不可用时 fallback 到 JD 存储模块 (`src/lib/jd-storage.ts`) 的 Dexie 缓存。

功能：浏览/搜索/删除已保存的 JD 原文。`reportId` 对应 `reports.report_num`，用于标识“已有报告”的 JD。

### 10. 报告浏览 (`/evaluate/reports`)

数据来源：优先 `/api/data/reports`，返回 `reports` 表；API 不可用时 fallback 到 Dexie。

功能：按公司/日期筛选，查看完整报告（A-G 板块 + 风险扫描结果）。
