## 数据架构

首页数据加载流程：

```
用户访问 / (首页)
  ├─ applications 数据: 前端通过 Dexie wrapper 读取本地缓存（SQLite 为后台唯一数据源）
  │   └─ 后端 db-write.mjs 写入 SQLite → 前端 API 读取 → Dexie 本地缓存
  ├─ 行业快讯: GET /api/news/industry
  │   └─ 检查 SQLite news_cache 表 → 有效(≤6h)则返回 / 过期则拉取 RSS
  └─ 目标公司动态: GET /api/news/company
      └─ 检查 SQLite news_cache 表 → 有效则返回 / 过期则 WebSearch + DeepSeek
```

所有持久化数据的唯一数据源是服务端 SQLite (`data/zhiyuan.db`)。前端 Dexie 仅作为本地读取缓存，不负责数据写入。

## 功能拆解

### 1. 每日问候语 `getGreeting()`

```typescript
function getGreeting(): string {
  const hour = new Date().getHours();
  const day = new Date().getDay();
  const dayNames = ["周日", "周一", "周二", "周三", "周四", "周五", "周六"];
  if (hour < 10) return `早安，${dayNames[day]}愉快`;
  if (hour < 14) return `午安，${dayNames[day]}顺利`;
  if (hour < 19) return `下午好，${dayNames[day]}加油`;
  return `晚安，${dayNames[day]}辛苦了`;
}
```

**细节**：
- 4 个时间段：早(0-10点)、午(10-14点)、下午(14-19点)、晚(19-24点)
- 根据星期几追加不同的后缀（"愉快"、"顺利"、"加油"、"辛苦了"）
- 纯前端计算，不涉及 API 调用
- 随页面渲染时更新（不实时刷新，切换页面后再回来会更新）

### 3. Hero 指标卡 (HeroMetrics)

展示 5 个核心指标，数据来自 SQLite applications 表：

| 指标 | 计算方式 |
|------|---------|
| 总评估数 | `applications.length` |
| 已投递 | `applications.filter(a => ["applied","responded","interview","offer"].includes(a.status)).length` |
| 面试中 | `applications.filter(a => a.status === "interview").length` |
| Offer | `applications.filter(a => a.status === "offer").length` |
| 平均分 | `scoredApps.reduce(sum, a => a.score, 0) / scoredApps.length` |

每个指标显示**周环比趋势**（本周 vs 上周）：递增/递减箭头 + 百分比变化。

### 7. AI 行业快讯 (IndustryNews + `/api/news/industry`)

这是首页最复杂的后端功能。完整的数据流：

```
┌──────────────────────────────────────────────────────────────┐
│                      数据获取流程                             │
│                                                              │
│  1. 检查 SQLite 缓存 (TTL=6h)                                │
│     ├─ news_cache 表，source="industry"                     │
│     ├─ 缓存有效 → 直接返回 (零网络开销)                       │
│     └─ 缓存过期/force=1 → 进入下一步                         │
│                                                              │
│  2. 并行抓取 7 个 RSS 源                                     │
│     ├─ 机器之心 (jiqizhixin.com/rss)                         │
│     ├─ 量子位 (qbitai.com/feed)                              │
│     ├─ 36氪 (36kr.com/feed)                                  │
│     ├─ OpenAI (openai.com/blog/rss.xml)                      │
│     ├─ Anthropic (anthropic.com/blog/rss.xml)                │
│     ├─ TechCrunch AI (techcrunch.com/artificial-intelligence/)│
│     └─ Hacker News (hnrss.org/frontpage)                     │
│     ├─ 全部成功 → 步骤 4                                     │
│     └─ 全部失败 → 步骤 3 (DeepSeek fallback)                 │
│                                                              │
│  3. DeepSeek 生成新闻 (RSS fallback)                         │
│     └─ DeepSeek V4 Flash 基于知识生成 5-8 条 AI 行业新闻     │
│                                                              │
│  4. DeepSeek 摘要 (正常路径)                                  │
│     ├─ 取 top 20 条 RSS 内容                                  │
│     ├─ 调 DeepSeek API: "生成 30 字以内中文摘要"             │
│     └─ 失败 → 降级使用原始标题                               │
│                                                              │
│  5. 写入 SQLite 缓存 (news_cache 表)                         │
│                                                              │
│  6. 返回 12 条最新快讯                                       │
└──────────────────────────────────────────────────────────────┘
```

#### RSS 解析

**RSS 2.0 格式**（机器之心、36氪、TechCrunch）：
```javascript
const rssItems = xml.match(/<item>[\s\S]*?<\/item>/gi);
// 提取: <title>, <link>, <pubDate>, <description>
// 每个 feed 取 8 条
```

**Atom 格式**（Anthropic、OpenAI、量子位）：
```javascript
const atomEntries = xml.match(/<entry>[\s\S]*?<\/entry>/gi);
// 提取: <title>, <link href="">, <published>, <summary>
// 仅在 RSS 无结果时使用
```

**日期过滤**：
```javascript
const MAX_AGE_DAYS = 3;
// 支持标准日期格式 + 中文格式 "2026年5月6日"
// 无日期信息的条目保留（不丢弃）
```

#### DeepSeek 摘要

```json
// System Prompt
"你是AI行业新闻摘要助手。为每条新闻生成一句中文摘要（30字以内），
只提取最核心的信息点。忽略与AI/科技/互联网无关的内容。
只返回JSON对象：{\"summaries\":[{\"index\":1,\"summary\":\"...\"}]}"

// 参数: temperature=0.3, max_tokens=2000, response_format="json_object"
// JSON 解析失败 → 降级使用原始标题
```

#### DeepSeek Fallback（RSS 全部失败时）

```json
// System Prompt
"你是AI行业新闻编辑。请基于你的知识生成最近一周的AI/科技行业重要新闻。
聚焦中国AI求职者关心的信息：大模型发布、开源动态、融资并购、招聘趋势、政策法规
生成5-8条，不要重复，不编造具体日期数字"

// 参数: temperature=0.5, max_tokens=2000, response_format="json_object"
```

#### 缓存策略

| 参数 | 值 |
|------|-----|
| 缓存位置 | SQLite `news_cache` 表 (`source` 字段区分 "industry" / "company") |
| 有效期 | 6 小时 (`isNewsCacheFresh("industry", 6)`) |
| 清理策略 | 超过 24 小时的缓存自动清理 (`cleanExpiredNews(24)`) |
| 强制刷新 | URL 参数 `?force=1` |
| 缓存降级 | RSS+摘要都失败 → 返回过期缓存（标记 `stale: true`） |

**news_cache 表结构**：
- `source`: "industry" 或 "company"
- `data`: JSON 格式的新闻数组
- `created_at`: 缓存写入时间
- 查询/过期检查均基于 `source` + `created_at`

#### 前端展示

- **加载态**：3 个脉冲骨架动画（`animate-pulse`）
- **空数据**："快讯暂不可用"
- **正常态**：最多 6 条，每条显示来源 + 摘要 + 相对时间 + 外部链接
- **交互**：点击刷新按钮 → `fetchNews(true)` → 强制拉取新数据
- **时间格式**：`formatRelativeTime()` — 刚刚 / Nh前 / Nd前

### 8. 目标企业动态 (CompanyNews + `/api/news/company`)

与行业快讯类似，但数据源是用户配置的目标公司。

```
数据流程：
  1. 从 SQLite profiles 表读取用户目标公司列表
  2. 对每个公司执行 WebSearch（公司名 + "新闻"/"招聘"/"动态"）
  3. DeepSeek 摘要
  4. 缓存到 SQLite news_cache 表 (source="company")
```

**状态处理**：
- **未设置目标公司** → 显示引导卡片："目标企业快讯" + "去设置添加"按钮 → 跳转到 `/settings`
- **加载中** → 2 个脉冲骨架
- **无新闻** → "暂无目标企业动态"

### 9. 周/双周趋势计算

```typescript
const weekAgo = new Date(Date.now() - 7 * 86400000);
const twoWeeksAgo = new Date(Date.now() - 14 * 86400000);

const thisWeek = applications.filter(a => new Date(a.date) >= weekAgo);
const lastWeek = applications.filter(a => {
  const d = new Date(a.date);
  return d >= twoWeeksAgo && d < weekAgo;
});
```

用于 HeroMetrics 的环比计算。数据来源为 SQLite applications 表。
