# 21 — 面试模拟引擎

> 所属阶段：Phase 3 · 完整面试教练系统：出题 + 模拟 + 评分 + 总结

---

## 1. 引擎概览：状态机驱动的面试模拟

面试模拟引擎是一个完整的状态机，模拟真实面试的五阶段流程。核心实现在 `src/lib/agent/interview/engine.ts`。

```
面试会话生命周期
═══════════════════════════════════════════════════════════════

  创建会话          出题 + 回答 + 评分循环                   结算
  ┌──────┐    ┌─────────────────────────────────┐    ┌──────────┐
  │ intro │───→│ tech(3题) → behavioral(2题)     │───→│ summary  │
  └──────┘    │   ↓ 追问        ↓ 追问           │    └──────────┘
              │   ↓ 评分         ↓ 评分           │         │
              │   → reverse(3题) →               │         ▼
              └─────────────────────────────────┘      done
```

**阶段顺序定义**（硬编码状态转移）：

```typescript
const PHASE_ORDER: InterviewPhase[] = [
  "intro",                                                   // 自我介绍
  "tech", "tech", "tech",                                    // 技术面 ×3
  "behavioral", "behavioral",                                // 行为面 ×2
  "reverse",                                                 // 反问 ×3
  "summary"                                                  // 总结
];
```

阶段内题目数量配置：intro 1 题、tech 3 题、behavioral 2 题、reverse 3 题、summary 0 题（直接生成总结报告）。

### 核心数据结构

| 接口 | 字段 | 说明 |
|------|------|------|
| `InterviewSession` | id, company, role, phase, questionIndex, questions[], answers[], currentQuestion?, currentFollowups[] | 完整的会话状态快照 |
| `InterviewQuestion` | id, phase, text, type (tech/behavioral/reverse) | 单道题目 |
| `InterviewAnswer` | questionId, question, answer, score?, feedback?, followups[] | 用户回答记录 |

## 设计思想

面试模拟引擎的核心理念直接借鉴了**医学教育中的"模拟病人"（Simulated Patient）训练体系**。在医学生的培养中，一个标准做法是让受训者在面对真实病人之前，先在经过训练的演员（标准化病人）身上练习问诊、诊断和沟通。模拟病人的价值不在于完美复制真实病人，而在于创造一个**可重来、可暂停、可纠错的安全环境**。医学生可以在模拟病人身上犯错——问错问题、漏掉关键症状、沟通方式不当——然后获得即时反馈，反复练习直到熟练掌握。这个"犯错-反馈-重试"的循环是技能习得最有效的路径，但它需要一个愿意让你犯错的练习对象。

面试模拟引擎正是求职领域的"模拟病人"。真实的面试没有暂停键，没有重来机会，没有"这个回答不好，让我换个方式再说一遍"——一次失败就是一次机会的永久损失。引擎创建的模拟环境则完全不同：你可以在 intro 阶段卡壳后重新整理思路，可以在答完一道技术题后看到四维评分和具体的改进建议，可以在反问阶段练习那些你在真实面试中不好意思问的问题。练习的底气来自于"这不是真实的"——这个表面上的缺陷恰恰是模拟环境的核心价值。

状态机驱动的五阶段流程（intro → tech ×3 → behavioral ×2 → reverse ×3 → summary）不是随意的顺序安排，而是对中国 AI 行业面试流程的**模式化抽象**。大厂的面试不会有"先 behavioral 后 tech"的情况——几乎总是自我介绍开场、技术面跟进、行为面在中后段、反问收尾。状态机将这个流程硬编码为阶段序列，用户不需要考虑"下一步应该练什么"，引擎自然地推进面试节奏。追问机制（每道主问题后自动追问一次）模拟了真实面试中最常见的交互模式：面试官几乎不会听完你的 STAR 回答后直接进入下一题，总会有至少一次追问（"你能再说说具体数据吗？""团队规模多大？"）。

六种教练模式的设计承认了一个容易被忽视的现实：**不同公司的面试风格差异巨大，用同一种方式练习所有面试会产生虚假的安全感**。字节的面试官会追问你的项目复盘——他们想知道你面对困难时的思考路径，不是想听一份流畅的自我推销。国企的面试官更关注你的稳定性和长期规划，"政治觉悟"和"服从意识"在这些场合不是空洞的说辞而是真实的评分维度。外企的行为面试几乎是标准化的 STAR 问答，创业公司的创始人面试更看重多面手能力和薪资弹性。六种模式对应六套评分权重和追问策略——练过大厂模式的人在国企面试中可能被认为"太自我"，练过国企模式的人在外企面试中可能被认为"缺乏主动"。引擎的目标不是让你在所有面试中都赢，而是让你在每一种面试中都不意外。

## 2. 会话生命周期：Action 状态机

每个回合根据当前状态和用户输入决定下一步动作，由 `nextAction()` 函数裁定：

```
                    ┌──────────────────┐
                    │  session.phase   │
                    │  == "done" ?     │──── yes ──→  return "done"
                    └────────┬─────────┘
                             │ no
                             ▼
                    ┌──────────────────┐
                    │  currentQuestion │
                    │  == null ?       │──── yes ──→  return "ask"  (出题)
                    └────────┬─────────┘
                             │ no
                             ▼
                    ┌──────────────────┐
                    │  lastAnswer      │
                    │  length < 50 ?   │──── yes ──→  return "followup" (追问)
                    └────────┬─────────┘
                             │ no
                             ▼
                    ┌──────────────────┐
                    │  followups == 0  │
                    │  && phase !=     │
                    │  "reverse" ?     │──── yes ──→  return "followup" (追问)
                    └────────┬─────────┘
                             │ no
                             ▼
                        return "score"  (评分 → 进入下一题)
```

### 2.1 完整回合流程

```
用户发起: "模拟面试 字节 AI产品经理"
         │
         ▼
   POST /api/agent/coach/session { company, role }
         │
         ├─→ createSession(company, role) → nextAction → "ask"
         │
         ├─→ askQuestion(session) → DeepSeek 生成题目
         │   └─→ 返回 { sessionId, phase, question }
         │
用户回答 ──→ POST /api/agent/coach/session { sessionId, answer }
         │
         ├─→ nextAction(session, answer)
         │   │
         │   ├─ "followup" → followUpQuestion() → 追问
         │   │               用户再次回答 →
         │   │
         │   └─ "score"    → scoreAnswer() → 四维评分
         │                   advance(session) → 下一阶段/题目
         │                   │
         │                   ├─ phase != "done" → askQuestion() → 下一题
         │                   │
         │                   └─ phase == "done" → generateSummary()
         │                                          → 综合报告
         │                                          → 删除会话
```

### 2.2 追问策略

追问覆盖三个阶段：技术面和行为面的每个主问题都会自动触发一次追问（除非用户在作答后主动要求评分）。反问阶段不追问。追问也经过短回答检测——回答不足 50 字符时强制追问。

## 3. 题目生成系统

题目生成有两个入口，分别服务于不同的使用场景：

### 3.1 模拟面试出题（session 流程内）

由 `askQuestion()` 函数驱动，调用 DeepSeek API 逐题生成。每一题的 prompt 都植入了完整的面试上下文：

- **面试官角色设定**：`你是${company}的面试官，正在面试${role}岗位`
- **阶段提示**：`getPhasePrompt(session)` 返回当前环节的中文描述
- **历史追踪**：已答题目的评分汇总（`Q: ... A: ... 评分: X/10`）

```typescript
// 阶段提示示例
// intro:   "自我介绍环节——让候选人用1-2分钟介绍自己"
// tech:    "技术面第1题——考察AI产品经理的专业能力"
// behavioral: "行为面第1题——考察沟通、协作、解决问题能力"
// reverse: "反问环节——候选人可以问面试官关于公司/团队/岗位的问题"
```

生成参数：`deepseek-v4-flash`，temperature 0.8，max_tokens 200。

### 3.2 独立出题（generation API）

`POST /api/agent/coach/generate-questions` 是一次性批量出题 API，支持按面试模式生成 8-12 道题。

**输入**：

| 参数 | 类型 | 说明 |
|------|------|------|
| jdText | string | JD 正文（提供时基于 JD 出题） |
| cvText | string | 简历正文（用于个性化出题） |
| company | string | 目标公司 |
| role | string | 目标岗位 |
| mode | CoachMode | 面试模式 |
| count | number | 题目数量（默认 8） |

**输出——每道题结构**：

```typescript
{
  category: "behavioral" | "technical" | "case-study" | "culture",
  question: string,       // 题目文本
  context: string,        // 出题依据（解释为什么问这道题）
  storyHint: string,      // 准备提示（帮用户思考怎么准备）
  source: "jd" | "general",  // 题目来源
  weaknessNote?: string   // 弱项标注（有 CV 时）
}
```

**四类题目均匀分布**：

| 类别 | 中文标签 | 考察方向 |
|------|---------|---------|
| behavioral | 行为面试 | STAR 故事、团队协作、冲突处理 |
| technical | 技术/专业 | 岗位专业知识、技能实操 |
| case-study | 案例分析 | 商业判断、逻辑拆解、方案设计 |
| culture | 文化匹配 | 价值观、工作风格、公司适配 |

### 3.3 STAR+R 框架植入

出题时，系统 prompt 会注入当前面试模式的回答结构框架。六种模式的 STAR 结构来自 `COACH_MODES` 定义：

| 模式 | 结构框架 |
|------|---------|
| 项目复盘（大厂） | 背景 → 角色 → 难点 → 思考 → 方案 → 结果 → 反思 → 数据 |
| 行为问答（外企） | Situation → Task → Action → Result → Reflection |
| 情景应对（管培） | 理解 → 拆解 → 方案 → 风险 → 反问 |
| 结构化面试（中小企业） | 为什么来 → 做过什么 → 怎么做的 → 结果 → 能带来什么 |
| 创始人对话（初创） | 理解业务 → 能立刻上手 → 薪资期望 → 创业节奏 |
| 稳重应答（国企） | 学历背景 → 政治觉悟 → 服从意识 → 长期规划 → 家庭情况 |

出题时 `storyHint` 字段会提示用户从哪些角度组织答案，遵循对应的 STAR 框架。

## 4. 答案评分引擎

### 4.1 四维评分体系

评分 API `POST /api/agent/coach/score-answer` 按四个维度打分（1-5 分，精确到 0.5）：

```
┌─────────────────────────────────────────────────────────────┐
│                    四维评分模型                              │
├───────────────┬─────────────────────────────────────────────┤
│ 结构完整度     │ 回答是否有清晰的开头-主体-结尾，逻辑是否连贯   │
│   structure   │                                             │
├───────────────┼─────────────────────────────────────────────┤
│ 具体程度       │ 是否有具体的数据、案例、情境细节支撑           │
│   specificity │                                             │
├───────────────┼─────────────────────────────────────────────┤
│ 亮点突出       │ 是否展现了独特优势和竞争力                    │
│   highlight   │                                             │
├───────────────┼─────────────────────────────────────────────┤
│ 时间控制       │ 回答是否精炼、不冗长                          │
│   timing      │                                             │
└───────────────┴─────────────────────────────────────────────┘
```

综合得分 = 各维度得分 × 模式权重的加权和。

### 4.2 按模式的权重分配

不同面试场景对四个维度的要求不同，权重因模式而异：

```
模式                  结构    具体    亮点    时间
─────────────────────────────────────────────────
项目复盘 (大厂)       30%     30%     25%     15%
行为问答 (外企)       30%     30%     25%     15%
情景应对 (管培)       25%     25%     30%     20%
结构化 (中小企业)     30%     35%     20%     15%
创始人对话 (初创)     20%     25%     35%     20%
稳重应答 (国企)       40%     20%     10%     30%
```

- **大厂/外企**：均衡型，注重 STAR 结构完整性和内容具体度
- **管培**：最看重亮点突出，因为竞争激烈需要差异化
- **中小企业**：最看重具体程度，需要即战力证明
- **初创**：最看重亮点（多面手能力），结构要求最低
- **国企**：最看重结构完整度和时间控制，不太在意个人亮点

### 4.3 反馈生成

评分输出包含三个层次的反馈：

| 字段 | 说明 |
|------|------|
| `dimensions` | 四个维度的逐项得分 |
| `overall` | 加权综合得分（1-5） |
| `suggestions` | 2-3 条具体可执行的改进建议（中文） |
| `segmentFeedback` | **逐段反馈**（回答 > 300 字时启用），每段标注 rating: good/expand/compress |

### 4.4 模拟面试内的简化评分

在模拟面试的逐题评分中（`session/route.ts` 内的 `scoreAnswer()`），评分更简洁：

- 输入：题目文本 + 用户回答
- 输出：`{ score: 1-10, feedback: 中文建议 }`
- 使用 `response_format: json_object` 强制 JSON 输出
- temperature 0.3 保证评分一致性

## 5. 六种教练模式详解

面试教练系统根据目标公司类型自动推断面试风格（`inferMode()`），也支持用户手动切换。

### 5.1 模式推断规则

```
公司/描述特征                              → 模式
───────────────────────────────────────────────────────
字节/腾讯/阿里/百度/美团/小米/京东/        → 项目复盘 (project-review)
拼多多/快手/小红书/滴滴/B站/网易

国企/央企/国有/银行/编制/事业单位          → 稳重应答 (stability)

初创/天使轮/A轮/Pre-A/创业公司/微型       → 创始人对话 (founder)

外企/外资/consulting/咨询公司/MBB/四大    → 行为问答 (behavioral)

中小企业/中小型/民营                      → 结构化面试 (structured-sme)

其他/未匹配                               → 行为问答 (behavioral, 默认)
```

### 5.2 各模式追问策略

| 模式 | 追问重点 |
|------|---------|
| 项目复盘 | 追问数据、决策过程、反思深度 |
| 行为问答 | 追问具体情境、转折点、可迁移性 |
| 情景应对 | 追问假设变化、风险考量、替代方案 |
| 结构化面试 | 追问细节、稳定性、即战力 |
| 创始人对话 | 追问多面手能力、风险认知、薪资期望 |
| 稳重应答 | 追问稳定性、长期规划、家庭因素 |

## 6. Story Bank 集成

故事银行（`interview-prep/story-bank.md` + SQLite `stories` 表）是 STAR+R 故事的持久化存储。面试引擎通过两个方式利用故事银行：

### 6.1 出题阶段

`prepareInterviewFull` 工具（`prepare-interview-full.ts`）会：
1. 调用 `/api/data/story-bank` 加载用户的历史 STAR 故事
2. 将故事内容注入出题 prompt
3. 在出题结果中提示："STAR 故事库已加载，请从中匹配用户经历对应目标岗位"

### 6.2 故事银行格式

```markdown
### [Theme] Story Title
**Source:** Report #NNN — Company — Role
**S (Situation):** ...
**T (Task):** ...
**A (Action):** ...
**R (Result):** ...
**Reflection:** What I learned / what I'd do differently
**Best for questions about:** [list of question types this story answers]
```

### 6.3 数据库存储

SQLite `stories` 表结构：

```
stories
├── id          INTEGER PRIMARY KEY
├── title       TEXT
├── situation   TEXT
├── task        TEXT
├── action      TEXT
├── result      TEXT
├── tags_json   TEXT (JSON array)
└── created_at  DATETIME DEFAULT CURRENT_TIMESTAMP
```

API `GET /api/stories` 返回所有故事，`POST /api/stories` 新增故事。该系统在每次 JD 评估的 F 板块（面试准备）中自动积累故事。

## 7. Interview Agent：子代理编排

`src/lib/agent/registry/agents/interview-agent.ts` 是面试教练的子代理定义，遵循统一的 Agent 注册体系。

### 7.1 职责与边界

```
│  │ questions             │  │                          │     │

│  └──────────────────────┘  └──────────────────────────┘     │

└──────────────────────────────────────────────────────────────┘
```

### 7.2 意图路由

Interview Agent 通过正则模式匹配被激活：

```typescript
const INTERVIEW_INTENT_PATTERNS = [
  /面试.*(练习|模拟|准备|教练|训练)/,
  /(准备|练习|模拟|训练).*面试/,
  /帮我.*出.*(题|面试)/,
  /怎么.*(答|说|面)/,
  /(练习一下|练一练|练一下).*面/,
  /(面经|面试题)/,
  /帮我.*(评分|打分).*(回答|面试)/,
];
```

优先级为 10，建议指令包括"出面试题""模拟面试""评分回答""换模式"。

### 7.3 System Prompt 构建

`buildSystemPrompt()` 方法按以下顺序拼接：

1. **Coach Overlay**：`buildInterviewCoachOverlay()` 根据公司/岗位/模式/简历生成完整的教练行为指南，包含六种模式速查表、出题策略、追问策略和反模式
2. **Career DNA**：用户画像数据（从 orchestrator 上下文注入）
3. **Agent Knowledge**：面试知识子集（`interview-styles`）
4. **Memory Digest**：分层记忆的会话摘要
5. **Tool List**：INTERVIEW_TOOLS 的列表化描述
6. **核心规则**：仅使用 interview 工具、禁止 web_search、同一会话支持多次出题

### 7.4 公司/角色自动提取

Agent 从用户消息中自动提取目标公司和岗位：

- **公司匹配**：正则匹配大厂关键词（字节/腾讯/阿里/百度/美团/小米...）或"公司是 XX"模式
- **岗位匹配**：正则匹配"XX工程师""XX经理""XX设计师""XX产品""XX运营"或"XX岗位/职位/方向"模式
- 提取成功则自动推断面试模式，失败则默认 behavioral

## 8. Coach API 端点

### 8.1 端点总览

| 端点 | 方法 | 功能 |
|------|------|------|
| `/api/agent/coach/session` | POST | 会话管理：创建、继续、结束 |
| `/api/agent/coach/generate-questions` | POST | 批量出题（独立使用） |
| `/api/agent/coach/score-answer` | POST | 回答评分（独立使用） |

### 8.2 Session API 详解

`POST /api/agent/coach/session`

**创建会话**：

```http
POST /api/agent/coach/session
Content-Type: application/json

{ "company": "字节跳动", "role": "AI产品经理" }

Response 200:
{
  "success": true,
  "data": {
    "sessionId": "iv_1715000000000",
    "phase": "intro",
    "question": "请简单介绍一下你自己，包括你的背景和为什么对这个岗位感兴趣",
    "questionIndex": 0
  }
}
```

**继续会话**（回答或追问）：

```http
POST /api/agent/coach/session
Content-Type: application/json

{ "sessionId": "iv_1715000000000", "answer": "我做过3年AI产品..." }

Response 200 (追问):
{
  "success": true,
  "data": { "action": "followup", "question": "你提到带领团队，能说说团队规模和分工吗？" }
}

Response 200 (进入下一题):
{
  "success": true,
  "data": {
    "action": "next",
    "phase": "tech",
    "question": "请描述一个你主导的AI产品从0到1的案例...",
    "questionIndex": 0,
    "previousScore": 7,
    "previousFeedback": "结构清晰，但缺少量化结果"
  }
}

Response 200 (面试结束):
{
  "success": true,
  "data": {
    "action": "done",
    "summary": "综合评估：...",
    "answers": [
      { "question": "...", "answer": "...", "score": 7, "feedback": "..." }
    ]
  }
}
```

**错误响应**：

```
400: 缺少公司/岗位
404: 会话不存在或已过期（内存存储，服务重启后丢失）
500: 面试引擎错误（DeepSeek API 调用失败等）
```

### 8.3 内存会话存储

会话存储在 `Map<string, InterviewSession>` 中（生产环境建议迁移到 SQLite/Redis）。会话在面试结束（phase 变为 done）后自动删除。

### 8.4 Generate Questions API

`POST /api/agent/coach/generate-questions`

接收 JD/CV/公司/岗位/模式参数，调用 DeepSeek 生成 8-12 道题目。温度 0.8（鼓励多样性），max_tokens 4096（容纳完整 JSON）。

**容错解析**：支持三种 JSON 格式（纯数组、`{questions: [...]}`、`{data: {questions: [...]}}`），自动去除 markdown code fence。

### 8.5 Score Answer API

`POST /api/agent/coach/score-answer`

接收题目/回答/模式/上下文，返回四维评分 + 综合得分 + 改进建议 + 逐段反馈。温度 0.3（保证一致性），使用 `response_format: json_object`。

## 10. 与 Phase 1 集成

面试教练系统与 Phase 1 的 JD 评估流程紧密协作：

1. **JD 评估 F 板块**：评估报告中的"面试准备"板块会调用 `prepareInterviewFull` 工具，生成针对性的面试方案
2. **故事积累**：每次评估后，F 板块生成的 STAR+R 故事会自动追加到 story-bank
3. **简历联动**：出题时注入用户简历内容，识别简历弱项并增加对应方向题目
4. **公司模式映射**：与 JD 评估共享公司到模式的推断逻辑
