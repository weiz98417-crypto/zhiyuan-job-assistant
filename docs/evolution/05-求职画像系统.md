# 05 — 求职画像系统

> 所属阶段：Phase 1 · Profile + CV + Archetype 三层架构

---

## 1. 设计理念

求职画像系统是筝筝纸鸢的**"你是谁"引擎**。它不只是存一份简历——它构建了一个**自适应的求职身份**，同一份经历根据岗位类型自动切换叙事框架。

### 灵感来源

系统的 adaptive framing 设计受 **Andrej Karpathy 的 Personal Wiki** 理念启发：

| Karpathy's Wiki | 筝筝纸鸢 Profile |
|-----------------|-----------------|
| "Living document" — 持续更新 | Profile 是活的——每次评估后 Agent 学到新东西 |
| Multi-layered (notes, projects, talks) | 四层数据：cv.md + profile.yml + _profile.md + article-digest.md |
| Concrete metrics over adjectives | Proof points 必须有 hero_metric |
| Same person, different framing per audience | 同一个 proof point，不同 archetype 用不同叙事 |

> **注**：这是设计哲学层面的参考，不是代码层面的直接引用。

## 2. 四层数据结构

```
Layer 1: cv.md                    ← 原始简历（Markdown）
  └─ Layer 2: config/profile.yml   ← 结构化身份（YAML）
       └─ Layer 3: modes/_profile.md ← 自定义 archetype 映射 + 叙事框架
            └─ Layer 4: article-digest.md ← 详细证明点（可选）
```

### Layer 1: cv.md — 标准简历

```markdown
# 张三 — 高级AI产品经理
## Summary
10年产品经验，主导3款AI产品从0到1...
## Experience
### 字节跳动 | AI产品负责人 | 2022-至今
...
## Projects
...
```

### Layer 2: config/profile.yml — 结构化身份

```yaml
candidate:
  full_name: "张三"
  location: "北京市朝阳区"
  target_roles:
    primary: ["高级AI产品经理", "AI产品负责人"]
    archetypes:
      - name: "AI产品经理"
        level: "高级/负责人"
        fit: "primary"
      - name: "AI运营"
        fit: "secondary"
  narrative:
    headline: "10年产品人转型AI产品"
    superpowers:
      - "AI产品方案设计"
      - "用户需求挖掘与数据分析驱动决策"
      - "跨部门推动"
    proof_points:
      - name: "AI客服机器人"
        hero_metric: "将客服效率提升60%，日均处理5000+对话"
```

### Layer 3: modes/_profile.md — 自定义 Archetype 映射

```markdown
## 你的自适应框架
| 如果岗位是…… | 强调你的…… | 证明来源 |
| AI产品经理 | 产品从0到1经验、AI功能设计 | article-digest.md + cv.md |
| AI运营 | 增长策略执行、AI工具在运营中的应用 | cv.md |
```

### Layer 4: article-digest.md — 详细证明点（可选）

当 cv.md 不够时，提供更详细的量化指标和项目描述。

## 3. 6 个 AI 岗位 Archetype

系统内置 6 个中国 AI 市场核心岗位类型：

```
┌─────────────────────────────────────────────────────┐
│  AI产品经理    AI运营    AI解决方案                   │
│  (产品规划)    (增长)    (售前方案)                   │
│                                                     │
│  AI项目经理    AI咨询    AI增长/市场                  │
│  (交付管理)    (变革)    (获客增长)                   │
└─────────────────────────────────────────────────────┘
```

每个 Archetype 有独立的：
- 优先证明点（B 板块按 Archetype 调整）
- STAR 故事框架（F 板块按 Archetype 选择）
- 职业叙事方向（E 板块按 Archetype 生成求职信）

---

## 4. 自适应叙事引擎

### 工作流

```
求职画像 (profile.yml + _profile.md)
    │
    ▼
JD Archetype 检测 (6选1或混合2个)
    │
    ▼
匹配画像中的对应 Archetype
    │
    ├──→ 选择该 Archetype 的 superpower 和 proof_point
    ├──→ 调整叙事框架 ("AI产品" vs "AI运营" vs "AI解决方案")
    └──→ 生成定制化简历摘要 + 求职信草稿
```

### 示例

同一份 CV 对不同岗位的输出：

**岗位 A: AI产品经理 (Primary)**
> "10年产品经验，主导3款AI产品从0到1。擅长PRD到上线的全流程，用数据驱动产品决策。"

**岗位 B: AI运营 (Secondary)**
> "10年互联网经验，专注增长策略和AI工具在运营中的落地。曾用A/B测试将社区用户从1万增长到10万。"

---

## 5. 数据闭环：评估后学习

```
每次评估后
    │
    ├── 用户说 "这个 archetype 不对" → 更新 _profile.md
    ├── 用户说 "你漏了我的X经验" → 更新 article-digest.md
    └── Agent 学到新模式 → 建议更新 profile.yml
```

**关键规则**：Agent 绝不自动更新 User Layer 文件。用户始终掌控自己的画像。
