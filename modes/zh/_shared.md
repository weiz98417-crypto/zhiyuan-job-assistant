## 评分体系 (Scoring System)

评估包含 6 个维度（A-F），总分 1-5：

| 维度 | 衡量内容 |
|------|---------|
| 简历匹配度 (Match con CV) | 技能、经验、证明点对应度 |
| 北极星匹配 (North Star) | 岗位与用户目标archetype的匹配度（来自 _profile.md） |
| 薪资 (Comp) | 薪资 vs 市场水平（5=市场前25%，1=远低于市场） |
| 文化信号 (Cultural) | 公司文化、成长性、稳定性、工作制度 |
| 红线/风险 (Red Flags) | 负面影响因素（负面调整） |
| **总分 (Global)** | 以上维度的加权平均 |

**分数解读：**
- 4.5+ → 强匹配，建议立即投递
- 4.0-4.4 → 好匹配，值得申请
- 3.5-3.9 → 一般，有特别原因才申请
- 低于 3.5 → 建议不投（参考 CLAUDE.md 中的道德使用准则）

## 职位真实性评估 (Block G)

Block G 评估招聘信息是否为真实活跃的职位空缺。它**不影响** 1-5 的总分——是独立的定性评估。

**三个等级：**
- **高可信度 (High Confidence)** — 真实活跃职位（多数信号为正面）
- **谨慎推进 (Proceed with Caution)** — 混合信号，值得注意
- **疑似虚假 (Suspicious)** — 多个虚假信号，用户需自行核实

**关键信号（按可靠性排序）：**

| 信号 | 来源 | 可靠性 | 说明 |
|------|------|--------|------|
| 职位发布时间 | 页面快照 | 高 | 30天以内=好，30-60天=中等，60天以上=需警惕（根据岗位类型调整） |
| 投递按钮可用性 | 页面快照 | 高 | 直接可观测 |
| JD技术细节 | JD正文 | 中 | 描述笼统可能与虚假发布相关，但也可能只是文案差 |
| 要求合理性 | JD正文 | 中 | 矛盾是强信号，模糊性是弱信号 |
| 公司近期负面新闻 | 网络搜索 | 中 | 需考虑部门、时间、公司规模 |
| 重复发布模式 | scan-history.tsv | 中 | 同一岗位90天内发布2次以上需警惕 |
| 薪资透明 | JD正文 | 低 | 地域差异，很多合法原因不公开薪资 |
| 岗位-公司匹配度 | 定性分析 | 低 | 主观判断，仅作为辅助信号 |

**中国招聘平台特有问题信号：**
- 薪资区间过宽（如15K-40K）且无具体JD → 可能为培训公司/猎头收集简历
- 公司主页无活跃动态（新注册、无最新职位更新）→ 可能是空壳
- 同一岗位长年挂在多平台 → 疑似虚假招聘
- 天眼查/企查查显示公司存在劳动仲裁或经营异常
- 招聘描述写"AI相关"但完全不提具体技术栈

**道德框架（强制）：**
- 帮助用户将时间花在真实机会上
- 永远不要将发现表述为对公司的指控
- 呈现信号，由用户做决定
- 始终标注可疑信号的合理替代解释

## 全局规则 (Global Rules)

### 绝对禁止

1. 编造经验或指标
2. 修改 cv.md 或作品集文件
3. 代替候选人提交申请
4. 在生成的消息中透露电话号码
5. 推荐低于市场价的薪资
6. 未读取JD就生成PDF
7. 使用空洞的企业套话
8. 评估完不记录到追踪表
9. 在非用户文件中写入中文求职者特定内容（保持DATA_CONTRACT）

### 必须执行

0. **求职信：** 如果表单允许，始终包含。与CV一致的视觉设计。JD要求对应到经历证明。1页以内。
1. 评估前读取 cv.md、_profile.md 和 article-digest.md（若存在）
1b. **每次会话第一次评估前：** 运行 `node cv-sync-check.mjs`。如有警告，通知用户。
2. 检测岗位archetype并根据 _profile.md 调整叙事框架
3. 匹配时引用简历的具体行
4. 使用 WebSearch 查询薪资和公司数据
5. 评估后记录到追踪表
6. 用JD的语言生成内容（中文JD→中文输出）
7. 直接可行动，不废话
8. 生成的专业文本：短句，主动语态，具体指标。
9. **追踪条目用 TSV 格式**——绝对不要直接编辑 applications.md。写入 `batch/tracker-additions/`。
10. **每个报告头必须包含 `**URL:**`**

### 中文写作规范

适用于所有候选人面向文档：PDF摘要、简历要点、求职信、表单回答。不适用于内部评估报告。

**拒绝套话：**
- 避免"具有强烈的责任心"、"善于团队合作"、"工作认真负责"等空泛描述
- 不写"精通"——写成具体项目中的成果
- 不写"熟悉"——写成使用场景和规模
- 避免"负责……工作"——写成具体贡献和量化成果

**偏好具体而非抽象：**
- "将推荐准确率从72%提升到89%" 远好于 "优化了推荐算法"
- "基于LangChain构建RAG系统，处理日均5000+用户查询" 好于 "擅长RAG系统搭建"
- 命名工具、项目和客户名称（当允许时）

**中标点规范：**
- 中文用全角标点（，。、；：）
- 英文字母和数字用半角
- 数字和中文之间加空格（"处理 5000 条数据"而非"处理5000条数据"）
- 专业术语保持英文原样（RAG、Prompt Engineering、Finetune）

## 中国薪资与福利体系 (Chinese Compensation Framework)

### 薪资结构认知

| 组成部分 | 说明 | 评估时需要关注 |
|---------|------|--------------|
| 税前月薪 (Base) | 每月税前收入 | 核心谈判标的 |
| 薪数 (Months) | 一年发N个月（通常12+N） | 13薪/14薪/15薪等，注意是"保底"还是"浮动" |
| 年终奖 (Annual Bonus) | 年底一次性发放 | 明确是"固定"还是"视经营情况" |
| 五险一金 | 社保+公积金 | 缴费基数（最低/实际/封顶）、公积金比例（5%-12%） |
| 补充福利 | 补充医疗、企业年金、餐补 | 重要但不是核心比较维度 |
| 期权/股权 | 股票激励 | 初创公司占比大，但需评估变现可能 |

### 市场薪资数据源

| 平台 | 数据类型 | 可信度 |
|------|---------|--------|
| 脉脉 | 匿名薪资分享、公司评价 | 中-高 |
| 看准网 | 面试反馈、薪资数据 | 中 |
| Boss直聘薪资查询 | 岗位薪资范围 | 中（平台显示区间偏乐观） |
| OfferShow (小程序) | 应届生/校招薪资 | 高（校招场景） |
| 牛客网 | 技术岗薪资分享 | 中-高 |
| 行业报告 | McKinsey/Boss直聘年度报告 | 中（宏观数据） |

### 红线信号（中国特化版）

以下信号按严重度分级：

**🔴 严重红线（强烈建议拒绝）：**
- JD明确要求996/大小周且无合理补偿
- 五险一金按最低基数缴纳（显性薪资 vs 实际成本差距巨大）
- 试用期超过6个月（违反劳动合同法）或试用期无五险一金
- 竞业限制范围过大（全行业禁止）且补偿金低于法定标准
- 外包/劳务派遣/非本部签约，JD中未明确说明
- 天眼查显示公司存在严重经营异常或失信记录

**🟡 中度风险（需谨慎核实）：**
- 年终奖表述模糊（"视经营情况和绩效"）且无往年参考
- 公积金比例低于8%（非一线城市可能正常，需结合当地政策）
- 薪资结构中浮动部分占比过高（>50%）
- 公司规模与JD要求不匹配（小公司招"AI大模型专家"）
- 面试流程过于简短（一轮即发offer）
- JD中"AI相关"但无具体技术栈或落地场景

**🟢 轻度注意（可接受但需了解）：**
- 公积金不解决（小公司常见）
- 试用期6个月（法定上限，可接受但需确认转正标准）
- 不提供补充医疗保险（非硬性要求）
