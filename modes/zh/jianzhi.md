# 模式：jianzhi — 完整评估 A-G（中文版）

当候选人粘贴职位信息（文本或URL）时，始终交付完整的评估报告。

**前置检查：** 如果 JD 提取后为空文本或少于 50 个有效字符（去除空白和 Markdown 标记后），输出"⚠️ JD 内容不足，无法完成评估。请确认链接可访问或手动粘贴 JD 文本。"并停止评估。

---

## 第-1步 — 风险检测 🛡️

**读取并执行** `modes/zh/jianzhi-risk.md` 中的风险检测流程：
1. 字面匹配 → `node scripts/scan-risks.mjs`
2. 公司风险精确查找 → `risk-intel.md` company_risks
3. LLM 语义补充 → 禁止重复已知信号
4. 合并去重 → 加权计分 → 风险等级 → 输出表格

详见 `modes/zh/jianzhi-risk.md` 获取完整的风险分级表和输出模板。

---

## 第0步 — Archetype 检测

将职位归类到 6 个 archetype 之一（见 `modes/zh/_shared.md`）。如果是混合型，标注最接近的 2 个。这决定了：
- B板块优先使用哪些证明点
- E板块如何改写摘要
- F板块准备哪些 STAR 故事

**第0.5步 — 读取 JD（如果是URL）**

用 Playwright 打开 URL 并获取完整快照（包括发布时间、投递按钮状态、公司信息）。

## A板块 — 职位概览

表格包含：
- 检测到的 Archetype
- 领域（AI产品/AI运营/AI解决方案/AI项目管理/AI咨询/AI增长）
- 职能（产品规划/运营增长/售前方案/项目管理/战略咨询/市场营销）
- 职级（初级/中级/高级/专家/总监）
- 工作模式（远程/混合/坐班）
- 团队规模（如有提及）
- 一句话 TL;DR

---

## B板块 — 简历匹配

读取 `cv.md`。创建表格将 JD 的每个要求映射到简历的具体行。

**按Archetype调整：**
- AI产品经理 → 优先 PRD、产品规划、数据驱动决策的证据
- AI运营 → 优先增长指标、AI工具应用、A/B测试的证据
- AI解决方案 → 优先方案设计、客户沟通、技术广度的证据
- AI项目经理 → 优先交付记录、跨团队协作、风险管理的证据
- AI咨询顾问 → 优先行业洞察、方法论、变革推动的证据
- AI增长/市场 → 优先增长指标、渠道经验、AI内容工具的证据

**缺口 (Gaps) 分析**——每个缺口都要有应对策略：

1. 硬性要求还是锦上添花？
2. 能否用相邻经验证明？
3. 有没有作品集项目可覆盖？
4. 具体弥补方案（求职信中的一句话、快速学习路径等）

## C板块 — 职级与策略

1. **JD中检测到的职级** vs **该archetype下候选人的自然级别**
2. **"卖senior不撒谎"方案**：按archetype适配的具体话术、要突出的具体成绩、如何将跨领域经验定位为优势
3. **"如果被downlevel"方案**：如果薪资公平可以接受，要求6个月review，明确晋升标准
4. **中国语境下的职级对应**：
   - P6/P7/P8（阿里职级）≈ 中级/高级/专家
   - T3/T4/T5（腾讯职级）→ 查阅当前对应关系
   - 注意：不同公司职级体系差异大，不要机械对应

## D板块 — 薪资与市场

使用 WebSearch 查询：

**中国数据源：**
- 脉脉：搜索"<公司> <岗位> 薪资"
- 看准网：搜索公司评价和薪资
- Boss直聘薪资查询：搜索同类岗位薪资区间
- OfferShow（如岗位偏应届/初级）：薪资分享
- 牛客网（技术相关岗位）：薪资分享

**评估维度：**
- 该公司在行业内的薪资竞争力（前25%/中等/偏低）
- 五险一金缴纳情况（搜索"<公司> 五险一金"、"<公司> 公积金"）
- 加班情况（搜索"<公司> 996"、"<公司> 加班"）
- 年终奖情况（搜索"<公司> 年终奖"）

表格含数据和引用来源。如果找不到数据，直接说而非编造。

**中国薪资计算示例：**
```
税前年薪 = 月薪 × N个月 + 年终奖
实际到手 ≈ 税前年薪 - 五险一金个人部分 - 个税
公积金入账 = 公司+个人缴存（按基数和比例计算）
```

## F板块 — 面试准备

6-10 个 STAR+R 故事映射到 JD 要求（STAR + **Reflection 反思**）：

| # | JD要求 | STAR+R故事 | 情境(S) | 任务(T) | 行动(A) | 结果(R) | 反思(Reflection) |
|---|--------|-----------|---------|---------|---------|---------|-----------------|

**反思列** 记录学到了什么或下次会怎么做不同。这体现seniority——初级候选人描述发生了什么，高级候选人提炼教训。

**故事库：** 如果 `interview-prep/story-bank.md` 存在，检查这些故事是否已在库中。如果不在，追加新的。随着时间推移建立 5-10 个可复用的核心故事。

**按Archetype选择和框架化：**
- AI产品经理 → 强调产品决策、trade-offs、用户洞察
- AI运营 → 强调增长策略、数据驱动、AI工具应用
- AI解决方案 → 强调客户沟通、方案设计、POC落地
- AI项目经理 → 强调交付记录、跨团队协调、风险管理
- AI咨询顾问 → 强调行业洞察、方法论应用、变革推动
- AI增长/市场 → 强调增长指标、渠道策略、AI赋能

同时准备：
- 1 个推荐的案例展示（带哪个项目去面试、怎么讲）
- 红线问题及应对话术（例："你为什么离开上一家公司？"、"你的职业规划是？"、"你期望的薪资是？"）

## G板块 — 职位合法性评估

分析招聘信息是否为真实活跃的职位空缺。帮助用户将精力集中在最有可能产生招聘流程的机会上。

**道德框架：** 呈现观察，不做指控。每个信号都有合理解释。由用户决定如何权衡。

### 信号分析（按优先级）：

**1. 职位新鲜度**（来自Playwright快照，第0.5步已获取）：
- 发布日期或"N天前"
- 投递按钮状态（可用/已关闭/缺失/跳转到通用页面）
- 如果URL跳转到通用职位页，标注

**2. JD质量**（来自JD正文）：
- 是否列出具体技术、框架、工具？
- 是否提到团队规模、汇报关系、组织上下文？
- 要求是否合理？（年限要求 vs 技术出现年限）
- 是否有明确的入职前6-12个月目标？
- 是否提到薪资/薪酬？
- JD中有多少比例是岗位特有内容 vs 通用话术？
- 是否有内部矛盾？（初级title + 专家级要求等）

**3. 公司招聘信号**（2-3次WebSearch，可结合D板块研究）：
- 搜索："<公司> 裁员 {年份}"
- 搜索："<公司> 招聘冻结 {年份}"
- 搜索："<公司> 经营异常" 或 天眼查/企查查查询
- 如果发现裁员：是否与这个岗位同一部门？

**4. 中国平台特有信号：**
- 是否为猎头代发（标注"猎头"字样）——中性信号
- 是否为培训公司伪装招聘（JD中有"零基础"、"包教包会"、"培训后上岗"）——高风险
- 公司注册资本与岗位薪资是否匹配（天眼查）
- 平台账号活跃度（发布历史、回复率）

**5. 岗位市场背景**（定性，无需额外查询）：
- 这种岗位通常4-6周就能找到人吗？
- 这个岗位对该公司的业务是否合理？
- 职级是否属于合理需要更长时间填补的？

### 输出格式：

**评估：** 三个等级之一：
- **高可信度** — 多个信号指向真实活跃职位
- **谨慎推进** — 混合信号，值得注意
- **疑似虚假** — 多个虚假/无效指标，投入时间前请核实

**信号表：** 每个观察到的信号及其发现和权重（正面/中性/需警惕）。

**备注：** 任何可能解释可疑信号的背景信息。

### 特殊情况处理：
- **国企/事业单位招聘：** 时间线更长是正常的。放宽阈值（60-90天正常）。
- **持续招聘岗：** JD明确写"长期招聘"或"滚动招聘"——这不是虚假岗，是储备岗。
- **高管/专家岗：** 总监、VP、高专岗位合法持续数月开放。放宽时间阈值。
- **初创公司：** 早期企业JD可能较模糊，因为岗位定义本身还在变化。降低JD模糊性权重。
- **无日期信息：** 如果无法确定发布时间且无其他可疑信号，默认"谨慎推进"并注明信息有限。绝对不要在无证据时判定"疑似虚假"。
- **猎头联系（无公开职位）：** 无法获取新鲜度信号。注意：猎头主动联系本身是正面信号。

## 评估后流程

**始终**在生成 A-G 板块后执行：

### 1. 保存报告 .md

将完整评估保存到 `reports/{###}-{company-slug}-{YYYY-MM-DD}.md`。

- `{###}` = 下一个顺序号（3位补零，从已有报告最大编号+1）
- `{company-slug}` = 公司名小写，空格用连字符
- `{YYYY-MM-DD}` = 当前日期

**报告格式：**

```markdown
# 评估报告：{公司} — {岗位}

**日期：** {YYYY-MM-DD}
**Archetype：** {检测到的archetype}
**Score：** {X/5}
**Legitimacy：** {高可信度 | 谨慎推进 | 疑似虚假}
**URL：** {URL}
**模式：** 中文 (zh)
**PDF：** {文件路径或待生成}

---

## A）职位概览
(A板块完整内容)

## B）简历匹配
(B板块完整内容)

## C）职级与策略
(C板块完整内容)

## D）薪资与市场
(D板块完整内容)

## E）定制化方案
(E板块完整内容)

## F）面试准备
(F板块完整内容)

## G）职位合法性
(G板块完整内容)

## H）申请草稿
(仅当 score >= 4.5 — 申请表单回复草稿)

---

## 提取的关键词
(15-20个JD关键词用于简历优化)
```

### 2. 校验输出

如果 LLM 在评估过程中超时或返回不完整结果，**不要编造缺失的板块**。输出已完成的部分，缺失板块标记为"⚠️ 此板块生成超时，请重新运行评估"。

保存报告后，**始终**运行校验脚本：

```bash
node scripts/validate-output.mjs --data '{"overall_score":<分数>,"date":"<日期>","status":"<状态>","report_path":"reports/<报告文件名>"}'
```

- 如果校验失败（exit ≠ 0），重试报告生成，修正校验错误字段
- 校验通过后才进入下一步持久化

### 3. 持久化到 SQLite（规范存储）

**始终**调用 `db-write.mjs` 写入 SQLite：

```bash
# 写入应用记录
node scripts/db-write.mjs --action upsertApp --data '{"num":<编号>,"date":"<日期>","company":"<公司>","role":"<岗位>","score":<分数>,"status":"<状态>","pdf_generated":<0或1>,"report_path":"reports/<文件名>","notes":"<备注>"}'

# 写入报告元数据
node scripts/db-write.mjs --action upsertReport --data '{"report_num":<编号>,"date":"<日期>","company":"<公司>","role":"<岗位>","archetype":"<archetype>","overall_score":<分数>,"legitimacy":"<等级>","blocks_json":"<JSON>","keywords_json":"<JSON数组>"}'
```

**Fallback：** 如果 `db-write.mjs` 不可用（exit ≠ 0），回退到 TSV 写入 `batch/tracker-additions/{###}-{company-slug}.tsv`：

```
{###}\t{日期}\t{公司}\t{岗位}\t{状态}\t{分数}/5\t{✅或❌}\t[{###}](reports/{###}-{slug}-{日期}.md)\t{备注}
```
